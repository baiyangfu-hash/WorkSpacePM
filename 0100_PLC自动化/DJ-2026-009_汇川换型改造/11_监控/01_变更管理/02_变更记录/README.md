# 变更记录 - DJ-2026-009

这个抽屉放两本登记本：

| 文件 | 记什么 | 谁写、什么时候写 |
|---|---|---|
| `02_业务变更记录.md` | 业务变更（BC），一行一件事：谁要改、改什么、为什么、谁批的、状态 | 客户或现场每提一次改动，**先加一行，再动手**；用户口述，AI 代填 |
| `01_版本变更台账.md` | 已关闭的 CHG 变更单和对应版本号 | CHG 关闭时记一行 |

## 规矩

- BC 编号按提出时间排（2026-10-22 用户定）：`BC-DJ-2026-009-<年>_<月>_<序号>`，例如 `BC-DJ-2026-009-2026_10_000` 是 10 月提出的第一条，序号每月从 000 起、最多 999，不重复使用；已有的 `BC-DJ-2026-009-001`～`004` 保留不改，下一条起用新格式。“提出时间”栏（原叫“提出日期”）新行写到分钟（`YYYY-MM-DD HH:MM`）和渠道；类型只填“需求 / 参数 / 硬件”。
- 状态只用五种：待批 / 已批 / 已实施 / 已验证 / 已取消。**只有“已批”的行才能被实施卡引用**；引用这一行的卡全部验收后，才改“已实施”。
- 表里不抄实施卡号，“关联 CHG / 提交”栏只填最终的提交号、版本号或 CHG 编号。
- 不知道的写 `待补`，括号里写该问谁；客户联系人、合同、价格等商业信息一律留白。
- 业务变更记录不叫“台账”，文件名不含这两个字，以免被驾驶舱的台账对账当成 CHG 台账。
