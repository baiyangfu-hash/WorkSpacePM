# 变更管理柜 - DJ-2026-009 汇川换型改造

> 2026-10-20 建。本文是说明，不是指令。分工依据：`0100_PLC自动化/00_通用规范/项目文档模板/README.md` 第 2 节。

这个柜子管本项目的一切改动。查一件事“谁要改、批没批、谁去改、改完没有”，只开这一个柜子。

## 1. 三个抽屉

| 抽屉 | 放什么 | 相当于工厂里的 | 什么时候有 |
|---|---|---|---|
| `02_变更记录/` | 业务变更记录（BC，一行一件事）+ 版本变更台账 | 客户来函、变更请求登记本 | 每件事都有，**先记一行再动手** |
| `01_变更单/` | CHG 变更单 | ECN 工程变更通知 | **只在大事时开**：程序正式下发设备或交付客户（发版）、安全相关 |
| `03_实施卡/` | 实施卡，一张卡一个文件 | 施工作业单 | 每次让 AI 动手都有 |

抽屉编号沿用骨架原有的 `01_变更单`、`02_变更记录`，没有按使用顺序重排，以免旧链接失效。使用顺序是 02 → 01（需要时）→ 03。

## 2. 一件事怎么走

```
客户/现场提出 ──▶ 02_变更记录：加一行 BC，状态“待批”
                     │ 用户批准
                     ▼
                 状态改“已批” ──(发版或安全相关?)──是──▶ 01_变更单：开 CHG
                     │                                   │
                     ▼                                   ▼
                 03_实施卡：开卡，头部写“依据：BC-…”“变更单：CHG-… 或 无”
                     │ AI 按卡改文件、跑检查，用户验收
                     ▼
                 BC 这一行：引用它的卡全部验收后改“已实施”，在“关联 CHG / 提交”栏填提交号
```

- **只从卡这一头写依据**。BC 表、版本台账、CHG 都不抄卡号；“这件事由哪几张卡完成”由脚本按卡头部反查（脚本在驾驶舱 D09 解冻后做，在那之前人工核对）。
- 修驾驶舱、修技能这类工具缺陷不算业务变更，不进 BC 表。`01_变更单/CHG-PLC/CHG-PLC-2026-001.md` 就是这类历史单子，原样保留。

## 3. 示范：一条真实变更从头查到尾

“本机与上下游的通讯换成 Modbus TCP，本机做客户端”：

| 步 | 在哪 | 内容 |
|---|---|---|
| 1 | `02_变更记录/02_业务变更记录.md` 的 `BC-DJ-2026-009-004` | 用户 2026-10-19 拍板：打胶机在下游；上下游走 Modbus TCP，本机做客户端；握手程序和变量不变 |
| 2 | 文档已更新 | 需求说明 V0.3、通讯契约 V0.3（PR #21，合并提交 `0924787`）。这一步发生在实施卡制度之前，没有卡 |
| 3 | `01_变更单/` | **不开 CHG**：只是改通讯层，还没有正式下发设备，也不碰安全回路。将来程序正式下发设备或交付客户时，按发版开 `CHG-PLC` |
| 4 | `03_实施卡/CARD-DJ-2026-009-001_ModbusTCP客户端通讯层.md` | 第一张新式卡，状态“草稿”，等驾驶舱 D09 解冻后派工 |
| 5 | 卡验收后 | BC-004 改“已实施”，“关联 CHG / 提交”栏补上程序提交号 |
