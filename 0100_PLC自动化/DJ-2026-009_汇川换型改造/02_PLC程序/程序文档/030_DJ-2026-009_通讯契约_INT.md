## 2. 交换区

### 2.0 寄存器约定（待对方确认）

- 上游机器人和下游打胶机各做 Modbus TCP 服务器，本机（AM500）做客户端：本机周期读取对方的状态字，并把本机的信号写进对方的寄存器。轮询周期建议值 ≤ 100 ms。端口、单元号、轮询周期都是建议值，以双方签字版为准。
- 两台对方设备各自提供下面这一块寄存器，地址都从 0 开始（各在自己的设备里，不冲突）。只用保持寄存器（功能码 03 读、06 / 16 写）。下表地址是协议地址（从 0 起）；习惯写法“4xxxx”时加 40001，例如地址 0 = 40001。如果对方设备的地址只能放在别处，可以整体平移，在 §4 签字时写明起始地址。
- 下面 2.1、2.2 的“地址”列写成 `字地址.位`，例如 `0.2` 表示地址 0 的 bit2。一个字里的位：bit0 是最低位。没有用到的位填 0，对方不得依赖。
- 组件 ID：最长 32 个 ASCII 字符，占 16 个寄存器，每个寄存器放 2 个字符，高字节在前；不足 32 个字符时其余字节填 0。
- 心跳放在各自状态字的 bit15，按 4 s 亮 / 4 s 灭翻转；12 s 内没有翻转即判通讯故障。
- 每一方只写属于自己的字：本机只写“本机写”的地址，对方不得改写这些地址。
- 安全信号不走 Modbus TCP，见 2.3。

**上游机器人（服务器）提供的寄存器**

| 地址 | 谁写 | 内容 |
|---|---|---|
| 0 | 上游 | 上游 → 本机 状态字（本机读，见 2.1） |
| 1 | 本机 | 本机 → 上游 状态字（本机写，见 2.1） |
| 2～17 | 上游 | 组件 ID（本机读入 `sRcvModuleID`） |
| 18～31 | — | 预留 |

**下游打胶机（服务器）提供的寄存器**

| 地址 | 谁写 | 内容 |
|---|---|---|
| 0 | 下游 | 下游 → 本机 状态字（本机读，见 2.2） |
| 1 | 本机 | 本机 → 下游 状态字（本机写，见 2.2） |
| 2～17 | 本机 | 组件 ID（本机写，来自 `sSendModuleID`） |
| 18～31 | — | 预留 |

### 2.3 公共信号（`ST_ExternalDevice`）

安全回路由独立的安全继电器控制，PLC 程序不能控制它；安全继电器只通过 IO 点向 PLC 报告安全状态，PLC 据此停机和报警。

| 信号 | 方向 | 类型 | 地址 | 含义 |
|---|---|---|---|---|
| `bEmergencyStop` | 安全继电器 → 本机 | BOOL | 硬线 IO 输入，点位待补 | 外部急停（1 = 正常，0 = 急停） |
| `bSafetyDoorOK` | 安全继电器 → 本机 | BOOL | 硬线 IO 输入，点位待补 | 外部安全门锁 |

## 3. 交互时序（程序里已实现的部分）

- 心跳：本机向上下游输出 4 s 亮 / 4 s 灭方波；对方心跳 12 s 内没有翻转，即报通讯故障（`bUpstreamComFault` / `bDownstreamComFault`）。程序：`FB_3001` 中的 `s_dHeartbeatPulse = 4000`、`s_dHbTimeoutMs = 12000`。
- 通讯故障时：本机不再发出 `bMachine_ReadyIn` / `bMachine_ReadyOut`，即不开始新的握手。
- 组件 ID：最长 32 个 ASCII 字符，由线上最初一站的设备按“线别 + 班别 + 时间戳”生成；本机从上游读入后原样写给打胶机，不改内容（10-19 答复）。
- 程序现状：握手逻辑（`FB_3001`）和变量已经有了；Modbus TCP 客户端数据映射层 `FB_3002_ModbusTcpClient` 已写在分支 `claude/dj009-modbus-client`（`CARD-DJ-2026-009-001`），D09 后合并，未导入 InoProShop、未现场验证。
- 断线验收（A3）：拔掉本机与上下游之间的 Modbus TCP 网线即可模拟。
