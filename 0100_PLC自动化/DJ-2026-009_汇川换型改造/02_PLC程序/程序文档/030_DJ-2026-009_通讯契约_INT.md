## 2. 交换区

### 2.0 寄存器约定（建议，待对方确认）

- 本机（AM500）做 Modbus TCP 服务器，上游机器人和下游打胶机各做客户端：客户端周期读取本机的输出字，并把自己的信号写进本机的输入字。建议轮询周期 ≤ 100 ms。
- 只用保持寄存器（功能码 03 读、06 / 16 写）。下表地址是协议地址（从 0 起）；习惯写法“4xxxx”时加 40001，例如地址 0 = 40001。
- 下面 2.1、2.2 的“地址”列写成 `字地址.位`，例如 `0.2` 表示地址 0 的 bit2。一个字里的位：bit0 是最低位。没有用到的位填 0，对方不得依赖。
- 组件 ID：最长 32 个 ASCII 字符，占 16 个寄存器，每个寄存器放 2 个字符，高字节在前；不足 32 个字符时其余字节填 0。
- 心跳放在各自状态字的 bit15，按 4 s 亮 / 4 s 灭翻转；12 s 内没有翻转即判通讯故障。
- 每一方只写属于自己的字，不写对方的字。
- 急停和安全门互锁不走 Modbus TCP（不是安全协议），保留硬线（建议，待用户确认）。

## 3. 交互时序（程序里已实现的部分）

- 心跳：本机向上下游输出 4 s 亮 / 4 s 灭方波；对方心跳 12 s 内没有翻转，即报通讯故障（`bUpstreamComFault` / `bDownstreamComFault`）。程序：`FB_3001` 中的 `s_dHeartbeatPulse = 4000`、`s_dHbTimeoutMs = 12000`。
- 通讯故障时：本机不再发出 `bMachine_ReadyIn` / `bMachine_ReadyOut`，即不开始新的握手。
- **已知缺陷**：握手进行到一半（第 20、30 步）时通讯中断，程序**不会**撤销 `bMachine_AllowInfeed`，`q_bAllowInfeedAct` / `q_bAllowOutfeedAct` 也保持不变，不满足验收项 A3 的“切断”要求。修改排在 M3 D09 之后，本文件届时同步更新。
- 组件 ID：最长 32 个 ASCII 字符（10-19 答复）。建议由上游机器人生成，本机原样转给打胶机（待用户确认）。
- 断线验收（A3）：拔掉本机与上下游之间的 Modbus TCP 网线即可模拟。
