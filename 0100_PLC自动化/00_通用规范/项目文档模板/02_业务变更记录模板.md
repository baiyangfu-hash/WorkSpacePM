# 业务变更记录 - <项目号> <项目名>

> 客户或现场每提一次改动，就在表里**先加一行，再动手**。一行写一件事。
> 这里记的是“谁要改、改什么、谁批的”。AI 动手改程序或文档时用实施卡（施工单），卡上写明依据的是本表哪一行；本表**不抄卡号**，哪几张卡完成了某一行，由脚本根据卡上的依据反查。
> 只有发版（程序正式下发设备或交付客户）、安全相关的改动才另开 CHG 变更单（相当于 ECN）。
> 修驾驶舱、修技能之类的工具或软件缺陷不记在这里。

## 填写说明

| 栏 | 怎么写 |
|---|---|
| 编号 | 按提出时间排：`BC-<项目号>-<年>_<月>_<序号>`，例如 `BC-DJ-2026-009-2026_10_000` 是本项目 10 月提出的第一条。序号每月从 000 起，每月最多 999，不重复使用；年月必须与“提出时间”一致。2026-10-22 之前的旧编号（如 `BC-DJ-2026-009-001`）保留不改 |
| 提出时间 | 对方提出的时间，写到分钟：`YYYY-MM-DD HH:MM`，后面括号写渠道（当面 / 电话 / 邮件 / 微信）。被问“什么时候谁提的”时靠这一栏 |
| 提出人 | 姓名 + 单位或岗位，例如“张工（客户设备科）” |
| 类型 | 只能填三种之一：**需求**（功能、工艺、范围）、**参数**（速度、时间、点位、通讯参数）、**硬件**（换型号、加减元件、改接线） |
| 改了什么 | 原来 → 改成，写具体值 |
| 为什么 | 对方给的原因，不要自己推测 |
| 影响 | 会动到的程序块、图纸、IO、节拍、成本、交期；没有就写“无” |
| 批准人 / 批准日期 | 谁同意的、哪天同意的；口头同意的写“口头”，并补一条书面依据（邮件、微信截图的存档位置） |
| 状态 | 待批 / 已批 / 已实施 / 已验证 / 已取消。只有“已批”的行才能被实施卡引用；改成“已实施”前，引用这一行的实施卡要全部验收 |
| 关联 CHG / 提交 | 最终落到的提交号或版本号；开了 CHG 的再写 CHG 编号。不写实施卡号 |
