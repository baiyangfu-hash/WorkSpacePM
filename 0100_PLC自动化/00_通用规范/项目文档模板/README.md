## 2. 业务变更、变更单、实施卡的分工

按工厂的做法分三层（2026-10-19 用户确认，方案见项目文件 `plans/实施卡与变更单_定位与存放方案_20261019.md`）：

| 层 | 相当于 | 回答什么 | 什么时候有 | 放在哪 |
|---|---|---|---|---|
| **业务变更记录**（BC）或需求条目 | 客户来函、变更请求 | 谁要改、改什么、为什么、谁批的 | 每件事都有 | `11_监控/01_变更管理/02_变更记录/02_业务变更记录.md` |
| **CHG 变更单** | ECN 工程变更通知 | 风险和影响多大、批到哪一级 | **只在大事时开**：程序正式下发设备或交付客户（发版）、安全相关；改程序记 `CHG-PLC`，改电气记 `CHG-ELEC`，改文档记 `CHG-DOCU` | `11_监控/01_变更管理/01_变更单/` |
| **实施卡** | 施工作业单 | AI 改哪几个文件、从哪个版本开始、用什么检查验收 | 每次让 AI 动手都有 | `11_监控/01_变更管理/03_实施卡/` |

规矩：
- **只单向挂接**：实施卡写明依据（至少一条已批的业务变更或需求，碰上大事再写一张 CHG）。业务变更记录、版本台账、CHG 都不手抄卡号，“这件事由哪几张卡完成”由脚本反查。
- 一条业务变更可以拆成多张卡；一张 CHG 可以挂多张卡，但一张卡最多挂一张 CHG。挂在同一张 CHG 下的卡改动文件不重叠，要么排好先后。
- 引用某一行的卡全部验收后，这一行才能改成“已实施”；CHG 也一样。
- 纯工具或软件缺陷（例如修驾驶舱技能）不算业务变更，不登记到业务变更记录里。
- **业务变更记录不叫“台账”**：文件名不含“台账”二字，以免被驾驶舱的台账对账（`ledger reconcile`）和锁定清单当成 CHG 台账处理。

里程碑表的规矩（2026-10-22 用户确认：迁入模板加里程碑表，计划日期必须填）：
- 表头 `项目来源` 写 `新项目` 或 `老项目迁入`。`plc docs check` 会检查计划日期：新项目没填直接拦住（退出码 1），老项目迁入先只提示；项目里还没有里程碑表的也只提示。
- 日期只写 `YYYY-MM-DD`；状态只写 `未开始`、`进行中`、`已完成`、`不适用`；`已完成` 要有实际日期；确实没有的阶段写 `不适用`。
- 计划日期按 `../项目周期规范.md`（项目类型 + 规模 → 各阶段工期）推算；推算值和最终日期都由用户确认，AI 不编。不知道就写 `待填`，检查会一直报出来，直到填上。

变更管理柜的完整样子见 `DJ-2026-009_汇川换型改造/11_监控/01_变更管理/`：柜子总说明、三个抽屉的说明，和两张示范实施卡。

## 3. 填写约定

- 工艺流程图：一张 Mermaid 图配一张步序表，步号与程序里的步序变量一致，每一步写超时和报警码（STD-850、STD-860）。

- 不知道的就写 `待补`，**不要猜**。`待补` 后面用括号写清楚该问谁、该查哪份资料。
- 日期统一用 `YYYY-MM-DD`；型号写到具体料号。
- 与原设备（被改造的旧机）有关的事实，注明出处文件，例如 `DJ-2026-005 012 需求规格 §5.1`。
- 发现两份文档互相矛盾时，不要自己挑一个，在文档末尾的“待确认”一节列出来。
