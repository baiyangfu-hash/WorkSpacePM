## 发现清单

### A. 只在 Linux 上成立，Windows 上会坏

1. **高：样件联调的测试在 Windows 上会失败。** `tests/e2e/test_closure_drill.py`（#46）的假代理 `codex` 是一个 `#!/bin/sh` 脚本，测试还用 `chmod 0o755` 给它加执行位；`test_closure_drill_agent_misconduct.py` 等用的是同一套假代理。这几个文件都没有按平台跳过。Windows 上 `subprocess` 不能直接运行 shebang 脚本，所以用户电脑上的正式全量门禁会在这里变红。
   - 建议二选一：Windows 上改写一个 `codex.cmd` 来调用 `python codex_agent.py`；或者加 `skipif(os.name == "nt")` 并在测试里写明原因。
2. **低，原有问题：Windows 上可能启动不了 Codex。** 本地执行器 `local_executor.py` 默认用 `("codex",)` 启动 Codex，Windows 上不会去找 `codex.cmd`（npm 装的 Codex 是 `.cmd`）。这是 09-20 就有的代码，不是今晚引入的；Codex 目前只做 PR 审查，所以影响小。
3. **信息：** `.claude/hooks/session-start.sh` 是 bash 脚本，只用于云端会话，Windows 上不会运行，没有问题。
