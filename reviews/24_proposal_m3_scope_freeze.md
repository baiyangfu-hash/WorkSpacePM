## 1. “完全可用”具体指什么（建议作为 M3 的唯一退出口径）

用户能在自己的电脑上，从根入口完成下面这些事，并且每件都有 D08 / AC 的证据：

1. 新电脑一键装好并启动（已完成：卡 158）；
2. 打开驾驶舱或 CLI，从一个新目标开始一次 **Python** 任务，走完报批 → 执行 → 门禁 → 验收 → 落账，不手写表单、不手改治理对象（AC01、AC14）；
3. 同样走完一次 **PLC 静态**任务（AC10；TIA 导入、编译仍是用户边界）；
4. 中途换 agent 或会话中断后能接着做（V04-R1、AC08）；
5. 出错时能恢复：写失败可以重试、不会重复结算（AC07），新旧版本可以回退（D06）；
6. 运行的是经过构建、门禁和回退演练的同一个发布版（D03～D07，AC13）；
7. 新建 Python 和 PLC 工程用的是从真实基准提取的模板（V07、V08，AC12）。

## 3. 建议移出 M3（进入“M3 之后”，慢慢迭代）

| 项 | 理由 |
|---|---|
| `M3-PILOT` | 用户本人负责，不在退出条件里；D08 的 PLC 静态任务能先挡住一部分问题（用户 2026-10-17 已倾向延后） |
| `M3-COLLAB` 的 B 部分（S1～S5）和 A6～A9 | 多机多 agent 协作，属于新能力；单机单 agent 的可用性不依赖它 |
| `M3-CF` | 编译报错反馈通道，是新功能，而且要等用户给样本 |
| `M3-FIG` | 图与文档一致性检查，是新功能 |
| `M3-INV`、`M3-REPOGOV`、`M3-HYG`（增量） | 仓库治理，不影响驾驶舱的使用 |
| M2-F01B | PLC 工程移动与退役入口，是新能力，WBS 写的是“范围待用户批准” |
| 多 agent 薄入口（TD-SW008-063/066/067） | 用户已挂起（`reviews/23`） |
| `M3-DEP-TECH` | 建议**并入 D04～D07**，不单独做：D07 本身就是“构建 → 门禁 → 回退演练 → 切换”，再做一次开发运行时部署是重复劳动 |

记账类任务（`M3-TD25` 这类）按 V3.0.43 的“记账卡配额”并进实质卡的收尾步骤，不单独出卡。

## 5. 需要提前定下的两件事

1. **D05 的 20 个已知失败**（Linux CI 基线）：WBS 允许“原始失败单列，不得称全绿”。建议 D05 前先逐个分类：哪些是测试环境问题（例如只能在 Windows 上跑的测试），哪些是真正影响使用的缺陷。后一类要在 D03 前修掉，否则就不算“完全可用”。这一步请本地 Claude 先估一下量。
