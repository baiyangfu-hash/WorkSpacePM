### 6.1 A6 工位布置规则（文档档，可并行）

- 每台电脑一个控制根 R，停在 `main`，账本 `continuity.db` 在这里，驾驶舱命令只在这里跑。
- 每个会改文件的 agent 一个工位 `R/.auto-pm/worktrees/<agent>`，各用自己的分支前缀：

| agent | 工位 | 分支前缀 |
|---|---|---|
| 本地 Claude（含在 VS Code 里跑的 Claude Code） | `worktrees/claude` | `claude/` |
| Codex | `worktrees/codex` 或 Codex 自带的 `.codex/worktrees/` | `codex/` |
| Trae 里的 AI | `worktrees/trae` | `trae/` |
| Cursor 里的 AI | `worktrees/cursor` | `cursor/` |
| VS Code 里的其他 AI（如 Copilot） | `worktrees/vscode` | `vscode/` |
| 项目 Claude（云端） | 不占本机工位 | `project/` |

- **依据**（`main` @ `46aead1`）：`main.py` 第 13–33 行在这两类目录下拒绝运行；`auto_pm/infrastructure/control_root_guard.py` 第 155 行要求 Run 的工作树在 `.auto-pm/worktrees/` 下；`git_hook_enforcer.py` 第 215–223 行要求工位提交时指明控制根；`.gitignore` 第 128 行忽略工位目录。
- **验收**：规则写进 AGENTS.md 与 `.cursor/rules`（`.trae` 只由 Trae 维护）；放在 `.auto-pm/worktrees/` 之外的工作树被驾驶舱识别并拒绝登记 Run，防止一台电脑出现两本账。
- **注意**：改 AGENTS.md 属于地盘规则变更，由本地 Claude 按 CHG 办，项目 Claude 不改。

### 6.2 A7 一键开工位命令（测试档或核心档，勘测后定）

- **成果**：一条驾驶舱命令，按 agent 名和卡号在 `R/.auto-pm/worktrees/<agent>` 建工位、切出 `<前缀>/<卡号>` 分支、从最新 `main` 派生；工位已存在、分支被占用、控制根有未提交改动时拒绝，并写明原因。
- **复用**：现有 `dogfood` 命令已能在 `.auto-pm/worktrees/` 建候选工作树（`auto_pm/ui/cli/dogfood.py`、`application/core/worktree_policy_service.py`），先勘测能否复用，不另造一套。
- **反例**：不删除已有工位；工位有未推送提交时拒绝重建。

### 6.3 A8 账本主机（核心档，跟跨机共享 S 步骤一起做）

- **成果**：配置里指定一台电脑为“账本主机”，只有它能写 Work、WBS 台账、TD 台账；其他电脑只做卡、推分支、开 PR，记账请求交给账本主机。
- **对应**：跨机共享方案 v3 §4.3“单写者分工”。
- **验收**：非账本主机执行台账写入命令时被拒绝，提示“本机不是账本主机（当前为 X）”，且不留下半写的记录；账本主机损坏时，可从 `M3-DBBACKUP` 的备份恢复并改指定另一台。

### 6.4 A9 两机两 agent 验收场景（演练档，最后做）

- **场景**：A 电脑上的 Claude 做卡 1，B 电脑上的另一个 agent 同时做卡 2；两张卡的文件范围不重叠。
- **能看到的结果**：两张卡各自合进 `main`；任一台电脑都能看到对方正在做哪张卡、租约到什么时候；B 电脑试图接卡 1 被拒并写明持有者；账本只在账本主机上有一份完整记录，另一台没有分叉的台账。
- **与 D08 的关系**：不给原 D08（单机三次真实交付）加前置，作为 M3 之后的增量验收单列。
