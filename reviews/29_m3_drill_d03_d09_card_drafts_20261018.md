## 1. `M3-DRILL` 真实进程演练

- **要证明的**：同一台电脑上两个不同 IDE 的 agent 经薄入口接棒（AC08“真实换 Agent”、AC14 的跨会话部分的预演），以及执行进程被杀后租约能安全回收（V04-R1 用例 1、3 的真机版）。
- **场景（默认，报批时可改）**：
  1. Trae CN 里一句话“继续 <演练项目号>”，经薄入口 `pm orient` 定位，领 Work、起 Run（带租约），做完第一步并写 Checkpoint；
  2. 用 HANDOFF 卡的“一条命令交接”交出；第二个 agent 只说一句“接手”，先定位再接手，同一个 Work 续跑到完成；
  3. 第二轮：执行中用任务管理器结束执行进程；租约到期加 120 秒宽限后，因能证明本机原进程已不在而自动回收（epoch 加 1，Run 记下由谁、为什么回收），另一个 agent 接手做完；
  4. 被杀那一方的旧 epoch 再来写 Checkpoint，被拒绝。
- **演练对象（默认）**：用模板新建一个专门的演练项目号，做一个很小的真实改动（例如给一份文档加一节），不碰 SW-2026-008 的台账与 WBS 内容，只在卡的最后一步回写 WBS 投影与台账。
- **范围**：演练脚本与证据目录（`.auto-pm/reports/m3-drill/`）；演练中发现的缺陷在本卡内修，修复若碰核心存储就按核心档跑门禁；本卡最后一步写回 WBS 投影（顺带把“Codex 备选”改成用户定的第二个 agent）与台账。
- **不做**：跨电脑（已移出 M3）；界面显示；不直改 `expires_at`、不泄露口令；“原持有者在另一台电脑”那条只演示“等待中、要你签接受风险 Decision”，不演示真接手。
- **验收用例（你能看到的）**：
  1. 你在 Trae CN 说一句话、在第二个 agent 说一句“接手”，屏幕上两边显示的是同一个 Work 编号；全程你没抄口令、没手改任何文件；最后 CHG 完成、`ledger reconcile` 零差异。
  2. 你结束执行进程后，约“租约时长 + 2 分钟”内，状态从“运行中”变成“已回收”，写明由谁、因为什么；另一个 agent 接着做完。
  3. 被杀的那一方再来写，被拒绝，提示“epoch 已过期”；台账、Run、Checkpoint 里没多出任何东西。
- **门禁**：§8.2 中本行为测试、Ruff/Mypy（变更文件）、Git 双 Hook、Run 执行就绪、台账；修了核心代码则补跑母体全量 pytest。
- **失败出口**：任一用例不过即停、保留现场、报你；同一问题两次未解报你；不靠重跑变绿。
- **需要你定**：第二个 agent 用谁（见 §9 第 1 条）；你在场的时间段。

  2. 报告里“只在本机未跟踪的依赖”一栏是 0；不是 0 就列出文件名，不冻结。
  3. 依赖表逐项列出 D01、D02、Q01～Q03、V06、G03～G10 的完成证据，V07/V08 标“AC12 例外”。
