# 附录 05：排错速查

> 本文件汇总本机日常运行与跨会话排查的高频环境坑点，供遇到报错时查阅。规则裁决仍以 `AGENTS.md` 与 `00_Obsidian_Base全局规范文件仓库` 现行规范为准。

## 1. Windows 中文编码与路径转义

- **终端或管道乱码 / GBK 报错**：运行脚本前设置 `PYTHONUTF8=1` 与 `PYTHONIOENCODING=utf-8`。
- **Git 输出中文路径变成八进制转义**：执行 `git config --global core.quotepath false`（或单条命令带 `-c core.quotepath=off`）。
- **Git Bash 误把带冒号的 Git 引用当路径转换**（如 `HEAD:path/to/file`）：在命令前加 `MSYS_NO_PATHCONV=1`。
- **PowerShell 中文全角引号切参**：在 PowerShell 传含中文引号的参数时，改用直角引号「」或通过 UTF-8 文本文件传参（如 `--files-from`、`git commit -F`）。

## 2. 换行符差异（CRLF vs LF）

- Windows 检出文件常为 CRLF，而 Git blob 对象多为 LF。对比工作区文件与 Git 提交内容时，先统一规范化换行符后再做字节比对，避免把纯换行符差异误判为内容冲突。

## 3. 现役发布快照、`-B` 与字节码报错（退出码 4）

- 控制根 `main.py` 委托启动器执行 `00_Infrastructure/auto_pm/active_release.json` 指向的现役发布快照，**不是** `SW8/` 源码目录。调用驾驶舱命令须在控制根用 `.venv` 的 Python 并携带 `-B`（禁止生成 `__pycache__`）。
- 若启动器发现现役发布目录混入 `__pycache__` 而以退出码 4 拒绝启动，运行：
  `python -B 00_Infrastructure/auto_pm/launcher/launch.py --purge-bytecode`
  清理完字节码后重试。

## 4. 发版切换后的指针保护与 PowerShell `sh.exe`

- `release deploy` 切换现役版本后、发布目录与指针文件尚未经变更单并入 `main` 前，严禁对 `00_Infrastructure/auto_pm/active_release.json`、`previous_release.json`、`deployment_manifest.json` 执行 `git checkout`、`git reset` 或 `git stash`。
- 若需回退到早于 `1.3.3-d356fb1` 之后的旧发布且在 Windows PowerShell 中触发找不到 `sh.exe`，确认已安装 Git for Windows 并将 `Git\bin` 或 `Git\usr\bin` 加入 `PATH`。

## 5. 目录清理安全（工位与报告目录）

- **清理 `.auto-pm/worktrees/` 前先查联接点**：在 Windows 上手动移除残留工位目录前，先检查是否含 NTFS 联接点，避免递归删除把目标目录清空：
  `Get-ChildItem -Force -Recurse -Depth 3 -Attributes ReparsePoint .auto-pm\worktrees`
- **清理 `.auto-pm/reports/` 旧目录前先检索引用**：删归档或旧实验报告前先检索现行脚本与 `git grep`，确认未被发布回滚脚本或事务日志引用。

## 6. PLC 静态检查与 TIA 实测基准边界

- SCL 源文件导入 TIA Portal 后，OB 组织块编号仍需按实际硬件组态手工复核。
