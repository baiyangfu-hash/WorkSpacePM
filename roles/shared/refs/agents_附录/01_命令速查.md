## 需要时查

名字、谁能跑、会不会写都在命令总目录里，用法看 `--help`。用之前记住这六条：

1. `plc docs sync` 补出来的行带“待确认”，要人确认后才算数。
2. `plc ingest` 先带 `--stage-only`。
3. 全量门禁（`gate run`、`long-run start`）要先告诉用户，内存总闸只有用户能动。
4. `pm retire` 默认只预演。
5. `decision list` 写本节时会报“决策包列表包含无效文件”，修好再用。
6. `spec lint` 在用户那台电脑以外必报错（注册表里写死了那台电脑的路径）。

## 只能请用户做的（AGENTS.md 红线 1）

看板上有按钮的请用户点按钮；没有按钮的，用户在本机主对话里亲口批准后，agent 带上那句话的位置去跑（能带 `--approval-evidence-ref` 的写成 `user-confirmation:<用户那条消息的时间或编号>`）。用户没说过的不跑、不代填，也不替用户点看板按钮。`pm sign-risk` 驾驶舱带凭据也拒 agent，只能交给用户在自己的终端跑。

| 场合 | 命令 |
|---|---|
| 批准和开工 | `pm approve`、`pm confirm-start`、`pm inbox confirm`、`pm inbox reject`、`decision create` |
| 验收、搁卡、收占位 | `pm accept`（日常是看板“确认验收”）、`pm park`（带凭据时）、`pm unpark`、`pm switch`、`claim reclaim` |
| 项目、发版、账本 | `project archive`、`project reactivate`、`project delete`、`project restore`、`release deploy`、`release rollback`、`continuity restore-backup` |
| 租约和风险 | `continuity lease extend-hold`、`pm sign-risk` |

变更单批准（`change transition … approved`）和推到完成，看板上有按钮的由用户点；还没有按钮的由用户在本机主对话里亲口说。其余写命令只在 AGENTS.md 允许时跑：`claim release` PR 没合不放，变更单只在本机建，`gate precheck` 跑得久、占内存算重任务。

## 不该用的（碰上就停下问）

旧交接包、`pm-session`、启动挂起执行器的 `pm context`/`pm workflow`/`pm execute`、三条单独推状态的 `continuity … transition` 和 `lease run-with-renewal`（AGENTS.md 已禁）、由提交钩子自动调用的 `git-hook` 4 条和 `worktree heartbeat`、`constraint guard`/`constraint verify`、已知有害的 `project snapshot`/`plc repair`/`template update`/`doc sync`/`spec sync`、6 条清旧数据的一次性命令、2 条 `orchestration`、旧格式实施卡的 `implementation-card create`/`dispatch`/`verify`/`approve`（只服务旧格式卡；新格式卡用表里的 `precheck`、`validate`、`by-change`）、批准口令的 `pm approver-pin init`/`status`（口令不做）。
