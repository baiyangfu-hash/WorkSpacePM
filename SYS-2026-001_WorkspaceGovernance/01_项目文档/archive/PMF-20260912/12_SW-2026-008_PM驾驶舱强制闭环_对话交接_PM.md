## 2. 用户目标与不可变边界

### 2.1 用户目标

建立一个物理上难以绕过的中心化闭环：

```text
原始需求
  -> 驾驶舱定位项目并生成事实包
  -> PLC/Fullstack 只读 Grooming
  -> 驾驶舱汇总事实
  -> PM 生成一页决策包和草稿 CHG
  -> 用户批准
  -> 领域技能执行
  -> 驾驶舱验证门禁
  -> PM 原子落账
  -> 用户验收
```

### 2.2 强制边界

- 驾驶舱负责项目定位、证据包、交接队列、变更状态、门禁和审计，不替用户作业务决策。
- PM 是唯一需求入口和落账 owner，不得无项目证据写正式方案，不直接修改 PLC/Fullstack 领域代码。
- PLC 技能只负责 SCL、控制抽象、状态机、接口和静态检查，不涉及实际硬件控制。
- Fullstack 技能负责驾驶舱 Python/QML、HTML 工艺原型、DTO 和自动化测试。
- Obsidian 是规范真源，不保存项目运行状态；任何规范变更必须经用户批准。
- Quick Track 只能减少人工等待，不能跳过变更记录。
- 紧急维修仅在稳定驾驶舱不可用时启用，维修后必须补齐 SYS 治理记录和证据。

## 8. 阶段 1 一页决策包

### 用户原话

从现在开始必须使用 PM + 驾驶舱，把现有技能契约和 handoff 骨架从“建议遵守”升级为“物理上无法绕过”。

### 已验证现状

- 驾驶舱已能创建和消费 handoff，但不能启动技能。
- 队列声明了中间状态，但没有领取、运行、超时和提交结果的状态迁移。
- Quick/Full 分类器存在，但未接入完整审批和执行链。
- handoff JSON 自身可原子消费，但 PM 多资产落账不是 Saga。
- Dogfood 隔离骨架存在，但部分关键证据仍可选。
- 只读项目查询会改写 Git 跟踪的运行态文件。

### 推荐方案

采用增量 Full Track，不推倒现有代码：

1. 第一批只批准 WBS-C1，先建立可信事实包和真正不污染 Git 的预检。
2. C1 全绿后实施 C2/C3，把执行生命周期和决策包接起来。
3. 再实施 C4/C5，把分类和证据真实性下沉为硬门禁。
4. C6 完成跨资产 Saga。
5. C7 使用 SW-2026-008 自管理和 DJ-2026-005 消费验收完成 Dogfood。

### 推荐执行器架构

驾驶舱核心只定义 `ExecutorAdapter` 契约，不直接耦合某个 IDE：

- `manual`：生成可领取任务，人工/现有 AI 会话领取。
- `codex`：对接可用的 Codex 子代理能力。
- `trae`：后续对接 Trae 可调用入口。
- 不支持的 provider 必须明确失败，不能把“已生成 JSON”显示为“已派发”。

### 替代方案

- 一次性实现 C1 至 C7：周期短但回归面和自证风险过大，不推荐。
- 只更新技能提示词：无法提供物理门禁，不能满足目标。
- 只增加 GUI 启动按钮：状态、证据和落账仍不可信，不能满足目标。

### 第一批影响范围

预计仅涉及：

- `00_Infrastructure/auto_pm/auto_pm/application/`
- `00_Infrastructure/auto_pm/auto_pm/contracts/`
- `00_Infrastructure/auto_pm/auto_pm/ui/cli/`
- `00_Infrastructure/auto_pm/tests/`
- 根 `.gitignore` 和被误跟踪运行态的治理需要单独 SYS 记录
- `CHG-SCPT-2026-156`、SW PM_SESSION 和 SYS PM_SESSION 仅由 PM 落账

第一批不涉及：

- PLC/HMI 业务程序
- 真实硬件
- Obsidian 规范改写
- 驾驶舱 GUI 扩张
- 删除历史变更单或五大过程组

### 第一批验收标准

- 项目事实包包含 Git SHA/状态、项目路径、PM_SESSION 指纹、开放 CHG、规范快照、代码结构摘要和可用门禁。
- 事实采集不修改任何 Git 跟踪文件。
- 缺失、过期或项目身份不一致的事实包被硬拒绝。
- 未消费 Grooming 时不能生成正式决策包。
- 相关 pytest、Ruff、Mypy、`auto_pm python check SW-2026-008`、doctor 和 spec check 全绿。
- 工作树只包含已批准范围，运行态不进入提交。

### 风险与回退

- 风险：事实包成为第二套账本。
  - 控制：事实包只保存指纹和引用，PM_SESSION 仍是项目事实真源。
- 风险：read-only 与运行态写入概念混淆。
  - 控制：允许写入被忽略的证据目录，但禁止修改 Git 跟踪资产。
- 风险：provider 绑定导致其他 AI 不可用。
