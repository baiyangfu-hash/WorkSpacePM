# PM-042 变更授权与执行状态边界（候选差异方案）

**状态**：候选，未修改正式 PM-042。
**变更单**：CHG-SPEC-2026-013；**上位候选**：文档 20。

## 1. 保留与修订

PM-042 的审批、状态机、append-only 历史和关闭原则继续有效。修订只解决两类问题：CHG 被误作执行进度库，以及过时命令/事后补单被当作常规路径。

## 2. 拟定职责划分

| 对象 | 唯一职责 | 不得承担 |
|---|---|---|
| CHG | 授权范围、审批条件、风险接受、关闭结论 | Work/Run 实时进度和 Agent 会话内容 |
| Work / Run | 已授权范围内的执行状态、基线、证据 | 改变或扩大 CHG 授权 |
| PM_SESSION | 当前项目治理摘要和引用 | 原始执行流水 |

Work 创建必须引用已批准 CHG（或规范定义的紧急例外）。CHG 关闭必须汇总已完成 Work/Run 的验证证据，但不得反向以“执行完成”推定授权。事后补写只可作为异常处置：必须有原因、审批人、时间窗和证据，不得使用源码标签或口头说明替代。

## 3. 操作语义与验证

最终规范使用 `AUTO_PM_ENTRY change ...`、`AUTO_PM_ENTRY ledger reconcile ...` 等语义命令，发布前以实际 launcher `--help` 核验其参数；不能再从历史文档复制失效参数。候选阶段不运行修复型台账命令，不修改既有 CHG 或台账。

验收要求是：无批准 CHG 的写入 Work 被拒绝；CHG 批准后 scope 外 Work 被拒绝；关闭时证据缺失被拒绝；例外记录可追溯且会过期。
