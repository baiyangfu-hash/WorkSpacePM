## 5. 规则（沿用，未变）

1. **四阶段**：澄清、报批、执行、验收；不得绕过卡、变更单、决策、Work、Run 与租约；PM 角色是主 Agent 的治理角色，`pm-workflow` 已隔离停用。
2. **门禁判卷**只采信底层检查的退出码；失败即停、保留现场、不靠重跑变绿；同一问题两次未解就通知用户。
3. **并行**：改核心存储、哈希链、Hook/门禁、共享夹具的卡全仓同一时刻只能一张；只读简报、审阅与文档卡可并行，开工前写明 owned paths 且不重叠；做的 agent 与审的 agent 不是同一个；并行时只由当前那张核心卡写回本文件与台账，并行的文档卡与审阅卡不写，以免 owned paths 重叠。
4. **`main` 只走 PR**：规则集 `main-protect`（必须 PR、禁止强推与删除、必须解决评审对话、仅合并提交）；用户 2026-10-18 授权 Claude 合并，条件是另一会话独立审计通过、CI 与门禁全绿、评审对话已解决，只用合并提交、不用 `--admin`，合并后告诉用户；本文件的改动同样走 PR。
5. **边界**：PLC 交付停在静态语法自检；插件二进制不入库；规范库只经已批准的变更单修改；`AGENTS.md` 只在已批准的卡里改；仓库在驾驶舱完工前保持公开；持续演进规划目录不入 Git。
6. **删除与卫生**：治理证据绝不删除；清理先列清单、先备份。
7. **口令信任模型**（TD-SW008-065，用户 2026-10-10 书面裁决）：单用户本机信任模型。租约口令明文只存在控制根的 `.auto-pm/continuity.db` 与本机钱包 `.auto-pm/cache/lease-wallet/`，二者都不入 Git；口令不进命令行参数、不进命令输出、不进 Git 与聊天；agent 不得签署“接受风险”。
8. **委托范围**（用户 2026-10-18）：普通核心卡与文档卡由 Claude 自行报批、跑门禁、收口并推送 PR 分支；合并到 `main` 按第 4 条由 Claude 做；仍先问用户的只有删除文件或证据、切换发布版本与部署、里程碑验收与 D09、规范库改动；重载门禁一律排在晚上 21:00（亚利桑那时间）以后，用户白天要用这台电脑。
