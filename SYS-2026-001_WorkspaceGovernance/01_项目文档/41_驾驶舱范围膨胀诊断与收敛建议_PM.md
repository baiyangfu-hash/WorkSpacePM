## 3. 膨胀是怎么发生的（不是谁的错，是机制）

1. **“只加不删”+“每做一张卡就回写一次”**：每张实质卡都会派生一张 WBS 写回卡和一张台账写回卡，写回卡本身又需要被下一张写回卡登记。这是一个自我繁殖的回路。V0.3 已经定了“记账卡配额”，但配额是“最多一张”，没有切断回路。
2. **审计放大器**：项目 Claude、Gemini、DeepSeek、GPT 的审计每次都能找到“属实的小问题”，每个都变成一张修复卡 + 一条债务 + 一次写回。审计越多，范围越大；而这些发现大多不影响 D08 能否完成。
3. **AI 执行成本低，让“顺手做”的门槛消失**：以前要花一周的事现在一晚上就能做完，于是“值不值得做”这个问题被跳过了。工具越好用，越需要一个硬的“不做清单”。
4. **目标在悄悄换**：§1.1 的目标是“一个用户可以日常使用的 PM 工作流”；`40` 号文件说驾驶舱“只做三件事：给任务、收结果、验收与记录”。而 COLLAB 的 A8“账本主机”、B“跨机共享状态”、V04-R1 的多写入者 epoch，是在做一个**分布式协作平台**——这是另一个产品。
5. **从没有真用过**：M1、M2 的“真实任务”都是驾驶舱改它自己。没有真实客户项目的痛点来裁剪，只能靠想象“以后可能需要”，范围自然无限。

## 4. 建议

### 4.1 立刻做：冻结 M3，定义“M3 最短路径”

M3 的退出标准本来就写着：“全部 AC、制品一致性、兼容回退、全量门禁与 D08 均有证据”。按这个反推，建议只保留：

| 保留 | 理由 |
|---|---|
| D03 固定提交集合 → D04 构建 → D05 全量门禁 → D06 回退演练 → D07 切换 | M3 退出标准原文 |
| **D08 用一个真实业务项目做**（至少一次 PLC 静态、一次 Python、一次跨会话恢复） | 这是唯一能证明“驾驶舱有用”的证据 |
| D09 最终判定 | 收口 |
| `M3-ENVPORT`（已完成）、`M3-DBBACKUP`（小卡，数据安全） | 便宜且保护已有成果 |
| D08 过程中**真实遇到**的缺陷 | 按 M2 冻结条款②：修缺陷，不加功能 |

建议移出 M3、进入“M3 之后的需求池”（不删，只是不排期）：

- `M3-COLLAB` 的 A6～A9 与 B（跨机共享状态、账本主机、两机两 agent）
- V04-R1 存储接入卡与真实进程演练卡（AC08 已由 V03/V04 在 M2 覆盖；多写入者 epoch 是为多机协作服务的。若 D08 的跨会话恢复真的失败，再拿回来）
- `M3-CF`（编译报错反馈通道）、`M3-FIG`（图文一致性）——它们是好想法，但应该由 D08 的真实项目来证明需要
- `M3-INV`、`M3-REPOGOV`、`M3-HYG-MIN` 剩余项、V07/V08 的“从基准提取”、持续演进规划首批（B01/B02/G01/O01）

做法完全可以照搬你在 M2 用过且有效的“冻结条款”（§4.11 的 M2 冻结条款 ①～⑤），只是把基线换成上表。

### 4.2 切断记账回路

- **零独立记账卡**：WBS 与台账的写回只能作为实质卡的最后一步，不再单独出卡、单独登记任务行、单独写变更单。V0.3 的“最多一张”改成“零张”。
- **WBS 改成“短投影 + 归档”**：39 号文件冻结为历史（改名或移入 `archive/`），新建一份不超过 200 行的当前投影：目标、M3 最短路径、每行一个状态、下一步。历史写回节（§4.7.1～§4.7.28）只留在归档里。判断标准：你自己能在 3 分钟内读完并说出“还差什么”。
- **任务行只为成果开**：没有用户可观察结果的事（写回、补入库、措辞更正）不占任务行。

### 4.3 给审计设闸门

外部/项目 Claude 审计的发现，先回答一个问题：**“它会让 D08 失败吗？”** 会，就修；不会，进需求池，不出卡、不登记债务。安全类与数据丢失类例外。

### 4.4 给新想法设闸门（每次冒出来时问三句）

1. 它在 AC01～AC14 里吗？
2. 没有它，D08 的三次真实交付会失败吗？
3. 如果它推迟到 M3 之后，我会损失什么？

三句都答不出“会/有损失”，就写进需求池，一行，不展开方案。

### 4.5 设时间盒

建议给 M3 最短路径一个硬期限（例如两周），到期按实际结果裁决：要么验收，要么砍范围，**不延长范围**。D08 选一个你本来就要做的真实项目，让驾驶舱为它服务，而不是反过来。
