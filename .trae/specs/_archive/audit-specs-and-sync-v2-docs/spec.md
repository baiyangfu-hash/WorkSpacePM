# 规范体系审查与 V2.0 文档全量同步 Spec

## Why

SW-2026-008 (auto-pm) V2.0 已完成实施（阶段0~G 全部 ✅，275+ 测试通过），但深度审查发现三类待解决问题：

### 问题 1：文档与实际实现脱节

| 文档 | 当前状态 | 实际状态 | 差距 |
|------|---------|---------|------|
| TEC | V1.0.0 草稿 | V2.0 已实现 PySide6 架构 | TEC 未升级到 V2.0.0，仍描述旧 pywebview 架构 |
| PRD §10.2 | 记录 5 项实现偏差 | 偏差已成为实际基线 | 偏差记录应整合为正式基线，而非"待补录"状态 |
| INT §3.3 | 声明 SVC-06/07/08 三个新方法 | 实际 CLI 层直接处理 | 接口文档与实际 Service API 不一致 |
| DSN §4.1 | 声明 `auto_pm/ui/` 五层结构 | 实际有 8 个子模块 | DSN 架构图未反映 navigation/change_center/dialogs 等实际模块 |

### 问题 2：规范体系自身存在隐患

经初步核查，规范注册表 (`spec_registry.json`) 与实际规范文件存在潜在不一致：

- **规范覆盖范围**：Python 侧仅 4 个规范（210/211/215/220），缺少 GUI/PySide6/Click CLI 等专项规范
- **PLC 侧规范**：LSP-905/904/903/906/907 + 023/815 共 7 个，但 906 错误预防规则是否覆盖 V2.0 实践中的新问题待核查
- **PM 侧规范**：数量最多（20+），但 040/042 变更管理规范与 auto-pm V2.0 变更管理实现的对接关系未文档化
- **spec_registry.json**：`last_updated: 2026-05-27`，但 V2.0 实施在 2026-06-19 完成，注册表可能未同步

### 问题 3：参考项目暴露工具与规范双重问题

| 项目 | 暴露的 auto-pm 问题 | 暴露的项目自身问题 |
|------|---------------------|---------------------|
| DJ-2026-000 | auto-pm 生成的 REQ 文档是空模板（"待填写"占位符），工具未引导填写 | REQ/TEC 文档均为空模板，项目需求未实质化 |
| SysLib | 同上，库项目的 REQ 也是空模板 | 同上 |
| SW-2026-004 | auto-pm 未识别 004 的 PyQt5 vs PySide6 技术栈不符、UserStore 硬编码、API 路由无 auth 等问题 | PRD 声明 PySide6 实际 PyQt5；UserStore 硬编码违反安全红线；影响分析未持久化 |

**根因**：auto-pm V2.0 聚焦"项目骨架生成 + 结构检查"，但缺少"需求文档实质化引导"和"规范合规深度检查"能力；同时规范体系本身未随 V2.0 实践迭代更新。

## What Changes

### 1. 规范体系审查与修订建议（核心交付）

- **审查 Python 规范**（210/211/215/220）：核对 V2.0 实际代码是否遵循，识别规范过时/遗漏条目
- **审查 PLC 规范**（LSP-905/904/903/906/907/908 + 023/815）：核对 DJ-2026-000/SysLib 是否遵循，识别规范缺口
- **审查 PM 规范**（040/042 变更管理 + 010/016 项目结构）：核对 auto-pm 变更管理实现与 PM-042 对接关系
- **审查 spec_registry.json**：核对注册表与实际规范文件的一致性（路径/版本/lifecycle/aliases）
- **输出规范修订建议清单**：针对每个规范提出修订建议（过时条目/新增条目/冲突条目）

### 2. 全量文档同步到 V2.0.0 实际状态

- **TEC 升级**：V1.0.0 草稿 → V2.0.0 已批准，重写技术方案对齐 PySide6 实际架构
- **PRD §10.2 整合**：将"实现偏差"记录整合为正式基线，消除"待补录"状态
- **INT 核对**：核对 CLI-07/SVC-06/07/08 等接口声明与实际实现一致性
- **DSN 核对**：核对架构图/模块划分与实际 `auto_pm/ui/` 8 个子模块一致性
- **CHANGELOG/README 同步**：反映 V2.0 最终交付状态

### 3. 参考项目双重审查

- **DJ-2026-000 / SysLib 审查**：
  - 验证 auto-pm 能否正确识别/扫描/管理（`project list`/`project show`/`plc check`）
  - 审查 REQ 空模板问题，提出"需求文档实质化引导"改进建议
- **SW-2026-004 审查**：
  - 验证 auto-pm 能否识别 004 的技术栈不符/安全问题
  - 审查 004 自身问题清单（PyQt5/UserStore/API auth/影响分析未持久化），提出修复建议

### 4. auto-pm 改进建议（不实施，仅记录）

基于审查发现，输出 auto-pm 后续版本（V2.1+）的改进建议：
- 需求文档实质化引导能力
- 规范合规深度检查能力（不仅结构检查，还包括安全/技术栈一致性）
- 规范注册表自动同步能力

## Impact

  - SW-2026-008 PRD/INT/DSN/TEC → 全量同步到 V2.0.0 实际状态
  - 210/211/215/220 Python 规范 → 审查并输出修订建议（不直接修改规范文件）
  - LSP-905/904/903/906/907/908 PLC 规范 → 审查并输出修订建议
  - 040/042 PM 变更管理规范 → 审查与 auto-pm 对接关系

  - 改进建议记录到 tasks.md 供后续版本实施
- **Affected docs**：
  - SW-2026-008 的 PRD/INT/DSN/TEC 将全量同步
