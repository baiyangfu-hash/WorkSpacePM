# 智能体团队协作SOP（文档先行·敏捷增量版）
**适用场景**：Python项目和PLC工控项目开发，遵循"文档先行、敏捷迭代、轻量化、减少第三方依赖"原则
**核心角色**：产品化项目经理、技术负责人、文档专家、开发工程师、测试工程师、PLC专家
**AI智能体快速启动**：Trae可直接根据SOP阶段定位对应模板，使用规范使用文档中的路径访问模板文件，严格按照模板结构生成内容

## 二、项目阶段与智能体调度流程

### 阶段0：项目启动与总需求确认
**触发条件**：用户提出项目总需求
1.  **产品化项目经理**：
    - 输入：用户原始需求
    - 输出：《总需求分析报告》（含业务目标、核心功能、约束条件）
    - 动作：与用户对齐需求边界，明确"必须做/可以做/不做"范围
2.  **用户确认**：
    - 动作：审核《总需求分析报告》，签字确认后进入下一阶段

---

### 阶段1：迭代规划（循环执行N次）
**触发条件**：总需求确认 / 上一迭代复盘完成
1.  **产品化项目经理**：
    - 输入：《总需求分析报告》、用户反馈
    - 输出：《迭代需求规格说明书》（本迭代核心功能、验收标准）
    - 动作：拆分总需求为2-4周可交付的迭代单元，明确优先级
2.  **用户确认**：
    - 动作：审核《迭代需求规格说明书》，锁定本迭代范围
3.  **产品化项目经理**：
    - 输入：《迭代需求规格说明书》
    - 输出：《迭代项目计划》（里程碑、时间节点、资源分配）
    - 动作：制定迭代排期，识别关键路径与风险点
4.  **技术负责人 + 文档专家 + PLC专家**：
    - 输入：《迭代需求规格说明书》
    - 输出：《技术方案文档》（含架构设计、依赖管理、程序框架）
    - 动作：优先选择原生库，减少第三方依赖；PLC专家负责PLC相关技术方案；文档专家审核格式与一致性

---

### 阶段2：详细设计与开发
**触发条件**：《技术方案文档》审核通过
1.  **开发工程师 + PLC专家 + 文档专家**：
    - 输入：《技术方案文档》
    - 输出：《详细设计说明书》（含流程图、逻辑说明）、《接口文档》、《PLC程序设计文档》
    - 动作：开发工程师完成Python代码设计，PLC专家完成PLC程序设计，文档专家统一格式并审核
2.  **技术负责人**：
    - 输入：《详细设计说明书》《接口文档》《PLC程序设计文档》
    - 动作：审核设计合理性，确认符合架构规范
3.  **开发工程师 + PLC专家**：
    - 输入：《详细设计说明书》《接口文档》《PLC程序设计文档》
    - 输出：可运行Python代码、PLC程序
    - 动作：严格按文档开发，每日提交代码/程序；技术负责人进行代码审查

---

### 阶段3：测试验证与缺陷修复
**触发条件**：开发完成代码/程序提交
1.  **测试工程师**：
    - 输入：《迭代需求规格说明书》《详细设计说明书》《PLC程序设计文档》
    - 输出：《测试用例》《测试报告》《缺陷跟踪表》
    - 动作：优先采用自动化测试（单元/集成测试），标记缺陷优先级
2.  **开发工程师 + PLC专家**：
    - 输入：《缺陷跟踪表》
    - 动作：开发工程师修复Python代码缺陷，PLC专家修复PLC程序缺陷，提交回归测试
3.  **循环**：测试→修复→回归，直至《测试报告》通过率达标

---

### 阶段4：迭代交付与复盘
**触发条件**：测试通过率达标
1.  **开发工程师 + PLC专家 + 文档专家**：
    - 输入：迭代代码、PLC程序、测试报告
    - 输出：《用户使用文档》《打包清单》《调试报告》
    - 动作：整理交付物，文档专家统一格式
2.  **用户验收**：
    - 动作：试用迭代版本，提交反馈
3.  **产品化项目经理 + 技术负责人 + PLC专家**：
    - 输入：用户反馈、迭代数据
    - 输出：《迭代复盘报告》（经验教训、流程优化点）
    - 动作：总结本迭代，调整下一迭代规划

---

### 阶段5：项目收尾
**触发条件**：所有迭代完成，用户验收通过
1.  **产品化项目经理**：
    - 输入：所有迭代文档、用户反馈
    - 输出：《产品化项目总结》《产品上线建议》《经验教训库》
    - 动作：基于高项收尾过程组知识，完成项目验收、移交、归档；从产品规划角度，总结产品成功经验，提出后续迭代或产品化建议
2.  **文档专家**：
    - 动作：整理全套项目文档，版本归档
3.  **产品化项目经理 + 技术负责人 + PLC专家**：
    - 输出：《项目总结报告》
    - 动作：复盘全周期，沉淀可复用流程与技术资产

---

## 三、协作规则与轻量化要求
1.  **文档轻量化**：
    - 必保文档：《需求规格说明书》《技术方案》《详细设计》《接口文档》《测试报告》《使用文档》
    - 可选简化：《项目管理计划》→《迭代里程碑清单》；《技术选型报告》→合并入《技术方案》
2.  **依赖管理**：
    - 技术负责人必须在《技术方案》中明确所有依赖，优先使用PLC原生功能块，禁止不必要的第三方库
3.  **自动化调度**：
    - 前一角色输出审核通过后，自动触发下一角色任务（如产品化项目经理输出需求→自动通知技术负责人启动技术方案设计）
4.  **每日同步**：
    - 产品化项目经理组织15分钟站会，所有角色同步进度、暴露阻塞问题

### 5.2 Trae执行流程

1. **识别阶段**：根据用户需求确定当前项目阶段
2. **选择模板**：在快速参考表中查找对应阶段的模板
3. **访问模板**：使用模板路径直接访问模板文件
4. **生成内容**：严格按照模板结构生成文档
5. **质量检查**：使用AI输出质量检查清单进行检查
6. **交付成果**：提交生成的文档并等待产品化项目经理确认（需求确认环节需用户确认）

### 5.3 最佳实践

- **文档先行**：先生成文档，再进行开发
- **模板化**：严格使用规范模板，确保一致性
- **质量控制**：每次生成后进行质量检查
- **版本管理**：遵循语义化版本规范
- **变更记录**：使用变更管理模板记录所有变更
- **角色闭环**：产品化项目经理统筹全流程需求、进度、复盘，确保端到端的项目与产品管理一致性
