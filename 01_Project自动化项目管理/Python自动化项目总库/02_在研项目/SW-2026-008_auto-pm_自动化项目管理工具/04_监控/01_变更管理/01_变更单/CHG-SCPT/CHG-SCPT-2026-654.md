## 4. 变更原因

**变更背景**：
看板上补项目生命周期的入口，命令行不改。工具页新增“项目”页签：新建项目（project create）和登记（project register），沿用工具页“先预览命令再运行”，两个表单各带一个默认勾着的“只试一次，不写（--dry-run）”。项目详情页新增“项目状态”一块：点“归档…”或“重新激活…”先跑不带 --confirm 的预演，把五项检查的输出原样摆出来，退出码 0 并且是预演才出现“确认归档”或“确认重新激活”；确认时用决定页现成的确认框和凭据（decisions.click_evidence），口令启用时改在新终端窗口里由用户本人输口令，看板不收口令、不预填用户原话。全部项目页加“新建项目…”跳页按钮。删除和恢复不上看板。改一条看板自己的规矩：policy.py 和 README 里“项目经理看板只读”改成“除决定类按钮外只读”。发版切换前的降级：现役 1.3.3-8573102 没有 project archive、project reactivate，register 没有 --kind；看板用 --help 探测，命令不存在时归档、重新激活两个按钮灰着并写明原因，登记的“性质”一栏灰着，切换后自动可用。看板起命令时原样带环境变量，不删改 agent 标记。只改 scripts/cockpit_board 和测试，不进发布载荷，不改命令行、账本和登记表格式；看板不替用户提交登记表。

**变更必要性**：
用户 11-12 指出项目生命周期管理缺失（新建、归档）。命令行已有新建、登记，652 加了归档和重新激活，但看板上没有入口，用户要记命令、敲终端。周一要给用户看“一个项目从新建到归档，看板点得通、命令行走得通、同一本账”。

### 12.1 填写指南

#### 如何选择技术领域?
- 主要改哪个专业的交付物,就选哪个领域
- 如果同时涉及多个专业,选**最主要**的那个作为主领域,其他在§6.2中标注

#### 如何判断影响范围?
- **LOCAL**: 改一个变量/一行代码/一个接线端子
- **MODULE**: 改一个FB/一条输送线/一台设备
- **SYSTEM**: 改全局变量/联锁逻辑/通讯接口
- **CROSS**: 改了电气,PLC和HMI都要跟着改
- **SAFE**: 动了急停回路/安全继电器/SIL相关
