## 4. 变更原因

**变更背景**：
A4 已提供只读老板驾驶舱和连续性展示，但已批准的 Work 目前只改变状态，尚不能以受控、可审计的方式选择执行适配器、隔离工作树并在不同 Agent 间转移租约。

**变更必要性**：
落实 Cockpit OS A5：在 Continuity v2 真源上建立 Codex、Trae 与手工执行适配器、默认拒绝的授权策略、受限 Git worktree 选择及 checkpoint-bound handoff.v2 接力；不启用 pm-workflow，不改稳定部署或业务靶项目。

**参考依据**：
37_Cockpit_OS_超级特种兵大一统目标架构与迁移总方案_PM.md；用户于 2026-09-10 明确批准 A5 开工；A4 基线 02956026

## 5. 变更内容

### 5.1 变更前（当前状态）

| 项目 | 当前值/描述 |
|------|-----------|
| 涉及文件/交付物 | Continuity v2 已有 Work、Run、lease、Checkpoint 与 handoff.v2；A4 的 PM Facade 只将已批准 Work 从 READY 推进为 IN_PROGRESS。 |
| 关键参数/配置 | 没有执行适配器白名单、并发上限或可审计的 worktree 选择策略；不能以统一、秘密隔离的方式准备 Codex、Trae 或手工执行包。 |

### 5.2 变更后（目标状态）

| 项目 | 目标值/描述 |
|------|-----------|
| 涉及文件/交付物 | `ExecutionAdapterKind`/收据契约、`ExecutionDispatchService`、`WorktreePolicyService`、`continuity dispatch prepare` CLI 以及契约、核心和 CLI 回归测试。 |
| 关键参数/配置 | AuthorityEnvelope 默认拒绝执行适配器；允许项仅为 `codex`、`trae`、`manual`，且设定 `max_parallel_runs`。受控根目录脏时仅在授权后创建 `.auto-pm/worktrees/<run-id>` 隔离工作树，绝不复用、覆盖、清理或删除现有工作树。 |

`prepare` 仅建立本地 Run/lease 并输出无 token 的 `PREPARED` 收据；它不会发送远程消息、启动 Codex/Trae 会话，也不会声称外部 Agent 已接单。

## 6. 变更影响分析

### 6.1 项目约束影响（PMBOK五大约束）

| 约束维度 | 影响程度 | 影响描述 | 应对措施 |
|---------|:--------:|----------|----------|
| **范围(Scope)** | □无 □低 ☑中 □高 | Continuity v2 增加受控本地派工准备能力 | 严格限定在 Decision 白名单路径与本单 Mission/Work/Run |
| **进度(Schedule)** | ☑无 □低 □中 □高 | 不改变发布节奏 | 不触碰稳定部署、发布指针或业务靶项目 |
| **成本(Cost)** | ☑无 □低 □中 □高 | 无外部服务、网络调用或新增依赖 | 使用现有运行时与 Git worktree |
| **质量(Quality)** | □无 □低 ☑中 □高 | 新增 fail-closed 授权、隔离和交接覆盖 | 契约、服务、CLI、静态与回归门禁 |
| **风险(Risk)** | □无 □低 ☑中 □高 | 错误派工或覆盖工作树会影响连续性 | 默认拒绝、唯一命名、禁止自动清理、无远程副作用 |

**风险等级**（PMBOK风险评估）：□无 □低 ☑中 □高

## 12. 附录

### 12.1 填写指南

#### 如何选择技术领域?
- 主要改哪个专业的交付物,就选哪个领域
- 如果同时涉及多个专业,选**最主要**的那个作为主领域,其他在§6.2中标注

#### 如何判断影响范围?
- **LOCAL**: 改一个变量/一行代码/一个接线端子
- **MODULE**: 改一个FB/一条输送线/一台设备
- **SYSTEM**: 改全局变量/联锁逻辑/通讯接口
- **CROSS**: 改了电气,PLC和HMI都要跟着改
- **SAFE**: 动了急停回路/安全继电器/SIL相关
