## 4. 变更原因

**变更背景**：
M2-V04：按卡 052 V1.0 用真实进程与真实时间演练进程中断与租约到期恢复：执行进程被杀如实记为失败、主控被杀 Run 留在运行中且重启不会启动第二个执行器、到期不冒记成功、到期 Run 经真实 continuity 命令结算为取消并被围栏、同一 Work 以新 Run 续做；并修复演练发现的两个真实缺陷：E06 对账（resolve_started_run 把 Run 执行者与回执的 executor_id 比较，而真实派发里 Run 记的是回执的 owner_id，所以原 session 永远认不出来），以及多个进程同时使用存储时对 WAL 边车文件瞬时状态的误报（写路径的路径校验遇到暂时异常的 -wal、-shm 就拒绝，第 1 期的并发入箱测试在演练的九组回归里负载下失败过一次；严格只读快照读 -shm 时别的进程有事务则 Windows 拒绝读取，r02 在 20 次重复里失败 1 次）；在活动技术债台账追加 TD-SW008-074～077

**变更必要性**：
WBS V04 要求在真实进程下演练进程中断与租约到期恢复；演练发现 E06 的主控重启对账在真实派发路径上永远认不出原 session（单元测试用手造对象掩盖了它），以及多进程同时打开存储时对 WAL 边车瞬时状态的误报，须修复并让测试能抓住；勘测同时发现主控重启后没有受支持的续做入口，须先在台账登记（台账规则 §4.3）；后续 V04-R1 依赖本任务

**参考依据**：
CARD-SW008-M2-V04 V1.0；CARD_SHA256=131edf48c03a62e9ff21a41b4e183e6a88c86023dc543deb6b95842b5d36d495；BASE=4e165cf4a6c36925e8c29cfdc4c392203c87096c；WBS=57e14c194fdcc9c69fa601223240d68589472747；委托执行：用户在对话中明确回复“批准”（批准卡 052 V1.0；批准发生在卡的最终字节与其 SHA-256 已向用户报告之后，其后卡字节未变），由 claude-sonnet-5-5 代为运行；最终验收由用户做出，CHG 收口须经用户确认后才可代跑

## 12. 附录

### 12.1 填写指南

#### 如何选择技术领域?
- 主要改哪个专业的交付物,就选哪个领域
- 如果同时涉及多个专业,选**最主要**的那个作为主领域,其他在§6.2中标注

#### 如何判断影响范围?
- **LOCAL**: 改一个变量/一行代码/一个接线端子
- **MODULE**: 改一个FB/一条输送线/一台设备
- **SYSTEM**: 改全局变量/联锁逻辑/通讯接口
- **CROSS**: 改了电气,PLC和HMI都要跟着改
- **SAFE**: 动了急停回路/安全继电器/SIL相关
