## 4. 变更原因

**变更背景**：
M2-V03：按卡 050 V1.0 新增 tests/e2e/test_pmf_handoff.py，用真实子进程经真实 continuity 命令行证明检查点绑定的交接（handoff.v2）：交接后旧 owner 的写入全部被拒且不留事件、接收方继续同一 Work、口令不泄露、重放幂等、链式交接逐级围栏；并在活动技术债台账追加 TD-SW008-063～069（项目管理层没有换 Agent 入口、口令多经命令行参数传递、口令明文存库、入口不分类且无分诊队列、没有可安装的薄入口、旧 pm-workflow 仍被 Git 跟踪、技能 README 仍推荐它）；不改任何产品文件

**变更必要性**：
WBS V03 要求证明“第二 Agent 接同一 Work、旧 owner 后续写入被拒”；交接机制目前只在服务层与单元测试里，没有真实进程经命令行的端到端证明；勘测同时发现项目管理层没有换 Agent 入口、口令多经命令行参数传递，须先在台账登记（台账规则 §4.3）；后续 V04～V08 依赖本任务之前的演练链

**参考依据**：
CARD-SW008-M2-V03 V1.0；CARD_SHA256=fbd566e422095a2054a3f5f6738199ff27311135e69b714e2be9c1711336a1f5；BASE=b6668dcfc57fd3c661b57fba8bd390662c1d2129；WBS=57e14c194fdcc9c69fa601223240d68589472747；委托执行：用户 2026-10-04 在对话中明确回复“批准”（批准卡 050 V1.0；批准发生在卡的最终字节与其 SHA-256 已向用户报告之后，其后卡字节未变），由 claude-sonnet-5-5 代为运行；最终验收由用户做出，CHG 收口须经用户弹窗确认后才可代跑

## 12. 附录

### 12.1 填写指南

#### 如何选择技术领域?
- 主要改哪个专业的交付物,就选哪个领域
- 如果同时涉及多个专业,选**最主要**的那个作为主领域,其他在§6.2中标注

#### 如何判断影响范围?
- **LOCAL**: 改一个变量/一行代码/一个接线端子
- **MODULE**: 改一个FB/一条输送线/一台设备
- **SYSTEM**: 改全局变量/联锁逻辑/通讯接口
- **CROSS**: 改了电气,PLC和HMI都要跟着改
- **SAFE**: 动了急停回路/安全继电器/SIL相关
