## 4. 变更原因

**变更背景**：
M2-GOV-IC01 requires a first-class implementation-card contract instead of free-form Markdown.

**变更必要性**：
Bind WBS, immutable baseline, owned paths, quality gates, Decision, Work, Run and Checkpoint in one machine-verifiable fail-closed contract.

**参考依据**：
WBS V3.0.5 §4.7.1；CARD-SW008-M2-GOV-IC01 V1.2；不可变基线 `4851fce49739ec192acb7a62b48ab31df0961b57`；纠正 Decision `DEC-20260928-M2IC0102`。

## 6. 变更影响分析

### 6.1 项目约束影响（PMBOK五大约束）

| 约束维度 | 影响程度 | 影响描述 | 应对措施 |
|---------|:--------:|----------|----------|
| **范围(Scope)** | ☑低 | 固定八个产品路径与两个提交证据路径 | 任何第十一条路径均 fail-closed |
| **进度(Schedule)** | ☑低 | 单次有界纠正，无额外迭代 | 最多一个纠正 Run |
| **成本(Cost)** | ☑低 | 仅本地开发与验证成本 | 周额度剩余 20% 为硬停止线 |
| **质量(Quality)** | ☑中 | 修复提交快照与实施卡授权范围不一致 | Checkpoint 和最终 commit diff 必须覆盖十路径并集 |
| **风险(Risk)** | ☑低 | 错把治理证据纳入产品门禁，或遗漏治理证据导致 hook 拒绝 | 两类路径分组建模，自动化负向测试锁定边界 |

**风险等级**（PMBOK风险评估）：☑低

**缓解措施**（风险应对策略）：
使用不可变基线、十路径精确授权、一次纠正 Run、当前字节哈希、严格 Mypy、Ruff、定向 pytest 与 `git diff --check`；禁止第十一条路径及绕过 Git hook。

## 12. 附录

### 12.1 填写指南

#### 如何选择技术领域?
- 主要改哪个专业的交付物,就选哪个领域
- 如果同时涉及多个专业,选**最主要**的那个作为主领域,其他在§6.2中标注

#### 如何判断影响范围?
- **LOCAL**: 改一个变量/一行代码/一个接线端子
- **MODULE**: 改一个FB/一条输送线/一台设备
- **SYSTEM**: 改全局变量/联锁逻辑/通讯接口
- **CROSS**: 改了电气,PLC和HMI都要跟着改
- **SAFE**: 动了急停回路/安全继电器/SIL相关
