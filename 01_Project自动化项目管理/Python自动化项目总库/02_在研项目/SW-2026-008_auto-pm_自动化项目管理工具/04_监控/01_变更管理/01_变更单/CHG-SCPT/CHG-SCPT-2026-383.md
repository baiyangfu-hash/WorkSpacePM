## 4. 变更原因

**变更背景**：
F01-a：删除 PLC 工程标记（.plc.json）后提交钩子与阶段门同时失效（独立审计 F01，TD-SW008-078）：钩子靠暂存区里有没有标记来识别 PLC 工程，阶段门靠工作区，标记一删两处都当作“不是 PLC 工程”而放行。按卡 057 V1.0 以 Git HEAD 为身份来源做失败关闭：HEAD 有标记而暂存区（钩子）或工作区（阶段门）没有就拒绝，不放行任何改名或移动（提示移动或退役走 F01-b），无 Git 的独立使用与未出生仓库保持原合同，Git 读取故障失败关闭；新增一个只读 Git 辅助模块、改提交钩子与阶段门各一处，并给三个既有测试文件追加 27 个测试；6 个路径（3 个产品、3 个测试），不新增存储、不改 checker

**变更必要性**：
删除 PLC 工程标记后提交钩子与阶段门同时放行，让“PLC 文档与代码一致”的两道防线可被一个删除动作绕过；V05、V08 与部署都建立在这两道防线上，必须先修；台账 TD-SW008-078

**参考依据**：

## 12. 附录

### 12.1 填写指南

#### 如何选择技术领域?
- 主要改哪个专业的交付物,就选哪个领域
- 如果同时涉及多个专业,选**最主要**的那个作为主领域,其他在§6.2中标注

#### 如何判断影响范围?
- **LOCAL**: 改一个变量/一行代码/一个接线端子
- **MODULE**: 改一个FB/一条输送线/一台设备
- **SYSTEM**: 改全局变量/联锁逻辑/通讯接口
- **CROSS**: 改了电气,PLC和HMI都要跟着改
- **SAFE**: 动了急停回路/安全继电器/SIL相关
