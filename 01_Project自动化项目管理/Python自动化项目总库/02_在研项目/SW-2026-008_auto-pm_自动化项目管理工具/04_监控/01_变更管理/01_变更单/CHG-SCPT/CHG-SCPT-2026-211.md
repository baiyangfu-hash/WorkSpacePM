## 4. 变更原因

**变更背景**：

A6-0 在隔离工作区进行真实 Copier 预飞时发现两项可复现的创建器缺陷：中文 Python 项目名会被直接用作 package_name，违反 Python 包名校验而在没有生成资产前失败；PLC test-suite 模板创建出的 PM_SESSION 没有可解析的 Spec Snapshot，导致新项目第一次 plc check 即产生模板告警。另发现 Python 默认分类目录仍落到旧的 0100_项目，未优先接入工作空间已有的 Python 在研项目层级。

**变更必要性**：

驾驶舱应让用户以业务名称创建项目，而不是要求电气工程师理解 Python 包命名、手动挑选目录或在创建后补规范快照。本单从创建器与模板源头修复，并以真实 CLI 回归防止同类问题再次进入后续 A6 测试、靶子项目或业务线。

**参考依据**：

用户于 2026-09-10 明确授权：“批准A6-R 源头修复并继续 A6，如果模板有问题或者规范有问题，你都可以修改，不过要有变更单。”；A6-0 Checkpoint CP-SW008-A6-209-01-03；templates/python-tool/copier.yml；auto_pm/ui/cli/project.py；动态 Spec Snapshot 服务 auto_pm/domain/plc/spec_snapshot.py。

## 5. 变更内容

### 5.1 变更前（当前状态）

| 项目 | 当前值/描述 |
|------|-----------|
| Python 包名 | templates/python-tool/copier.yml 从 project_name 直接推导 package_name；中文业务名不能匹配 Python 包名规则，Copier 在创建前拒绝。 |
| Python 分类目录 | 未显式传入 --dest-dir 时，Python 项目固定落入工作区根的 0100_项目，忽略已存在的 Python 在研项目层级。 |
| PLC 初始规范快照 | plc-test-suite 模板的 PM_SESSION 没有 Snapshot；现有动态快照服务未在成功创建时调用，首轮静态检查产生模板告警。 |
| 验证覆盖 | 现有测试覆盖创建路径的一部分，但不覆盖中文项目名、优先分类目录和 PLC 新建项目的动态 Snapshot。 |

### 5.2 变更后（目标状态）

| 项目 | 目标值/描述 |
|------|-----------|
| Python 包名 | 默认包名从受校验的项目编号推导，例如 SW-2026-010 生成 sw_2026_010；展示名称继续完整保留中文。 |
| Python 分类目录 | 当工作空间存在既有 Python 在研项目层级时优先使用该层级；其他工作空间保持 0100_项目 兼容回退。 |
| PLC 初始规范快照 | 新建 PLC 项目在 Copier 成功后使用现有动态 Spec Snapshot 服务和当前 spec_registry.json 初始化其自身 PM_SESSION；不在模板中硬编码规范版本。 |
| 验证覆盖 | 新增真实 CLI 回归，证明中文 Python 名称、目录选择和 PLC Snapshot 均可用，且无用户目录审计副作用。 |
