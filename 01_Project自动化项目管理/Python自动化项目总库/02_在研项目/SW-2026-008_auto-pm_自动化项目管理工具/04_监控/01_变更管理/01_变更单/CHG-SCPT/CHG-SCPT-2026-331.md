## 4. 变更原因

隔离工作树会从 Git 基线携带历史 `active_release.json`。如果在候选
目录直接运行根 `main.py`，启动器可能按候选目录解析旧 runtime，
造成“候选源码新、执行 runtime 旧”的身份错配。

## 5. 变更内容

1. 根入口同时识别 `.auto-pm/worktrees/<candidate>` 与
   `.codex/worktrees/<candidate>/My_Workspace` 两类托管候选。
2. 托管候选直接运行 `main.py` 时以 Exit 2 fail-closed，并要求从 canonical control root 调用稳定入口。
3. 未知根且缺失稳定 launcher 时继续 Exit 2，不静默 fallback。
4. canonical 根仍解析到 configured/effective release `1.3.3-f462694`。

## 6. 风险与边界

- 不修改 `active_release.json`、`previous_release.json` 或 `releases/**`。
- 不修改历史 Checkpoint、C09/P2 历史记录或 WBS 历史。
- 仅允许对 `main` 做一次可证明的本地 fast-forward 采用；不推送、不部署、不切换 release。
- 出现第五条脏路径或 canonical 入口无法证明稳定 runtime 时立即停止。
