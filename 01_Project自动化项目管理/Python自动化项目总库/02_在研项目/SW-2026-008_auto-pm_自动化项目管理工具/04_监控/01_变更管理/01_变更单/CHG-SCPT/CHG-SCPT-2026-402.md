## 4. 变更原因

**变更背景**：
M2-GOV-CICD1：把云端执行者起草的 Linux 最小版 CI 候选（分支 claude/cloud-ci-lite-candidate，提交 82291847）按字节落地到受治理线：新增 .github/workflows/sw008-ci.yml 与 .github/sw008-ci 下 4 个工具文件（基线比较、密钥扫描、自测、Linux 已知失败基线）。工作流只读令牌、不用任何 secret、不由 fork 触发，只在非 main 分支的推送与手动触发时运行，是早期预警而不是验收证据。候选里对 .github/workflows/plc-tool-ci.yml（现存项目 SW-2026-005 的 CI）的删除不在本卡范围，该文件保持不动。只新增 5 个文件，不改产品、测试、模板、台账；不推送，不合并 main。

**变更必要性**：
项目没有任何 CI：每次提交的静态检查与回归只在本机跑，换一台机器或换一个云端执行者就没有早期预警，也看不出 Linux 与 Windows 的行为差异。云端执行者已在 GitHub 的 Linux 运行器上跑通一个最小版并证明：全量 3485 过 / 35 败，失败与记录的基线逐项一致；本卡把它落地到受治理线，它不替代本地受治理门禁

## 12. 附录

### 12.1 填写指南

#### 如何选择技术领域?
- 主要改哪个专业的交付物,就选哪个领域
- 如果同时涉及多个专业,选**最主要**的那个作为主领域,其他在§6.2中标注

#### 如何判断影响范围?
- **LOCAL**: 改一个变量/一行代码/一个接线端子
- **MODULE**: 改一个FB/一条输送线/一台设备
- **SYSTEM**: 改全局变量/联锁逻辑/通讯接口
- **CROSS**: 改了电气,PLC和HMI都要跟着改
- **SAFE**: 动了急停回路/安全继电器/SIL相关
