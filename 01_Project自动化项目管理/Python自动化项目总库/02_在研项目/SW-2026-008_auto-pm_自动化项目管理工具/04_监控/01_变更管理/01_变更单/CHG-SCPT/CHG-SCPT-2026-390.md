## 4. 变更原因

**变更背景**：
V06（钩子一半）：在隔离的真实 Git 仓库里，用产品自己的 change 与 ledger 命令造台账一致的夹具，装真实的 pre-commit 与 commit-msg 钩子，做真实的 git commit：正例放行，无变更单、变更单不存在、两个变更单、变更单未获批、归属未知的生产文件、台账与变更单不一致分别被对的钩子以对的理由拒绝，检查器崩溃也拒绝；拒绝后 HEAD 不动、暂存区原样；共 1 个新增测试文件，产品零改动；判卷反例（verdict_check.py 不在 Git）如实留作后续事项

**变更必要性**：
WBS 的 V06 要求两个钩子的负向实演：错变更单、坏台账、越权文件、预检异常分别被拒绝，且不得破坏真实用户项目来造测试；目前钩子只有单元级与探针级的测试，没有在真实隔离仓库里用真实钩子、真实 git commit 的端到端拒绝证明，也没有“同一个夹具的正例能提交”的对照

**参考依据**：
CARD-SW008-M2-V06 V1.0；CARD_SHA256=a4d675aac4ce8f0e8710fc0a85bc55c5378b4de039cc9db88cecf162aff52434；BASE=715713bb24d7439a953a2938b8751a1352495cd3；WBS=0b56b2f4de2b35effea7e100ab2c56bc1cec0bc7（V06 行）；委托执行：用户在对话中预授权批准卡 065（V06）并委托验收与收口（原话见 .auto-pm/reports/PREAUTH_M2_20261007.txt；批准条件：卡 SHA 已先在聊天报出、字节一致、机器预检通过、范围不超出卡列路径；验收与收口条件：G1～G9 全过且提交与 Checkpoint 一致）；由 claude-sonnet-5-5 代为运行

## 12. 附录

### 12.1 填写指南

#### 如何选择技术领域?
- 主要改哪个专业的交付物,就选哪个领域
- 如果同时涉及多个专业,选**最主要**的那个作为主领域,其他在§6.2中标注

#### 如何判断影响范围?
- **LOCAL**: 改一个变量/一行代码/一个接线端子
- **MODULE**: 改一个FB/一条输送线/一台设备
- **SYSTEM**: 改全局变量/联锁逻辑/通讯接口
- **CROSS**: 改了电气,PLC和HMI都要跟着改
- **SAFE**: 动了急停回路/安全继电器/SIL相关
