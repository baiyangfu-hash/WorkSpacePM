## 4. 变更原因

**变更背景**：
worktree open 的持有人记录只读 CLAUDE_CODE_SESSION_ID/CLAUDE_PID，Trae/Cursor/VS Code 记成空；会话别名漂移，同一对话收不了自己的工位；worktree close 留空目录，看板报没有登记在 Git 里的工位，且不识别孤儿目录。

**变更必要性**：
让非 Claude agent 的工位身份可核对、同一对话能收自己的工位、close 原子化并识别孤儿，减少残留和误拒。

**参考依据**：

## 6. 变更影响分析

### 6.1 项目约束影响（PMBOK五大约束）

| 约束维度 | 影响程度 | 影响描述 | 应对措施 |
|---------|:--------:|----------|----------|
| **范围(Scope)** | 中 | 改工位持有人记录、稳定会话 ID、close 原子化和看板孤儿识别；不改业务功能 | 严格按 §5.2 路径；超出即停 |
| **进度(Schedule)** | 低 | 单批完成，不拆多轮 | 先写失败测试再改 |
| **成本(Cost)** | 低 | 不新增资源 | — |
| **质量(Quality)** | 中 | 身份和 close 改动影响所有 agent；误判会误收或误拒 | Claude 与 Trae/Cursor/VS Code 各跑正反例；保留现有护栏 |
| **风险(Risk)** | 中 | 会话 ID 取值或 close 顺序改错，可能误收工位或留残留 | 原子 close + 明确残留清理；L3 + 独立审计；合并提交可 revert |

**风险等级**（PMBOK风险评估）：中

**缓解措施**（风险应对策略）：
先固定“持有人记录能写对会话 ID/PID”这一层，再改 close 和看板；Claude 的现有行为必须保持，其他 agent 的别名在同一对话内稳定。close 失败时不允许留下“登记已删、目录还在”的半状态；空目录自动清或给出明确清理命令。误收、误拒都算失败，不用人工绕过。

### 12.1 填写指南

#### 如何选择技术领域?
- 主要改哪个专业的交付物,就选哪个领域
- 如果同时涉及多个专业,选**最主要**的那个作为主领域,其他在§6.2中标注

#### 如何判断影响范围?
- **LOCAL**: 改一个变量/一行代码/一个接线端子
- **MODULE**: 改一个FB/一条输送线/一台设备
- **SYSTEM**: 改全局变量/联锁逻辑/通讯接口
- **CROSS**: 改了电气,PLC和HMI都要跟着改
- **SAFE**: 动了急停回路/安全继电器/SIL相关
