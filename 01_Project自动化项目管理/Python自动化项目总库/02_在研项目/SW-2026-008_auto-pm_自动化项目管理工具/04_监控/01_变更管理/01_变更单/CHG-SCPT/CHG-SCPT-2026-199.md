## 4. 变更原因

**变更背景**：
Continuity v2 的 Checkpoint 将当前 owned-path dirty 集合与 Run 启动时 declared_dirty_paths 比较，导致干净基线启动并正常产生代码修改的 Run 无法创建 Checkpoint，错误提示为 Checkpoint 包含未声明的 dirty path。

**变更必要性**：
Checkpoint 必须区分启动前已声明脏路径与 Run 在 owned_paths 内合法产生的变更；否则执行成功也无法形成恢复点，迫使使用二次验证 Run 接管，增加流程摩擦并削弱自动接力。

**参考依据**：
CHG-SCPT-2026-198；WORK-SW008-A0-198；RUN-SW008-A0-198-01；auto_pm/application/core/continuity_execution_service.py checkpoint。

| 项目 | 当前值/描述 |
|------|-----------|

| 关键参数/配置 | Checkpoint 把 `dirty_paths` 与 Run 的 `declared_dirty_paths` 比较；干净基线 Run 在 owned path 内产生修改时会被错误拒绝 |

### 5.2 变更后（目标状态）

| 项目 | 目标值/描述 |
|------|-----------|
| 涉及文件/交付物 | 连续性执行服务、回归测试、CHG/Decision/台账与总方案状态投影 |
| 关键参数/配置 | Checkpoint 校验 `dirty_paths ⊆ owned_paths`；启动前已有脏路径仍由 Run 创建阶段强制声明；外部路径、基线漂移和 lease 异常继续失败关闭 |

### 12.1 填写指南

#### 如何选择技术领域?
- 主要改哪个专业的交付物,就选哪个领域
- 如果同时涉及多个专业,选**最主要**的那个作为主领域,其他在§6.2中标注

#### 如何判断影响范围?

- **MODULE**: 改一个FB/一条输送线/一台设备
- **SYSTEM**: 改全局变量/联锁逻辑/通讯接口
- **CROSS**: 改了电气,PLC和HMI都要跟着改
- **SAFE**: 动了急停回路/安全继电器/SIL相关
