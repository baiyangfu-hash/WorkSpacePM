## 4. 变更原因

九条 C09/R3C 历史辅助 Work 仍处于 `BLOCKED`，与 CHG-SCPT-2026-323 的五文件 scope 重叠，导致新 Mission 派生 Work 被活动路径检查拒绝。唯一非终态的 `RUN-SW008-PMF-C09R3C-NOSKIP-001` 租约已过期、无 Checkpoint；其余相关 Run 为终态。本单仅消除历史控制面占用，不宣称 P2 或 M1 验收。

| 项目 | 目标状态 |
|------|----------|
| NOSKIP Run | 仅经独立恢复 Decision 和有效恢复 Work/Run，使用 `settle_expired_run` 前向置为 `CANCELLED`，旧租约在同一事务内标为 `RELEASED` |

### 5.3 精确授权边界

唯一可写目标为 canonical `.auto-pm/continuity.db` 中上述恢复链与九条历史 Work 的追加事件及合法投影；恢复 Decision 的 `runtime_capability` 只允许 `settle_expired_run`、目标 `RUN-SW008-PMF-C09R3C-NOSKIP-001`、结果 `CANCELLED`。原 Decision `DEC-20260924-6BAAB080` 原样固化到 Git。不得改写旧 Run/Checkpoint/事件、源码、WBS、CHG-323 候选、release 指针或其他项目。

## 6. 影响分析与回退原则

执行前必须在隔离控制根、canonical 数据库备份上通过同一高层链路演练，并逐节点核对 Git HEAD、Decision SHA-256、Work/Run 版本、租约和进程。追加事件不作破坏性回档；任一前置条件失败即停止，保留现场与失败证据。对已有终态 Run 仍保留的过期 token，只验证其不能续租或写入，不为本单新增独立 fencing 批次。

## 7. 验证与验收

验收仅包括：NOSKIP Run=`CANCELLED`、租约=`RELEASED`；恢复链合法终态；九条旧 Work=`CANCELLED`；QG 两份 Checkpoint 数量及字节未变；事件链与数据库完整；CHG-323 五文件路径冲突为零；SW008 台账对账无缺失、孤儿或不一致。未达成则如实保持本单未完成，不推定 P2/M1 完成。
