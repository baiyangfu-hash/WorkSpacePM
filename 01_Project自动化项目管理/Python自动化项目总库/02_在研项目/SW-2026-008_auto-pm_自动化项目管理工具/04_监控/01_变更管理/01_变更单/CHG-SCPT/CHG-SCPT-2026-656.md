## 4. 变更原因

**变更背景**：
三条小缺陷加一组补测。D-359：project archive“收口走完”一项的提示写“先用 D 单的办法收掉”，那个办法（D-340）实施时撤出了、并不存在；改成实话“这类卡现在还没有命令能把收口补走完（缺陷 D-340，待修），请把卡号交给主执行，这个项目先不归档”。这句是 CHG-SCPT-2026-652 批准件的原话，由本单明确改掉；判定不动。D-360：project_delete_guard.uncommitted_blockers 读没提交文件时 Git 把中文路径写成八进制转义码；给这条 git status 加 -c core.quotePath=false，project delete 和 project archive 的提示里路径显示原字，英文路径的输出逐字节不变。D-348：pm orient、pm resume 看不见孤卡（卡开着、工作项已取消或关闭）；在 continuity_resume_service.collect 里往现有的 hold_warnings 加一句提示（已取消的推荐 pm retire --mission-id 预演，其余交主执行查；候选卡的工作项读不出只提示不报错），不改冲突、下一合法动作、JSON 结构。另补 CHG-SCPT-2026-649 遗留的 3 条 continuity_resume 测试（点名已验收工作项、只剩陈年残留、账本空但有冲突，第三条造不出就写明不补）。3 个源文件进发布载荷、是受保护路径，切换后生效；D-340 不在本单。

**变更必要性**：
归档提示让用户去找一个不存在的办法；中文项目路径在删除和归档提示里是一串看不懂的转义码；孤卡在进门定位里没有任何提示，只看到一个空的下一步。三处都是对人说的话不准或不全，改动小、判定不动。

## 12. 附录

### 12.1 填写指南

#### 如何选择技术领域?
- 主要改哪个专业的交付物,就选哪个领域
- 如果同时涉及多个专业,选**最主要**的那个作为主领域,其他在§6.2中标注

#### 如何判断影响范围?
- **LOCAL**: 改一个变量/一行代码/一个接线端子
- **MODULE**: 改一个FB/一条输送线/一台设备
- **SYSTEM**: 改全局变量/联锁逻辑/通讯接口
- **CROSS**: 改了电气,PLC和HMI都要跟着改
- **SAFE**: 动了急停回路/安全继电器/SIL相关
