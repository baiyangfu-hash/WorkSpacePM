## 4. 变更原因

**变更背景**：
驾驶舱变更单完成后自动入库与进门积压提示。用户原话：我需要根治，你出解决方案吧，申请变更单。2026-11-22 盘点发现 726、729、732、733、734 已在本机完成但最新记录未入库，727 仍显示实施中且历史合并 fee3708b 不在当前 main。现行完成流转只更新本机变更单和台账，普通合并可保全未提交记录，ledger reconcile 对入库积压只打提示，进门小结因此仍显示通过。

**变更必要性**：
一期落地脚本层受控归档命令 pm_merge.py archive-changes 与 pm_flows.py 进门/体检只读积压摘要，合入 main 后即用于归档本机已完成变更单并原样保全 727；二期（change transition completed 自动后台触发、ledger CLI 扩展、cockpit_board UI 与 AGENTS.md 规则调整）另立变更单及发版切流。安全回路：否。

**目标与验收边界（一期）**
- 落地脚本层受控归档命令 `scripts/pm_merge.py archive-changes <PID>` 与 `scripts/pm_flows.py` 进门/体检只读积压摘要；Git 的 `main` 是入库事实，未选中变更单原件与台账行逐字节保留。安全回路：否。
- 不等待 GitHub，沿用 GH-001 档位（`关 / 备份 / 多机`）；归档路径白名单仅限选中已完成变更单原件及所属项目版本台账；二期（`change transition completed` 自动触发、台账命令扩展、总控屏 UI 与 `AGENTS.md` 规则更新）另立变更单实施。

**实施（一期）**
1. 在 `scripts/pm_merge.py` 新增 `archive-changes <PID>`：在独立临时 Git 索引以 `main` 台账为底稿仅投影已完成（`completed`）单的台账行并连同原件原子提交，复用 `_main_transaction` 与 `merge_log.jsonl`（确保 `verify-log` 通过）；对索引非空、进行中托管门禁、活跃开发工位或当前基线未消费独立审计凭证实行互斥拒绝并保留现场；重复执行幂等。
2. 在 `scripts/pm_flows.py` 进门/体检小结新增只读“变更单入库积压摘要”，比对磁盘 `CHG-*.md`、台账与 `main`，区分本机已完成待入库、实施中未入库与历史合并不在当前主线（识别 `727` 不当已完成也不改变其状态）。
3. 本单合入 `main` 后实跑 `pm_merge.py archive-changes SW-2026-008` 清理现存已完成积压，原样保全 `727`。

**机器验收（一期）**
- 隔离回归测试 `pytest tests/infrastructure/test_pm_merge.py tests/infrastructure/test_pm_flows.py tests/infrastructure/test_command_catalog.py -q -p no:cacheprovider --no-cov` 退出码 0；实施卡预检、档次核验、严格 UTF-8 与云端全量门禁、独立审计 `PASS`。
- 合入 `main` 后实跑 `pm_merge.py archive-changes SW-2026-008`、`pm_merge.py verify-log` 与 `pm_flows.py entry SW-2026-008` 均退出码 0，已完成积压清零且 `727` 原样保留。

## 12. 附录

### 12.1 填写指南

#### 如何选择技术领域?
- 主要改哪个专业的交付物,就选哪个领域
- 如果同时涉及多个专业,选**最主要**的那个作为主领域,其他在§6.2中标注

#### 如何判断影响范围?
- **LOCAL**: 改一个变量/一行代码/一个接线端子
- **MODULE**: 改一个FB/一条输送线/一台设备
- **SYSTEM**: 改全局变量/联锁逻辑/通讯接口
- **CROSS**: 改了电气,PLC和HMI都要跟着改
- **SAFE**: 动了急停回路/安全继电器/SIL相关
