## 4. 变更原因

**变更背景**：
RC-004 项目生命周期第一张实施单，并修 D-344（TD-SW008-609）：登记表 workspace_registry.json 加“项目性质”“项目状态”两栏，作为唯一真源，project list 和看板都改读这两栏，不再从已退役的 PM_SESSION 推阶段，看板不再写死工具项目名单；project delete 和窗口删除都同时把登记表里这一条标“已删除”（不抹行）；新增从回收区搬回的命令，只听用户本人、默认预演；project import 和窗口导入都按技术栈调 resolve_project_destination，落点和 project create 一致（D-344）。schema_version 保持 workspace-registry.v1，新栏可缺省（缺省按在研、未分类），保证能回退到现役和上一版。给现有 9 个项目填栏是治理库数据，由本地主力按附表写，不在云端 PR 里改。

**变更必要性**：
项目没有“性质”“状态”的真源，看板靠写死名单分组、靠猜状态；删除后登记表留空壳；回收区不能搬回，删错了救不回来；project import 的 PLC 项目和 project create 落在不同目录，窗口导入连 Python 也写死在 02_在研项目（D-344）。归档（下一张单）要先有“状态”这一栏才做得了。

## 12. 附录

### 12.1 填写指南

#### 如何选择技术领域?
- 主要改哪个专业的交付物,就选哪个领域
- 如果同时涉及多个专业,选**最主要**的那个作为主领域,其他在§6.2中标注

#### 如何判断影响范围?
- **LOCAL**: 改一个变量/一行代码/一个接线端子
- **MODULE**: 改一个FB/一条输送线/一台设备
- **SYSTEM**: 改全局变量/联锁逻辑/通讯接口
- **CROSS**: 改了电气,PLC和HMI都要跟着改
- **SAFE**: 动了急停回路/安全继电器/SIL相关
