## 1. 根因与变更方案

1. 根因：
   - `worktree open` 的持有人记录只读 `CLAUDE_CODE_SESSION_ID`/`CLAUDE_PID`，Trae/Cursor/VS Code 开出的别名工位记成 `session_id=""`、`pid=0`，身份无法核对；
   - `ensure_session_id` 按父进程号生成会话 ID，Trae 每条命令的父进程号都不同，同一对话的别名一路漂移（`trae-c19ba3` → `trae-1c9fd5` → `trae-04d028`），收不了自己的工位；
   - `worktree close` 在 Windows 上 `git worktree remove` 报错时会留下“登记已删、目录还在”的空壳，下一次 close 只报“没有登记在 Git 里的工位”；
   - 看板对“目录在、Git 未登记”的会话工位仍给“收工位”，没有“清理残留”。
2. 方案（按 `CHG-SCPT-2026-747` §5.2、§7）：
   - 持有人记录改用 `session_id()`（`AUTO_PM_SESSION_ID` 优先）和 `declared_pid()`（`CLAUDE_PID` 优先，其次 `VSCODE_PID`），Claude 现有行为不变；
   - `ensure_session_id` 先认 `TRAE_CHAT_SESSION_ID`、再认 `VSCODE_PID`，两样都没有才按父进程号生成；不改 `.trae/`；
   - `worktree close` 原子化：目录已没或只剩空壳的就地收干净（prune 登记、删空目录、已并进 main 的本地分支一并删），还有文件的一律不动并给出人工清理命令；入口遇到“目录在、Git 未登记”的空目录自动清、有内容明确报残留；
   - 看板对 `registered=false` 的会话工位显示“清理残留”（仍跑 `worktree close`），名册外目录仍走清理清单；`policy.WORKTREE_BUTTONS` 登记这个按钮字；
   - 补测试：Claude 行为不变、Trae/Cursor/VS Code 记录非空且稳定、空壳/有内容/半删三种 close、看板按钮与真命令端到端；现有护栏（别人工位拒收、用户终端可收、`reclaim` 不变）不削弱。
