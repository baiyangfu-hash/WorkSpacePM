## 3. 验收

- 本机受保护改动接受标准实施卡。缺卡、路径越界、变更单未批准或审计与候选不匹配，均在重门禁前拒绝。
- 正式绑定变更单的普通路径改动也必须核对实施卡、范围和独立审计。提交说明里引用历史变更单的普通改动沿用原流程。
- 工位内的标准卡按仓库内项目路径预检。默认项目相对路径和显式控制根路径均可用，需求与变更单原件从控制根读取。
- 合并候选完全避开未提交的驾驶舱变更单与台账、控制根索引无暂存改动时，合并保留这些文件并核对摘要。范围重叠、存在暂存内容或有其他无关未提交改动时拒绝进入台账保全流程。
- 历史实施卡仍核对范围。发布归档的成功和回退在隔离 Git 仓库验证，现役发布文件保持原样。

- 普通本机合并以及 GitHub 关闭时的驾驶舱流程继续可用，正式全量仍复用驾驶舱的托管任务。
- 733 的 GUI 工位、发版切换、三档 GitHub 策略均在本卡范围外。
