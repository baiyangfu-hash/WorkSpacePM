## 一、白话摘要（只看这一页就够）

**结论：你的担心是对的，实施卡不是个例。** 这次一共扫出 506 样东西（命令、脚本、模板、规范、规则文件、角色包、看板页面和按钮、账本表、CI、检查规则），另外查了 393 个源码模块有没有入口能走到。

用盘柜打个比方：“功能”是柜里实际装的元件，“记录”是图纸。这次是拿着图纸逐个端子核了一遍。

| 分类 | 白话 | 数量 |
|---|---|---|
| 甲　有功能、有记录 | 柜里有，图纸上也画了 | 268 样 |
| 乙　有功能、没记录 | 柜里有，图纸上没画（重点） | 219 样 |
| 丙　有记录、功能不存在或已坏 | 图纸上画了，柜里没有或不通 | 4 处 |
| 丁　孤儿 | 柜里有，但没有任何线接到它 | 19 样，另加 11 个源码模块 |

“有记录”的口径放得很宽：规则文件、手册、基线文档里只要有一处提到它的名字就算。即便这么宽，仍有四成多没记录。

1. **222 条命令里，agent 进门必读的规则文件只提到 51 条。** 规则、手册、基线文档三处都没提到的有 109 条。实施卡的 7 条命令在规则文件里一次都没出现，和你发现的一致。（直接读到）

### 我的建议（都要你点头才动）

- **先补一张“总目录”，不要逐条补文档。** 最省事的做法是让《功能清单》由脚本自动生成（这次的扫描脚本改一改就能用），每条命令一行：干什么、谁能跑、有没有记录。以后新加命令不登记，检查就报红。这样“忘了有这个功能”这类事由机器拦，不靠人记。
- **退役候选一次性列给你批**：旧交接包命令、PM_SESSION 命令、`workflow` 的 9 条重复命令、旧启动包、不会启动的 CI、11 个走不到的源码模块（约 700 行）。

- 只按英文名字查。文档里只用中文叫法的会漏算成“没记录”（例如 WBS 里写的“产品经理角色包”我是手工核的）。

## 六、怎么重跑（给以后的 agent 复核用）

脚本都在 `plans/基线校准_20261113/盘点扫描脚本/`，只读，除了 `scan_cli.py` 要用仓库的虚拟环境，其余只用 Python 标准库和 git。在仓库根依次执行：

```
SRC="01_Project自动化项目管理/Python自动化项目总库/02_在研项目/SW-2026-008_auto-pm_自动化项目管理工具"
T=<脚本目录>
PYTHONPATH="$SRC" .venv/bin/python -B $T/scan_cli.py > cli_tree.json      # 导出整棵命令树（不执行任何命令）
python3 $T/build_items.py > items.json                                     # 实扫脚本、模板、规范、规则、角色、CI 等
python3 $T/inventory.py --cli-tree cli_tree.json --items items.json --baseline <基线文档目录> --out out   # 逐项对照，约 1 分钟
python3 $T/scan_reverse.py --cli-tree cli_tree.json --baseline <基线文档目录> > reverse.json            # 反查：记录里有、仓库里没有
python3 $T/scan_imports.py "$SRC" > imports.json                           # 走不到的源码模块
python3 $T/make_tables.py out/inventory.json imports.json                  # 生成下面的附表
```

已知的口径限制：

- 按名字做文字匹配。名字太普通的会多算（例如内部模板目录叫 `plc`，我已手工改判）；只用中文叫法的会少算。
