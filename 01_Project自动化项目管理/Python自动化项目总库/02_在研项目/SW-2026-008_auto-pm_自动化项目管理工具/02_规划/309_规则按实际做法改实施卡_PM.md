改成什么：

1. 全流程、标准线的授权凭据是：用户批准过的变更单、领卡占位、PR（CI 全绿加独立审计）、验收后由用户推到完成。不再要求每次改动都有 Work/Run/租约。
2. Work/Run/租约只在两种情况下要：
   - 看板“确认开工”一键流，由驾驶舱自己建，agent 不手工建；
   - 命令本身要求 Run 或租约的，例如 `pm verify`。
3. 变更单被用户批准之前（快线除外），agent 只做三件事：跑只读命令、建变更单、领卡占位。此外不改仓库里的文件。
4. 新增 PR 线收口流程：`pm_flows.py closeout-pr <项目编号> --chg <变更单号> --card <占位卡号>`。原来的“交卷到收口”保留，给走 Run 的卡用。顺带修一个缺陷：`pr settle-scan` 退出 1 只表示“有等收口的卡”，原来的“交卷到收口”会把它当成失败、在推到完成之前停下。

   同类排查（FIX-001，两条收口流程里脚本自己跑的每条命令，退出码非 0 各是什么意思）：
   - `pm acceptance-scan`：退出 1＝有验收命令会被拒，是真问题，照旧算红；
   - `pm control-root-status`：读码核过，只打警告，正常都退 0；非 0 只在命令本身出错时，照旧算红；
   - `pm missions`：正常退 0；非 0 是读账本出错，照旧算红；
   - `pr settle-scan`：0＝没有等收口的，1＝有等收口的（收口时的常态，改成不算红），2＝判断不了（照旧算红）；
   - `ledger reconcile`：0＝无差异，非 0＝有差异，照旧算红。
   只有 `pr settle-scan` 这一处要改，两条流程都用同一个设定。
