## 1. 背景与已核实事实（2026-10-09 夜）

1. **为什么**：远端仓库 `github.com/baiyangfu-hash/WorkSpacePM` 是公开的（用户告知）。治理记录入库、release 源码提交推送、旧 release 标注都必须以一份可核对的清单为依据；并且在推送任何东西之前，必须知道公开历史里**已经**有什么。
2. **已经发现的事实**（见 `.auto-pm/reports/RELEASE_GOVERNANCE_FINDINGS_20261009.md`）：164 个 CHG 正文不在任何提交里；5 个 release 载荷校验不通过；6 个 release 源码提交不在远端；对集成源一棵树的快速扫描没有发现私钥或令牌，但本卡的演练扫描了**全部历史**，发现一处高置信度命中：`gittoken.txt`（2026-05-17 提交 `b1934cb7` 加入，已于 5 月 26 日的清理提交里删除，但仍在公开历史中，可从远端引用到达）里含 GitHub 个人访问令牌格式的字符串。**不论它是否仍有效，都应由用户在 GitHub 上撤销**；本卡不读取、不使用、不记录它的值。
3. **做什么**：只读生成四个文件：①CHG 冻结清单；②release 资产清单（含从源码提交重建并与载荷逐文件比对）；③公开历史暴露扫描；④报告。运行前后各取一份仓库指纹，必须逐字节相同。
4. **检查**：独立检查器重算汇总数字、重新哈希抽样的 CHG 文件并重新判定其 Git 状态、对 manifest 里每个 release 重取事实、核对暴露扫描覆盖的引用与提交数等于当前远端、确认输出里没有任何秘密值、核对报告里的数字等于 JSON 里的数字；8 个反例各被对应断言拒绝。**它不证明结论正确**，结论由用户读报告后裁决。
5. 我在系统临时目录里完整试跑了一遍（非受治理执行，不能复用为正式证据）：468 个 CHG 文件（不同编号 435）、15 个 release（exact-tree 通过 10，从源码提交重建与载荷逐文件相同 12）、554 个提交 11020 个文件对象；检查器退出 0，8 项反例全部被拒绝；试跑输出与检查结果保存在 `.auto-pm/reports/m2-rgov0/rehearsal/`。
6. 不在本卡范围：入库任何 CHG、推送、打 tag、改 manifest 或指针、标注旧 release、改台账或 WBS、处置任何债务或失败记录、撤销令牌（用户在 GitHub 上做）。
