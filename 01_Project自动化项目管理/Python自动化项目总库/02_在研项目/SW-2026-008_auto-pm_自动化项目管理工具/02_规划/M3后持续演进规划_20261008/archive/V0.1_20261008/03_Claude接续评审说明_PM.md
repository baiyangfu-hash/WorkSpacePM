## 3. 先区分两种Claude使用方式

**受监督方式**：用户在现有Claude环境发起，Agent通过合法、已支持的入口恢复和执行。P04验证这一条，不要求先开发自动进程适配器。

**自动方式**：驾驶舱启动并管理Claude进程、失败与恢复，属于P05条件项。当前源码枚举/文件存在不能证明这个能力；必须用真实接口、真实模型、真实进程边界验收。

同样，DeepSeek在VS Code内能聊天，不代表它具备所需工具权限、正确工作目录、受控命令执行和Checkpoint回收能力。P06要验证实际插件/模型/版本/权限组合，不预设某个扩展或订阅必然可用。

不得为过关冒填codex身份、沿用旧token、自己编辑治理JSON或用旧Run继续另一个人的lease。存在适配合同阻塞就给出失败事实和小范围后续卡，不用提示词绕过。

## 4. 候选转成正式执行计划

每张拟开卡至少补全：

| 字段 | 要求 |
|---|---|
| 本批用户价值 | 一件具体任务能减少什么错误或投入；不只写“提升架构” |
| 现状与缺口 | 精确来源/提交/运行身份；已做部分先扣除 |
| 范围 | 逐文件精确路径；哪些拟新增、哪些现存；依赖工具也列出 |
| 对应原WBS | 新增强还是原任务未尽项；不在两个计划重复计完成 |
| 验收 | 可观察正反例、实际用例集合、机器可判的失败场景、外部人工验证边界 |
| 风险/门禁 | 依据当时有效规则；未知路径core；验证工具不能自己降档 |
| 预算 | 工程、门禁每轮、预计轮数、独立复核、用户窗口分别列出 |
| 并发 | 其他Agent范围、共享资源、重门禁窗口；不能自行删除锁或杀别人进程 |
| 兼容与退出 | 回滚保留新事件；失败/缺环境记未验证；有界重试次数和转交条件 |
| 批准与执行 | 提交具体可评审计划，按现行规则取得授权后再进入Work/Run/lease执行 |

原有能力足够时只引用现有实现，不新造模块。正式批准前的只读勘测可以发现本初稿拟路径不合理；修正拟路径并解释即可，不能声称这些占位已授权。

## 5. 独立复核如何在Claude为主时继续

复核可以由独立Claude会话承担：提供冻结卡、基线、候选差异、原始证据和验收要求，尽量不先喂入实现者“已经正确”的自证叙述。复核会话按机器证据和反例给结论，不能改实现把它偷偷做绿。

同模型不同会话能减少对实现上下文的依赖，仍有同源盲点。治理核心变更优先增加确定性反例与真实进程/故障场景，条件允许时再引入其他合适审阅来源；没有GPT不等于可以取消独立复核。

用户做最终验收，但不能把缺失门禁、无法复现或虚假证据的责任转给用户判断。对“已完成”只陈述实际证实的层级。

## 6. 操作细节中特别容易再犯的错误

- 根入口位于工作区部署链；不要直接运行母体源码来证明active可用。
- 当前读取的launcher会在标准输出先写校验提示；不能假设所有--json输出直接整段json.loads成功。应先核实际版本的输出契约，必要时单独提规范化输出卡。
- 原M3 D01已经覆盖部分手册与入口规则，本包P07只补实测遗漏；不自动启动全母体文档重写。
- HEAVY_GATES_RUNNING存在时遵守当前任务的重门禁限制，不能把collect-only当作“没跑测试”绕开。
- 未批准跨Run复用时，历史PASS只作参考。改了候选字节应重核适用证据。
- 新增确定性验证器也要有坏输入；抛异常、导入失败或超时不能冒充命中目标断言的变异结果。
- 模型守规则的强度取决于实际入口、工具权限和隔离。不要声称一份技能提示能阻止拥有任意shell权限的Agent从旁路修改文件。
- 不把只读设计报告的交付误写成业务能力验收；也不把现场编译/接线未知补成PASS。
