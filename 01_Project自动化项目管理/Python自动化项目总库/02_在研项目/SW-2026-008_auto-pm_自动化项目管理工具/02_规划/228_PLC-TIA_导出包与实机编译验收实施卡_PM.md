## 1. 背景与已核实事实（2026-11-04 夜～11-05）

1. **起因**：DJ-2026-011 的三个 FB 在 TIA V19 实机导入，暴露三件事：自写库类型（`FB_TON` 等）TIA 里不存在；UTF-8 无 BOM 的 `.scl` 被当 ANSI 读，中文注释乱码；“LSP 全绿”不等于 TIA 能编译。规范已改（LSP-903/905/906），但**只靠规范，下一个人还会踩**。用户原话：“不仅仅是规范固化，通过脚本固化工作流”。
2. **今天已经有的**：`reviews/tools/plc_ci.py` 在 CI 里检查“同项目其它 .scl 带 BOM，这个没有”（随 #539 入库）；`main.py plc check <PID>` 只有 Siemens LSP 诊断、结构规则、命名与禁用语法规则、文档一致性。**没有**：类型白名单检查、导出包、实机编译结果的记录与验收门。
3. **TIA 导入方式**（用户实测）：整段粘进 FB 编辑器的变量声明区不行；用“外部源文件 → 从源生成块”导入。依赖顺序错会报找不到类型。
4. **为什么旧版 011 的两个问题 LSP 没拦住（已核实的部分来自仓库记录）**：① `FB_TON`：011 的 `.plc.json` 引用了 `../01_SharedLibraries/SysLib`，SysLib 里有 `FB_TON` 的源码定义，LSP 按库解析成功，所以不报“类型不存在”；而 TIA 导入的是 011 单个项目，没有 SysLib，该类型不存在。② 全局 DB 里放 FB 实例：CHG-PLC-2026-002 的验收记录（2026-10-22）显示这种写法下 `plc check DJ-2026-011` 退出码 0（Pass=18 Warn=1 Fail=0）、插件 test 12/12——LSP 的 DB 语义检查和仿真运行时没有“全局 DB 不能含 FB 类型成员”这条 TIA 规则，仿真还把 `fb_x` 当成可寻址成员，所以连用例都跑得通。结论：**LSP 是“Siemens 语言的子集模拟器”，不是 TIA 编译器**，凡是 TIA 独有的限制（块结构、OB 号、库依赖是否随包导入）都只能靠我们自己的规则和 TIA 实机编译兜住。③ 另有交付流程上的缺口：这次把包交给用户导入之前，云端没有驾驶舱环境、没有跑 `plc check/test`，而 PR 正文只在证据栏写了“未核实”，没有对用户明说“未经 LSP 检查”——见 §5 第 7 条。
5. **未核实**：Siemens LSP 是否认 `TON_TIME`/`R_TRIG`/BOM（等 #539 的 `plc check`/`plc test` 原文）；`SclLinter` 对 BOM 开头文件曾误报 `LSP-905-STRUCT-NO-BLOCK`（#539 夹具里复现过，源码在受保护的 `auto_pm/**`）；GUI 的 PLC 卡页代码位置、验收条件读取点还没勘测，开工第一步先只读勘测并把落点补进 §4。

## 2. 单一目标与完成定义

**让任何 agent 或用户都只能走一条路把 PLC 源码送进 TIA，且“TIA 实机编译 0 错误”成为 PLC 卡的机器可判验收条件。**

完成 = 下面 9 项全部由命令和测试证明，不靠口头：

| # | 交付 | 机器可判的验收 |
|---|---|---|
| 1 | `main.py plc export-tia <DJ号>` | 先**强制**跑 `plc check` 与插件 `check`/`test`（不接受“跳过”或“找不到插件”，找不到插件算未验证、不出包），任何失败或未跑都不出包（退出码非 0，不留半成品目录）；通过则在 `.auto-pm/tia-export/<DJ号>/<提交号>/` 生成：`.scl` 一律 UTF-8 带 BOM（已有 BOM 不重复加）、按依赖排序编号（UDT → FB → DB → OB，同类按被调用关系）、`导入步骤.md`（第一条：导入前备份；外部源文件 → 从源生成块、编译顺序（全局 DB → 被测 FB → 测试台 FB → 背景 DB → OB）、期望结果、OB 可改名改号或只复制调用行）、`manifest.json`（文件列表 + SHA-256 + 源仓库提交号 + 本次 `plc check`、插件 `check`、插件 `test` 的退出码、时间、原文输出文件及其 SHA-256；原文随包附在 `lsp_report/` 下）；再打成同名 `.zip`。同一提交重复导出字节相同。 |
| 2 | 类型与指令白名单检查并入 `plc check` | 读 LSP-905 §4.9 白名单（以规范文件为真源，不在代码里复制清单）；源码里出现不在白名单、且仓库里也没有定义的类型 → 失败，报“文件:行:类型名”。`FB_TON`、`IEC_Timer_0_DB` 单实例写法必须被抓到。 |
| 3 | `SclLinter` 修 BOM 误报 | BOM 开头且首行是代码的文件，不再报 `LSP-905-STRUCT-NO-BLOCK`；另加一条检查：导入 TIA 的 `.scl` 缺 BOM 一律失败（和 CI 的 `plc_ci.py` 同判据，二者共用一份实现或互相对拍的测试）。 |
| 3b | TIA 块结构检查并入 `plc check` | ① 全局 `DATA_BLOCK` 的 `VAR` 里出现 FB 类型成员（如 `fb_x : FB_某某;`）→ 失败，报“文件:行:成员名”，提示“改为测试台 FB 多重实例或背景 DB”；② **agent 写的 OB 编号低于 100 一律拦截**（用户 2026-11-05 规定：只能 100 以上，S7-1200 程序循环 OB 实际取 ≥123）：文件名或声明里的编号 <100（含 OB1）→ 不出包；块名为 `Main` 的 OB 同样拦截（会覆盖用户项目的 OB1）。整机项目自己的 OB1 主程序（005/009/000）不走导出包的自动覆盖，须另经用户确认。依据 LSP-905 §4.11、LSP-906 §7.3/7.4（2026-11-05 DJ-2026-011 实测：全局 DB 含 FB 实例导致 TIA 连环报错）。 |
| 3c | 交付前拦截（规范固化下沉） | PLC 卡进入“交付给用户”阶段前（`pm verify` 与报用户验收的收口检查），驾驶舱读该提交对应的 `lsp_report` 记录：没有、不是当前提交、退出码非 0、或原文哈希对不上 → 拦下，提示“未经 LSP 检查，不得交付给用户导入 TIA”。该判据读 manifest，不读聊天文字，也不接受 agent 手写的结果。 |
| 3d | 不覆盖用户块（2026-11-05 实测：旧 `OB1.scl` 块名 `Main`、无 BOM，“从源生成块”把用户模板里的 `Main [OB1]` 整个覆盖并变乱码） | 导出包里的块名与块号：禁止 OB1、块名 `Main`、`Startup`、`Cyclic` 等常见用户块名（名单放在规范文件，不写死在代码里）；包内所有块、DB、OB 的名字必须带项目标记（`DJ<项目号>` 或 `DJ` 前缀），否则不出包；`导入步骤.md` **第一条**固定写“导入前先备份项目（另存为）：从源生成块会覆盖同名块，覆盖后不可撤销”，并列出本包会生成的全部块名供对照。旧版 011 的 DB 名（如 `DB_TwoHandStartTest`）不带项目标记，实施时随迁移卡改名并同步 `.scltest`。 |
| 3e | 块编号段与命名检查（LSP-905 §3.4，用户 2026-11-05 批准） | 解析导出包里每个块声明：FB 编号必须落在 905 §3.4 编号段表（执行器 1001–1099、通信 1100–1199、安全 1200–1299、工站 1300–1999、公共服务 2001–2999、外部通信 3001–3999、测试 9001–9999）；DB 名里的所属 FB 编号必须与被实例化/所属的 FB 一致，测试 DB 在 9000 段；FC 编号可选，带编号时同样查段；OB 编号 <123 拦截（与 3b ② 同一条）；不在段内也不在“历史例外登记”里的 → 不出包，报“文件:行:块名:应属哪一段”。**段表与例外登记以 905 §3.4 为真源，脚本运行时读该文件解析，不在代码里复制**。DJ-2026-011 在研块（FB_1091、DB_*Test、DB_TestBench）按例外登记通过，迁移卡改名后移出例外。 |
| 4 | `main.py plc record-tia-compile <DJ号> --errors N --warnings M --tia V19 --evidence <截图路径> [--package-sha <manifest 的 SHA>]` | 把用户实机编译结果记为验收证据（写入项目目录下的受控位置并进账本，不是聊天文字）；`--package-sha` 必须等于当前提交导出的包，否则拒收（防止拿旧包的结果顶替）；证据文件必须存在。 |
| 5 | PLC 卡验收门 | `pm verify`/收口读第 4 项的记录：没有“本提交号 + errors=0”的记录，PLC 卡不能结；有 errors>0 的记录，明确报“TIA 编译未通过”。记录里的 warnings 数写进验收报告，不阻断。**LSP 全绿不再等于可交付。** |

驾驶舱 PLC 卡页加“导出 TIA 包”按钮，调用第 1 项（GUI 薄壳，不另写逻辑）。按钮可以拆到第二期，不挡第 1～5 项合并。

## 5. 验收（机器无情判卷）

1. 新增测试全绿，且至少包含这些反例：缺 BOM 导出前自动补 BOM；含 `FB_TON` 的项目不出包；同提交两次导出字节相同；`--package-sha` 不匹配被拒；无证据文件被拒；errors>0 的记录让 PLC 卡验收失败；errors=0 的记录让它通过。
2. 对 DJ-2026-011 实跑 `plc export-tia`，产出的包与用户当天在 TIA 里导入成功的那批文件逐字节一致（BOM 之外）。
3. `main.py plc check DJ-2026-011`、`main.py doc check`、`ruff`、`mypy` 退出码 0；`pytest tests/plc tests/cli` 分组全绿。
4. 白名单与块结构检查各有反例：含 `FB_TON` 类型的 FB、全局 DB 里放 FB 实例（DJ-2026-011 旧版 `DB_TwoHandStartTest.scl` 即是反例，须被抓到）、OB 号 1、2、99。
5. **与 LSP 不冲突的核查（2026-11-05，云端只读，已核实的与未核实的分开）**：
   - 已核实：驾驶舱源码（`auto_pm`）里没有任何写死“入口 OB 必须叫 OB1”或“FB 名字数字必须在某段”的检查；`SclLinter` 的规则只看关键字、变量前缀、REGION 等（`LSP-905-STRUCT-*` 只认 `ORGANIZATION_BLOCK/FUNCTION_BLOCK/FUNCTION/DATA_BLOCK/TYPE` 关键字，不看块名）。`entryOb: "OB1"` 只出现在 VS Code 调试配置 `.vscode/launch.json` 与 LSP-907 示例里，不是 `plc check/test` 的输入。驾驶舱按**目录名** `DB1/`、`OB1/`、`Test/` 识别“测试套件”项目类型（`checker.py`），所以改 OB 编号时**不得改目录名**。
   - **未核实（等笔记本跑）**：Siemens 语言服务插件自己的 `test` 在找不到 `OB1` 时怎么选入口（011 现在只有 OB123）；插件是否接受背景 DB 写法、带引号的全局 DB 名；`SclLinter` 对以 BOM 开头文件的误报。必须在笔记本上对 DJ-2026-011 跑 `plc check` 与 `plc test` 并贴原文后，才能把 OB 改号这一条标为已验证。若插件要求入口叫 OB1，退路是测试用 `.scltest` 之外另找入口约定或让 011 的测试外壳放回 OB1 目录名（目录名不动，不影响 OB 编号规则）——到时再议。
6. **库依赖随包检查**（补上面 ① 的缺口）：`plc export-tia` 对项目 `.plc.json` 的 `libraries` 里被源码实际用到的每个类型，要么来自白名单，要么其源码文件随包一起导出并排在被依赖者之前；用到了库类型却没带源码 → 不出包。TIA 里并不存在“公共库自动可见”。
7. **交付纪律（机器与流程各一条）**：① `export-tia` 的 `导入步骤.md` 与 manifest 头部必须写入本次 `plc check`、插件 `check/test` 的退出码与摘要原文（含时间与提交号）；没有这些记录就不出包。② 云端或没有驾驶舱的环境交付 PLC 源码给用户导入时，消息第一行固定写“未经 LSP 检查”，用户可据此决定是否先等笔记本跑完。
8. 同类排查：全库搜“拷贝 .scl 给用户”“导入 TIA”的说明文字（`docs/handover/10 §七`、AGENTS.md 第 4 条边界、`roles/plc-electrical-engineer`、项目模板 `templates/`），改成指向这两个命令（受保护文件的改动各自列入可改范围并取规则批准）；模板里生成的 `.scl` 骨架默认带 BOM 且不含自写库类型。

## 6. 硬停止

出现 §4 之外的候选变更、需要改 `.github/workflows/*`、或需要删除任何文件时停止并报协调者；删除只由用户自己执行。`plc export-tia` 不得写 PLC 项目目录之外的仓库位置（输出只落 `.auto-pm/tia-export/`）。

## 7. 限制与后续

1. 本卡不替用户操作 TIA，也不判断编译结果真假——结果由用户在虚拟机里编译后用 `record-tia-compile` 记录；截图是证据，不是自动识别对象。
2. 白名单的“实机”列需要用户在 TIA V19 逐项确认后才能把对应条目标为已验证；未验证条目只告警不阻断，已验证条目之外的类型才阻断。
3. 005/009/000 项目与 SysLib 内部块的迁移（改用 TIA 原生定时器）另立卡，不在本卡。
4. FB_1030 数组下标 0..7 与“数组从 1”规则的冲突需要用户裁决，不在本卡。
