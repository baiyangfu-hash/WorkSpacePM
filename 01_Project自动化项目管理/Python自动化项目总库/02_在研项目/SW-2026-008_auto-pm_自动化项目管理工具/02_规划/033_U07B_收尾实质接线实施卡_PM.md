## 5. 合同（全部定稿，执行者不得改写含义）

### 5.1 注入器（`substance_injector.py`）

1. 签名：`inject_closure_evidence(cls, workspace_root, *, change_number, target_path, evidence, change_facts: Mapping[str, str] | None = None) -> Path`。新增的只有最后一个关键字参数，默认 `None`；`None` 时除 5.1-4 外行为与基线逐字节一致。
2. `change_facts` 的键集合**恰为** `{"baseline_ref", "scope_files", "objective", "acceptance", "checkpoint_id"}`，全部非空字符串；键集合不符或有空值抛 `SubstanceInjectionError("change_facts 字段不完整或包含未授权字段")`，不写任何数据。`scope_files` 为以换行分隔的路径，`acceptance` 为以换行分隔的验收条件。
3. 当 `change_facts` 不为 `None` 且 evidence 标记尚未写入时，在插入 §9/§10.1 行之前，按下列**固定**规则回填变更单中**确实存在**的模板占位（不存在则跳过，不报错）。`clean(x)` = 把连续空白折叠为单个空格、`|` 换成 `/`、去首尾空白、截断到 200 字符；多项用 `<br>` 连接，验收条件用 `；` 连接。替换一律用函数式替换（不得把事实文本当作正则替换模板，防止 `\g<1>` 之类注入）。
   - §5.1“涉及文件/交付物”（第一处 `（待填写）`）→ `基线 {baseline_ref} 中的范围文件：<br>{clean(每个 scope_files 项)}`
   - §5.1“关键参数/配置”→ `需求：{clean(objective)}`
   - §5.2“涉及文件/交付物”→ `按批准范围修改：<br>{clean(每个 scope_files 项)}<br>Checkpoint {clean(checkpoint_id)}`
   - §5.2“关键参数/配置”→ `验收条件：{clean(每个 acceptance 项)，以；连接}`
   - §6.1“缓解措施”下的 `（待填写）` → `范围限定于批准的文件清单；在隔离工作树执行；经自动质量门禁（pytest/ruff/mypy）与用户最终验收后才收尾。`
   - §6.3 的 `[___________] → [___________] → [___________]` → `[本次变更仅涉及 SCPT 领域] → [无跨领域传播] → [无需联动]`
4. §10.3：把 `### 10.3 验证结论` 紧随其后的**首行表格行**，不论是 `| **验证结论** | … |` 还是模板的 `| 结论 | … |`，统一改写为 `| **验证结论** | {既有的 closure 结论句} |`；两种形态都不存在时抛 `SubstanceInjectionError("目标 CHG 缺少 §10.3 验证结论字段")`（沿用既有文案）。§8.2 的 `| 结论 |` 行不得被改动。
5. 其余既有行为不变：证据标记 `<!-- PM-CLOSURE-EVIDENCE:… -->` 已存在则只做验证、不回填、不改字节；已含另一份证据则拒绝；渲染后仍含 `（待填写）`、`(待填写)`、`待补充`、`[在此填写`、`[___________]` 任一项则抛 `SubstanceInjectionError`（沿用既有文案）；所有校验在 `write_file` 之前完成，失败时变更单字节不变。

### 5.2 收尾服务（`pm_closure_service.py`）

1. `inject_prepared_change_substance(closure_id)` 在调用注入器前，用 Store 读取事实并构造 `change_facts`：`mission = store.get_mission(closure.mission_id)`、`work = store.get_work(closure.work_id)`、`run = store.get_run(closure.run_id)`；`baseline_ref = run.git_head[:12]`，`scope_files = "\n".join(work.scope_paths)`，`objective = mission.objective`，`acceptance = "\n".join(mission.acceptance_criteria)`，`checkpoint_id = closure.checkpoint_id`。
2. 读取失败（`ContinuityStoreError`）或任一事实为空 → 抛 `PmClosureError`（保持既有 `except` 链，使收尾落为 `PENDING_SYNC`），不写任何数据。
3. 不新增公开方法、DTO、状态、事件或持久化对象；`complete_closure`、`_project_preparation`、`finalize_closure` 的逻辑与签名不变。
