## 1. 要达到的结果

驾驶舱的持续演进应帮助一名电气工程师更快、更稳地完成工程变更。优先减少找版本、搬运上下文、手改卡号、对点表、回传编译错误和整理现场证据的时间。用户保留需求取舍、真实物理事实、费用与最终验收决定；Agent 消化检索、执行、验证和证据整理。

一个具体目标是：客户增加一个到位光电并要求超时报警，系统能说明资料来自哪里、哪些 IO/程序/接口/画面受影响，Claude 在合法范围内修改，检查器指出差异，用户复编后结果回到同一版本链，现场问题和复验继续可追溯。

成功标准是这条真实任务链变省心。任务池中没有持续收益的方向，可以推迟或删除；不以实现全部候选为目标。

## 3. 目标架构及需要减轻的耦合

以下为后续设计方向，不表示这些模块目前全部存在。

```text
用户的工程目标、业务取舍和批准
              ↓
Claude / VS Code + DeepSeek / 其他已验证入口
              ↓ 薄入口：读取真源、调用统一命令、呈现结果
稳定根入口 → 应用服务 → 授权与连续性真源
              ├→ 受控执行适配器 → 候选工作树中的任务
              ├→ 版本化门禁工具 → 原始报告与判卷
              └→ 电气输入/编译/现场证据适配 → 同一工程版本链
                             ↓
                    人工验收 → 批准发布
```

### 3.1 统一入口，不把 IDE 变成第二套 PM

日常入口仍落在稳定部署与统一服务。Agent 侧可以将来提供轻量技能/命令映射，但本初稿不安排安装 /pm，也不在各 IDE 复制业务规则和治理状态。

工程规范保留在规范库，确定性约束下沉到版本化工具，Agent 入口只负责定位真源、提交参数和呈现结果。换编辑器或模型时，恢复流程不依赖这次聊天。

### 3.2 身份、能力、权限分开

provider/model 表示调用了谁；adapter 表示通过什么协议/工具接入；executor/owner 表示实际责任身份；Work/Run/lease/Decision 表示本次可做什么。能力记录只能说明一个版本、环境与任务类别的试验结果，不能自行授予批准权。

先验证现有合法 manual/受监督路径。无法合法承载 Claude 或 DeepSeek 时，明确 NOT_SUPPORTED 并提出小范围解耦卡；不得冒充 codex、沿用旧 lease 或把聊天批准替代运行授权。自动 Claude 进程适配是 P05，可晚于实际使用。

### 3.3 工具同源，但验证独立

卡工厂以一份冻结配置派生身份和脚本；判卷器独立验证生成物、真实执行记录和报告内容。生成器生成自己的“正确答案”再通过比较判绿，会掩盖同源错误。

T09 首版可以接受已批准的显式门禁矩阵，T11 后续再自动推导。两者不能循环依赖。哈希证明字节相同，不能独自证明命令执行、用例完整或业务正确。

### 3.4 领域能力通过边界接入

电气输入、编译反馈、现场记录应复用已有应用服务与治理对象，不另建一套平行状态机/审批库。领域模块不得直接改 continuity.db，界面也不绕过服务直接写库。

代码是否值得拆分，要看调用依赖、共同变更、测试困难和故障传播证据。A01 先识别一个热点，A02 只拆一个边界；不以“整洁架构”名义全面重写。T/P 中实际修改判卷、身份授权、租约等核心行为的任务按 core；只读设计与受监督演练按实际最高影响定档，不能仅因属于 T/P 分组就一律升档，也不能因此降档。

## 8. 成本控制与停止条件

WBS 的估算为低置信的**有效工程人时**，不是模型运行墙钟，也不是用户需要工作那么久。正式门禁机器占用另列；审批、排队、编译/现场窗口、账号费用和返工另算。没有本次实测支持固定交付日期。

先记录3个真实小任务的现状，再看后续3个任务是否改善：

| 指标 | 记录方法 | 决策用途 |
|---|---|---|
| 搭卡投入与身份错漏 | 配置开始至冻结的有效时间、被门禁抓出的残留次数 | 证明T08/T09是否值得维护；建议目标为人工重复填身份处数降到0 |
| 门禁成本 | 每组时长、负载、失败类型、重跑原因；失败不能删 | 校正预算，区分产品故障与环境问题 |
| 恢复成本 | 新会话读材料至提出合法下一步的时间、用户解释次数 | 检验P04/P06/P07，目标为用户无需手改内部治理JSON |
| 编译往返 | 首次编译结果、修复轮数、错误版本关联完整率 | 衡量C链是否节省工作 |
| 对表与现场问题 | 有出处条目比例、未解释差异数、复验缺口 | 衡量I/F链，而非统计生成文档数量 |

若一项工具在后续真实任务中没有减少错误或投入，停下评估而不是继续铺功能。无法获得真实厂商样本/运行环境时，该适配保持未验证；不要用模拟文本补出“完成”。

## 9. 开源项目与官方实践的借鉴

只借鉴已核实的机制，不在本次安装、复制代码或引入依赖：

- **Copier** 使用参数与版本化模板生成项目内容，可借鉴给T08/T09。具体卡工厂还必须来自本地已审定真实卡；模板引擎不能承担批准和验收。[Copier 官方仓库](https://github.com/copier-org/copier)
- **pytest JUnit XML** 提供结构化测试结果，可作为T04的一种首片格式。仍要同时核对受控命令回执、退出码、期望用例集合和运行身份，XML存在本身不证明执行。[pytest 官方文档](https://docs.pytest.org/en/stable/how-to/output.html#creating-junitxml-format-files)
- **GitHub Actions concurrency** 展示按资源分组限制并发的方式，可借鉴给本地重门禁调度。不能直接把其取消策略当成本地进程已安全停止，更不能据此自动终止其他Agent。[GitHub 官方文档](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency)

以上页面于2026-10-08读取。具体版本、许可证、Windows兼容与离线可用性在真正引入前再评估。没有建议搬入完整Agent平台，避免新增一套状态与维护责任。
