## 5. 合同（全部定稿，执行者不得改写含义）

### 5.1 `auto_pm/infrastructure/plc_doc_hook.py`（新增；只依赖 `auto_pm.plc.doc_consistency`，不依赖 CLI、应用层或 Qt；不写 SCL）

1. **常量**：`SOURCE_SUFFIXES = (".scl", ".db")`；`EXPORT_SUFFIXES = (".scl", ".db", ".md", ".json")`；`MAX_SHOWN = 12`；`ARCHIVE_PARTS = frozenset({"archive", "_archive"})`。以别名方式导入 `from auto_pm.plc import doc_consistency as dc`（与既有代码风格一致）。
2. **`is_plc_relevant(path)`**：只有三类文件触发——扩展名（不分大小写）为 `.scl`/`.db`；文件名以 `接口文档_IFC-` 开头的 `.md`；文件名等于 `PLC变量定义文档_VAR.md`。项目内的其他文件（README、笔记等）不触发。
3. **`plc_project_roots(root)`**：用 `git ls-files --cached -z -- :(glob)**/.plc.json` 列出暂存区（含本次新增）里所有含 `.plc.json` 的目录，仓库根用空字符串表示；目录路径含 `archive`/`_archive` 分量（不分大小写）的项目是历史存档，**排除**。
4. **`project_for(path, roots)`**：取包含该路径的**最高一层** `.plc.json` 目录（与 V01 验收门一致；DJ-2026-009 的嵌套 `.plc.json` 归到项目根）；没有则返回 `None`。
5. **按暂存区内容核对**：把项目在暂存区里的 `.scl/.db/.md/.json` 文件用 `git checkout-index --prefix=<临时目录>/ -z --stdin` 导出到临时目录，对该目录调用 `dc.analyze_project`，无论成败都清除临时目录；**工作区的任何未暂存改动都不参与判断**。
6. **判定**：有 `fail` 级发现或有带标记行 → 该项目“阻断”；`missing_doc`、`unparsable_doc` 只打印 `⚠️` 警告（含“建议运行 plc docs sync”）、不阻断。阻断时打印 `🚨 [auto-pm pre-commit] 物理阻断：PLC 项目 <名> 的文档与代码不一致（拦住项 N、待确认标记 N）：`，逐条列出（每条用 `Finding.render()`，至多 `MAX_SHOWN` 条，余下给出条数与 `plc docs check` 提示；带标记行列出文档名、行号、变量名）。

## 11. 与其他任务的关系与需要用户知悉的决策点

- **V02**（依赖 V01、V01B、V01C、V01D、C09）：演练工程取自治愈并重新钉死的基准。
- **需要用户在批准本卡时知悉的点**（均为我的默认裁决，如要改请在批准前说，我改卡后重新报批）：
  ① **只检查本次提交涉及的 PLC 项目**，不检查全部项目；代价是未治愈的项目（DJ-2026-009、SysLib）一旦被碰就会被拒；
  ② **拒绝时自动把文档草稿补进工作区**（只写文档、不写 SCL、不动暂存区）；对未治愈项目这一次可能补出很多行（DJ-2026-009 演练补入 74 行），需要审核后确认，或用 Git 还原；

  ④ **检查本身崩溃时拒绝提交**（与既有台账门一致，不为故障让路）；
