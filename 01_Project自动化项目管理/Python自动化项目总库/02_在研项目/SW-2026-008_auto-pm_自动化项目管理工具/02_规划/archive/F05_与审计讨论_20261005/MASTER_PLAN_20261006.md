## 2. 防止来回拉扯的规则

1. GPT 每项交付只提交一次；Claude 只审一遍，把**最终决定**写进 `m2-relay/DECISIONS_20261006.md`；GPT 照决定实现，不再等下一轮审阅。
2. 意见分歧：GPT 把不同意见写进自己的笔记，不阻塞；由 Claude 裁决，写进 DECISIONS；不再就同一点往返。
3. GPT 不通过用户转述等待 Claude：它读本文件与 DECISIONS 就知道下一步。用户只在批准/验收时介入。
4. 重门禁只由 Claude 跑。**重负载标记**：Claude 在跑重门禁时会创建 `.auto-pm/reports/HEAVY_GATES_RUNNING`，该文件存在期间 GPT 不跑任何 pytest；文件不存在时 GPT 可跑单个进程、2 分钟以内的针对性快速回路，且不得在 Claude 的真实进程测试窗口内跑。
5. 卡的流程不变：GPT 写草稿 V0.1 → Claude 在冻结字节的全量演练全绿后写最终 V1.0、机器预检、向用户报 SHA → 用户批准 → 执行 → 用户验收。
6. 失败不重试到绿；任何门禁失败就停、保留现场、由 Claude 判断最小修法。
