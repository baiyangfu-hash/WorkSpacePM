## 1. 背景与已核实事实（2026-10-08，基线 `763395e4`）

1. **审计发现（我已对照源码核实）**：`RuntimeCapabilities.contract_version` 与 `ContinuityQuery.schema_version` 原来都带 v1 默认值，所以一份缺了版本的载荷会被静默补成 v1；显式写错的版本本来就会被 `Literal` 拒绝，缺口只在“缺失被补齐”。下游也没有消费点重新校验：`PmFacadeService._query` 只做 `cast`，命令行 `pm resume`、`pm orient` 与 SDK `CockpitClient.orient` 直接使用 Facade 的返回，驾驶舱的能力提示只看两个开关与动作集合，不看版本。结果是版本检查在入口处形同虚设。
2. **设计采纳（对 GPT 的修复设计 `astra-milestone-audit-20261008/proposals/F01_F02_REPAIR_PLAN.md` §4 的取舍）**：采纳——两个版本字段必填；生产构造显式填写；新增共用的严格重验（对象先导出为普通字段数据再整体校验，这样 `model_construct` 与 `model_copy` 造出来的未校验对象也过不了）；接入服务返回前、Facade、命令行、SDK 与驾驶舱能力提示；存在的 query 块必须完整，缺版本、错版本、空块一律拒绝，不补默认值也不降级到旧格式；旧 Resume 缺整个 query 的历史读取保持兼容，但现代入口一律要求 query。**未采纳**：不改其他 DTO 的默认策略、不改外层 `ContinuityResume.schema_version` 的默认、不让驾驶舱每次快照都去调完整 query（GUI 没有完整 query 的输入，本卡不假称“GUI 已校验 query 版本”，完整 query 的身份消费留给 V05-C）。

   - M02-schema-version-defaults-again：the query schema version is required again, not filled in
   - M03-validation-trusts-model-instances：a model instance is re-validated from its exported data, never trusted as it is
   - M04-a-missing-query-block-passes-for-modern-entries：a modern entry never accepts a Resume without a query block
   - M05-the-producer-returns-without-the-check：the producer re-validates its own answer before returning it
   - M06-the-facade-only-casts：the facade checks what the producer returned instead of casting it
   - M07-the-commands-print-without-the-check：pm resume and pm orient check the answer again and print nothing when it is broken
   - M08-the-sdk-returns-without-the-check：the SDK orient checks what the facade returned
   - M09-the-cockpit-notice-trusts-the-producer：the cockpit reads the capability block only after checking its version
   - M10-a-missing-capability-version-is-filled-in：a capability block without a version is refused, never repaired
