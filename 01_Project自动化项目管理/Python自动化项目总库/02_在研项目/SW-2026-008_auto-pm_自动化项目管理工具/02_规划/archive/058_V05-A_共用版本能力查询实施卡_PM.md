### 5.2 行为合同

**5.2.1 合同 `continuity_query`**：`ContinuityQuery`（冻结）含 `schema_version="continuity-query.v1"`、控制根、执行根、候选提交、已配置与实际的 release 标识、运行时加载路径与回退原因、`producer_load_path`、`producer_sha256`、`capabilities`、可选的 `requested_action`、`evidence_id`；`RuntimeCapabilities` 含 `contract_version="runtime-capabilities.v1"`、`parking_supported` 与 `preemption_supported`（类型为 `Literal[False]`，写不出 true）、三个动作的 `ActionCapability`（`status` 类型为 `Literal["UNSUPPORTED"]`，附固定原因）；动作枚举只有 PARK、RESUME_PARKED、PREEMPT。

**5.2.2 查询服务 `ContinuityQueryService`**：只读；先校验被问的动作（未知则抛 `ContinuityQueryError`，此时不读取任何东西），再调用既有 `ContinuityResumeService.collect`，把 query 块附到结果上返回（`model_copy`），**不改 resume 自己的证据号**；`producer_sha256` 是本模块与合同模块实际加载字节的 SHA-256；`evidence_id`（`QUERY-…`）由 resume 证据号、版本、能力内容、被问动作与生产者哈希确定，不含墙钟时间；不创建库、不写文件、不带租约口令。

**5.2.3 Facade 与 SDK**：`PmFacadeService.resume` 委托查询服务（动作为空）；新增 `orient`（同一生产者，可问一个动作）；`CockpitClient.orient` 只读，经 Facade 返回同一份查询，错误统一为 `CockpitApiError`。

**5.2.4 CLI**：`pm resume` 的行为与参数不变，JSON 里多一个 `query` 块，文字输出多“查询合同”“挂起与插队不支持”两行；新增 `pm orient [项目] [--work-id] [--run-id] [--requested-action PARK|RESUME_PARKED|PREEMPT] [--path] [--json]`，与 resume 共用文字输出；被问的动作回答 `UNSUPPORTED` 且退出码 0，未知动作由命令的选项校验拒绝（退出码非 0，不读取任何东西）。

**5.2.5 兼容**：`ContinuityResume` 只增加一个默认为空的可选字段 `query`；去掉它的 JSON 仍能被旧读者解析；Store、resume 收集器、schema 与迁移一概不动。
