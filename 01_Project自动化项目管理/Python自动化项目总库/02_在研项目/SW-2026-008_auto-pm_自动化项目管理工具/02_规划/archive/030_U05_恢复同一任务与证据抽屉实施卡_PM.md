### 5.1 DTO（`contracts/pm_cockpit.py`，向后兼容：所有新增字段都有默认值；`schema_version` 字面量保持 `pm-cockpit-evidence.v1`；旧载荷必须仍能通过校验）

2. `PmCockpitFocus`（冻结）：`mission_id: str = ""`、`work_id: str = ""`、`run_id: str = ""`、`run_state: str = ""`（中文状态标签，取自服务既有 `_state_label`）。全空表示当前没有焦点。
3. `PmCockpitResumeState(StrEnum)`：`NO_ACTIVE_WORK`、`WAITING_FOR_USER`、`MONITORING`、`NEEDS_REVIEW`。
4. `PmCockpitResume`（冻结）：`state: PmCockpitResumeState`、`user_action: CockpitUserAction`、`reason: str`（≤200 字符）。默认值为 `NO_ACTIVE_WORK / NONE / ""`。
5. `PmCockpitCheckpointEvidence` 新增 `run_id: str = ""`、`is_current_run: bool = False`。
6. `PmCockpitEvidence` 新增 `focus: PmCockpitFocus`（默认空）、`evidence_currency: PmCockpitEvidenceCurrency`（默认 `NOT_APPLICABLE`）、`evidence_currency_reason: str = ""`、`resume: PmCockpitResume`（默认值同上）。

### 5.2 服务规则（`pm_cockpit_service.py`；`evidence()` 全程只读，不创建、不迁移、不写任何对象）

1. **焦点选择复用既有选择器**：Mission 取 `_primary_mission`，Work 取 `_primary_work(mission, works)`，Run 取 `_primary_run(该 Work 的 Run 列表)`。无 Mission 时焦点全空。焦点必须与同一存储上 `snapshot()` 的卡片 `mission_id`、活动时间线的 `work_id`/`run_id` 一致（根 Work 存在时）。
2. **重开同一任务**：两个各自新建的服务/Bridge 实例读取同一存储，得到逐字段相同的 `focus`；历史已验收/已关闭/已取消的 Mission、Work、Run 不得抢占焦点（沿用既有选择器的终态规则）。
3. **证据当前性**：
   - Mission 为 `ACCEPTANCE_PENDING` 时，调用 Facade 的 `acceptance_gate_reason(mission_id)`：返回空串 → `CURRENT`；返回非空 → `NOT_CURRENT`，原因取该字符串；Facade 之外的异常（`OSError`、存储错误等）→ `NOT_CURRENT`，原因固定为“无法核验验收证据：读取失败，未做任何修复。”，不得带异常文本。
   - 其它状态一律 `NOT_APPLICABLE`：无 Mission →“暂无进行中的需求。”；Mission 终态（`ACCEPTED`/`CLOSED`/`CANCELLED`）→“该需求已结束，证据仅供追溯。”；其余→“尚未进入验收阶段，暂无需核验。”。
   - 不得对每次 `snapshot()` 做证据核验（核验要采集 Git 内容，较重）；只在 `evidence()` 中做。
   - 不得 Mock `EvidenceCollectionService` 或 Facade 来得出 `CURRENT`；必须来自真实内容哈希比对。
4. **恢复状态判定表**（自上而下首个命中者生效；`reason` 一律为下表中文固定句，不拼接异常、路径或 ID）：

| 条件 | state | user_action | reason |
|---|---|---|---|
| 无 Mission，或 Mission 终态 | `NO_ACTIVE_WORK` | `NONE` | 暂无进行中的需求。 |
| 阻塞（沿用 `_is_blocked`） | `NEEDS_REVIEW` | `REVIEW_ESCALATION` | 存在需要您决策的阻塞事项；不会自动重复启动。 |
| Mission `AWAITING_APPROVAL` | `WAITING_FOR_USER` | `CONFIRM_START` | 等待您确认开工；确认前不会创建或启动任何执行。 |
| Mission `DRAFT` | `NO_ACTIVE_WORK` | `NONE` | 需求仍在准备阶段，尚无可执行内容。 |
| Mission `ACCEPTANCE_PENDING` 且证据 `CURRENT` | `WAITING_FOR_USER` | `CONFIRM_ACCEPTANCE` | 验证证据与当前内容一致，可确认最终验收。 |
| Mission `ACCEPTANCE_PENDING` 且证据 `NOT_CURRENT` | `NEEDS_REVIEW` | `REVIEW_ESCALATION` | 验收证据不能确认：后接 §5.2.3 的原因（整句仍 ≤200 字符，超出截断并以“…”结尾） |
| Mission `ACTIVE`，焦点 Run 为 `READY`（启动进行中） | `MONITORING` | `NONE` | 执行正在启动，无需操作。 |
| Mission `ACTIVE`，焦点 Run 为 `PENDING` | `NEEDS_REVIEW` | `REVIEW_ESCALATION` | 执行结果仍待核验；为避免重复执行，不会自动重试。 |
| Mission `ACTIVE`，焦点 Run 非终态且有可信启动证据（`started_run_ids`） | `MONITORING` | `NONE` | 执行已启动，驾驶舱正在处理，无需操作。 |
| Mission `ACTIVE`，焦点 Run 非终态但无可信启动证据 | `NEEDS_REVIEW` | `REVIEW_ESCALATION` | 已有执行记录，但无法证明进程已启动；为避免重复执行，不会自动重启。 |
| Mission `ACTIVE`，焦点 Run 为 `FAILED` 或 `CANCELLED` | `NEEDS_REVIEW` | `REVIEW_ESCALATION` | 最近一次执行未完成；需要您决定是否重新授权，不会自动重试。 |
| Mission `ACTIVE`，焦点 Run 为 `SUCCEEDED`，或尚无 Run | `MONITORING` | `NONE` | 已授权，等待执行或验证流转，无需操作。 |
| 其余 | `NEEDS_REVIEW` | `REVIEW_ESCALATION` | 当前状态无法确认，已保留现场；请向 PM 说明。 |

5. `checkpoints` 每项填 `run_id`；`is_current_run` 仅当其 `run_id` 等于 `focus.run_id`。条目的既有排序与内容不变（既有测试 `checkpoints[0].checkpoint_id` 必须继续成立）。
6. 服务对 `snapshot()`、`confirm_start`、`start_execution`、`confirm_acceptance` 的行为与签名保持不变。

### 5.3 Facade（`pm_facade_service.py`）

1. 新增 `acceptance_gate_reason(self, mission_id: str) -> str`：**只读**。Mission 不在 `ACCEPTANCE_PENDING` → 返回“当前 Mission 尚未到达用户验收门”；否则执行与 `accept` 完全相同的 `_require_current_acceptance_checkpoint`，通过返回空串，`PmFacadeError` 则返回其消息。Mission 不存在时沿用既有 `_mission` 的异常。
2. 不得改动 `accept`、`_require_current_acceptance_checkpoint`、`_acceptance_evidence_is_current` 的任何逻辑；既有验收测试不得修改、不得跳过。

### 5.4 Bridge（`pm_cockpit_bridge.py`）

1. 新增 `evidenceFinished = Signal(cast(type[object], "QVariant"))`；载荷 `{"success": bool, "project_id": str, "evidence": dict, "message": str}`。
2. 新增槽 `requestEvidence(project_id: str) -> QVariant`，返回 `{"accepted": bool, "busy": bool, "message": str}`：
   - `project_id` 去空白后为空 → `accepted False, busy False`；
   - 已有一个证据读取在途 → `accepted False, busy True`，不堆积；
   - 线程池拒绝启动 → 清理在途标记，`accepted False, busy False`；
   - 其余 → 启动 `QRunnable` 后台任务，`accepted True, busy True`。
3. 后台任务调用 `service.evidence(project_id)`：`PmCockpitError` → `success False`，消息取其文本；其它异常 → 记日志，消息固定为“无法读取证据。”，不带异常文本、路径或堆栈。
4. 完成信号**恰好发射一次**，沿用现有“50 ms 轮询 Timer + 工作对象 done 标记”模式；Bridge 销毁或 `stopSnapshotRefresh` 后，晚到结果不得发射（沿用 `_snapshot_delivery_enabled`，`startSnapshotRefresh` 会重新启用）。
5. `loadEvidence` 保持原签名与行为，仅作为非 QML 调用方的同步遗留接口；文档字符串注明 QML 必须使用 `requestEvidence`。
6. 不新增任何写入型或会启动/转移 Run 的槽。

### 5.5 QML

1. `boss_main.qml`：`showEvidence(projectId)` 只调用 `pmCockpitBridge.requestEvidence`；`accepted` 时 `statusMessage` 置为“正在读取证据…”，否则置为返回的 `message`；新增对 `evidenceFinished` 的处理：成功则 `evidenceDrawer.openEvidence(response.evidence)` 并清除该“正在读取”提示，失败则显示 `message`。`boss_main.qml` 中不得再出现对 `loadEvidence` 的调用。
2. `EvidenceDrawer.qml`：在既有内容之上新增三个区块，全部使用既有 `Theme` 令牌，不引入新依赖、不显示百分比、不显示任何令牌/租约信息：
   - “当前任务”：Mission / 根 Work / Run（`focus`）及 Run 状态；焦点全空时显示“暂无进行中的需求。”；
   - “验证证据与当前内容”：`CURRENT` 显示“与当前内容一致”（成功色）；`NOT_CURRENT` 显示“与当前内容不一致或无法核验”并列出原因（警示色）；`NOT_APPLICABLE` 显示“无需核验：”加原因（次要文本色）；
   - “下一步”：`resume.reason`，以及由 `resume.user_action` 映射的中文动作名（`CONFIRM_START`→“确认开工”，`CONFIRM_ACCEPTANCE`→“确认最终验收”，`REVIEW_ESCALATION`→“需要您查看并决策”，`NONE`→“无需操作”）。**抽屉内不提供任何动作按钮**（启动/验收仍只走卡片上的既有按钮，避免第二条入口）。
