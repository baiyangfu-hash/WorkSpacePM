## 2. 单一目标与完成定义

补强 V06 钩子测试的证明：完整暂存状态比较，加上空台账、垃圾台账、两个项目同提交、他项目变更单四类真实拒绝；一个既有测试文件的修改，产品、其他测试、模板、台账、WBS 均零改动。

6 个新增测试节点：

| 测试 | 证明 |
|---|---|
| `test_g10_…[empty]`、`test_g10_…[garbage]` | 变更单在、台账为空或为垃圾时 pre-commit 拒绝，且对账输出“缺失 1 条”（不是孤儿，也不是异常）；HEAD 与完整暂存状态不变 |
| `test_g11_…` | 一次提交含两个已注册项目的生产文件，commit-msg 以“归属项目不唯一”拒绝 |
| `test_g12_…` | 有效、已批准但属于另一个项目的变更单，commit-msg 以“缺少或重复关联变更单”拒绝 |
| `test_g13_…` | 同一双项目夹具里项目自己的变更单正常提交（排除“夹具坏了所以什么都被拒”） |
| `test_g14_…` | 暂存状态比较能看出同一路径的 blob 变化与 mode 变化，而名字列表分不出 |

4 个变异（三个改钩子产品代码，一个改测试辅助函数本身；每个由一个点名测试的真实断言失败杀死）：
   - M01-the-ledger-gate-is-off：an empty or garbage ledger (the change request's row is missing) blocks the commit
   - M02-two-projects-in-one-commit-are-accepted：production files of two registered projects in one commit are refused
   - M03-a-change-request-of-another-project-is-accepted：a valid change request that is not in the project's own tree is refused
   - M04-the-staged-state-is-compared-by-name-only：the staged-state comparison sees a changed blob and a changed mode, not only a changed name
