## 4. 根治合同

### 4.1 成功规划提交边界（A-P1-01）

1. 先纯校验 scope、risk、non-goal、grant、项目/条目/分类关系和重放身份，不只提前检查通配符。
2. 解析分类不得消费条目。只建草稿 CHG、仅计算范围卡或失败返回，都不是成功规划。
3. **持久化可读取的范围卡修订＋request/item/classification 绑定＋CONFIRMED→PLANNED＋对应事件，在同一 SQLite 事务成功或全部回滚。**事务内复核状态、项目、绑定和当前卡内容；两个各自成功的事务不等于原子提交。
4. create/submit 及 CLI 完整 approve 复用的规划流程都遵守同一成功边界。不分类的旧 SDK/GUI 兼容路径保留，TD-SW008-070 不在本卡；批准前不生成 Mission/Work/Run。
5. CHG 文件与 SQLite 不具备跨资源原子性，不承诺所有文件回滚。失败前已产生的草稿、CHG 编号预留、规范绑定按既有 P10 合同保留给相同请求重试，但条目不消费、不冒记成功；不得在重试改变域/性质/动作/范围后沿用不相符的旧 CHG。
6. 成功重试复用原 CHG/身份；同卡重放不新增消费事件或卡修订。条目不能供两个计划，真正竞争至多一个合法消费身份，失败者没有孤立 PLANNED 状态。
7. 不新增表/schema 版本，不手改 canonical 或补写旧条目的历史。测试库 SQL 断言/故障注入允许，生产仅走高层服务。

基础设施可提取并复用同连接事务内辅助操作。禁止应用层直接 SQL、跨连接伪装事务、删除事件补偿或吞掉失败。若必须新增表/改变未覆盖合同，停止，不扩项。

已有绑定时，每个显式 kind/action/domain/impact_scope 都必须与旧值一致；全部省略的合法重放保留，不要求重给 kind。不同输入在新增草稿/CHG/范围卡或消费事件前拒绝。request_id 不能跨项目借用。分类相同的正常范围卡修订仍按既有规则，不扩大成禁止修订。
