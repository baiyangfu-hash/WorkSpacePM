## 1. 背景与已核实事实（2026-10-12 夜，只读勘测）

1. **来源**：WBS 任务 `V08`（PLC 模板）。现有的 PLC 模板测试里，只有一个（`tests/plc/test_template_integrity.py`）用真模板渲染并要求零失败，没有测试证明“生成的字段与文件错误会被产品检查拒绝”“文件集稳定”“第二个工程独立”。
2. **做什么**：新增 `tests/e2e/test_pmf_template_plc.py`。它经产品的 `TemplateService.copy_template` 用真模板 `templates/plc-standard-project` 生成两个真实工程（`DJ-2026-901`/`DJ-2026-902`），并用产品的 `PlcChecker` 做静态检查：
   - v01 生成的文件集**精确等于**钉死的 83 个；v02 文件名与文本里没有残留的模板语法或 `.jinja`（HMI 原型的纯前端代码除外）；
   - v03 静态 PLC 检查零失败、通过项不少于 50、`.plc.json` 项通过且点名项目号；
   - v04 根与 `PLC_ST` 两处 `.plc.json` 都带着项目答案（name、version、description、libraries）；
   - v05 两份接口文档与变量文档点名项目号与项目名；台账与 PM_SESSION 存在且点名项目；
   - v06 **八种实际会被拒绝的错误**各自让检查**恰好一个失败项**（两处 `.plc.json` 非法、缺 name、缺 version、缺失；PM_SESSION 缺失；台账缺失；`PRD/接口文档_INT.md` 缺失；标准目录缺失），每个都先断言破坏前同一工程零失败；
   - v07 第二个工程文件集精确、不含第一个的项目号与名称、检查零失败；v08 非法项目号（小写短号、无连字符、年份过短、空串）被拒绝且不留残留。
3. **不做什么**：不改任何产品、模板、脚本字节（G6 逐字节核对）；**不把产品检查的偏松钉成合同**——PLC_ST 下接口文档被删、`OB1.scl` 被改成垃圾内容、变量文档被删、集成测试方案模板被删，产品检查都不报告或只警告（TD-SW008-129，需用户裁决，已在卡 121 登记）；不宣称 TIA 编译、下发或设备运行（保留 PLC 静态验证边界）；不推送。
4. **实测**（草稿工作树，非治理）：19 个测试全过（约 3 分钟，复制 PLC 项目较慢）；ruff 与 `mypy --platform win32` 对该文件干净；六个真实模板变异各被预期测试杀死并按字节还原（演练里发现并更正了一处预期，见下）。
5. **CI 风险（已核实、公开的局限）**：远端 CI 在 Linux 上跑全量测试；本卡的新测试在 Linux 上未经验证（项目名含中文、`copier` 复制 83 个文件）；若 CI 报告失败，是新发现、需另卡。该测试文件单跑一次约 3 分钟（复制 PLC 项目较慢），会让 rest 组多出约 3 分钟。
6. **容忍规则**：沿用 M3-RACE 的同一条具名规则（事先声明）：rest 组里若恰有 r09 一个失败且同字节隔离重跑 3/3 通过则放行并记偏差；此前四张受治理卡均严格全绿（未使用）。
7. **演练事实（非治理，草稿工作树，不是正式证据）**：2026-10-12 夜在基线 `c8a4f689`（卡 122 的提交）的临时工作树里跑了本卡的快速门禁脚本（原始输出在 `.auto-pm/reports/m3-v08/gates_rehearsal/`）：基线与候选的健康测试相同、新测试单跑 3 次各 19 passed、ruff 与 mypy 干净、六个真实模板变异各被预期测试杀死并按字节还原、四棵树核对只差新文件、真实 pre-commit 钩子对暂存的 1 个文件退出 0；rest 组用合成输出（卡 120 的通过数 +19）走判卷，G1–G9 全 PASS，4 个反例变体判卷结果各符合预期。**演练暴露一处预期错误并已在冻结前更正**：第一版把“删掉集成测试方案模板文件”的变异预期写成 t01、t03 都失败，实测静态检查不报告（只有 t01、t07 失败），所以预期改为只要求 t01 失败，这一点是 TD-SW008-129（静态检查偏松）的又一个例子，不是新测试的缺陷。演练不是正式证据，正式 Run 完整重跑。
