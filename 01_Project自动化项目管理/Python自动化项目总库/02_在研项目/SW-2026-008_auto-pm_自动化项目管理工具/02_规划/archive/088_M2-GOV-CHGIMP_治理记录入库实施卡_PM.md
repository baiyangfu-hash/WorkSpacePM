## 1. 背景与已核实事实（2026-10-10）

1. **为什么**：变更单正文与变更台账只存在于控制根的工作区磁盘上，不在任何提交里：版本库无法证明某次变更为什么发生，换机器或本机损坏就丢失（TD-SW008-108、009）。盘点卡 087 的清单显示：全工作区 470 个 CHG 文件，196 个不在任何分支历史里。
2. **做什么**：在基线 `425f8b09` 之上建一条**本地**分支 `codex/m2-chgimp-records`，一次提交 227 个冻结文件：
   - SW-2026-008 项目：新增 187 个 CHG 正文，更新 9 个（只是变更状态在工作区里更新过）；变更台账 1 个；
   - SYS-2026-001 项目：新增 29 个 CHG 正文；变更台账 1 个。
3. **台账怎么处理**：工作区的两个台账由控制根的工具链维护，比基线提交里的版本多行、行序号不同；本卡以“基线台账里的每一个行 ID 都在新台账里”为合同，而不是逐行相同；并要求每个新增 CHG 文件在台账里有行、每个台账行在（基线 ∪ 本卡新增）里有文件。
4. **不做什么**：PLC 项目（`0100_PLC自动化`）的变更单与台账（属于客户项目，等仓库可见性裁决）；`.disabled` 归档文件；SYS-2026-001 的文档移动与 WBS、`PM_SESSION`（控制根工作区里已有的未提交改动，另案）；`.auto-pm/` 下的任何运行态；不推送、不打 tag、不合并。
5. **已知的局限**：本卡自己的变更单与它在台账里的行是在启动之后才产生的，所以**不在冻结集合里**，收口之后控制根仍会多出这一个文件与一行台账；这正是 TD-SW008-113 要用门禁与流程修正的根因（以后每张卡把自己的变更单与台账行放进自己的提交）。
6. **检查**：独立检查器（沿用 TD8 的辅助函数，判断部分为本卡新写）核对：变更集恰为冻结集合、每个文件字节等于冻结哈希、文件种类只有 CHG 正文与两个台账、每个文本不含秘密格式的值、台账行 ID 不丢失且与文件互相覆盖；9 个反例（extra_file、missing_file、byte_drift、ledger_orphan_row、secret_injected、ledger_base_row_deleted、wrong_kind、file_not_in_ledger、crlf_flip）各被对应断言拒绝。**它不证明内容就是你的意思**，这由你验收。
7. 我在隔离演练树上完整跑了一遍（非受治理执行，不能复用为正式门禁）：基线、安装、候选三步原始退出码均 0；G1–G9 全部 PASS（含候选上的 `doc check` exit 0 和两个项目的台账对账 0/0/0）；9 项反例全部被指定断言拒绝；`gate_verdict` SHA-256 `9eafd9bf62561930e7449443ce6fc3ae910a825ed720c5a1dd611a1cf0c29fd9`，`DONE` SHA-256 `7db026228bed56cc8be70a09f7c42dde04390b42720b038b76c0e41d2e4ef3b1`；另在一次性工作树里对同一批字节执行了真实 pre-commit 钩子，退出 0；证据目录 `.auto-pm/reports/m2-chgimp/gates_rehearsal/`。
