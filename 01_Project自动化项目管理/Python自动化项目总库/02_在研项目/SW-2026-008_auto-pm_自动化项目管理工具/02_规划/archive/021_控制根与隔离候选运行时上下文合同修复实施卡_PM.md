### 1.2 目标

为 `control_root != execution_root` 的受管候选调用建立可证明的身份规则：

1. 运行管理 CLI 的包必须来自控制根 active release 的精确 payload；
2. 候选源码 HEAD 是被检对象，必须与 runtime release 身份并列回执，但**不要求二者为同一 Git HEAD**；
3. runtime 若既不属于 execution root 的受验证来源、也不属于控制根 active release，则拒绝解析，不能仅输出冲突后以成功码继续；
4. 候选直接启动继续因缺少 release payload fail-closed，不复制 release、不修改指针。

### 1.3 非目标

- 不合并、推送、部署、构建或切换 release；
- 不修改 `active_release.json`、`previous_release.json`、release payload 或 manifest；
- 不重新验证或改写 M1、C09、P2、U01～U04 的历史证据；
- 不创建第二个 continuity 数据库，不修改 canonical `.auto-pm/continuity.db`；
- 不把候选源码与稳定 runtime 的不同提交误判为版本漂移。

## 3. 设计合同

### 3.1 允许的两种模式

| 模式 | `execution_root` | 已加载 `auto_pm` 包 | 结果 |
|---|---|---|---|
| canonical | 控制根 | 控制根 active release 的 payload | configured = effective，允许 |
| governed candidate | 受管同仓候选 | **控制根** active release 的 payload | configured = effective，记录 candidate commit，允许 |

候选源码是测试/实施对象，不是治理 CLI runtime。其 HEAD 只需由 Git 提供并进入证据回执；不得以“HEAD 与 release source_commit 不同”作为自动拒绝理由。

### 3.2 必须拒绝的模式

- 已加载包不位于控制根 `runtime_root/releases/<configured_release_id>/auto_pm/__init__.py`；
- active 指针、release 目录、manifest 或 exact-tree 无法验证；
- execution root 不是同一仓库的受管 worktree，或无法证明 candidate commit；
- 候选直接启动而自身没有完整、受验证的 release payload；
- configured/effective release 不一致，或存在 fallback。

拒绝必须抛出上下文错误并使对应 CLI 非零退出；不得仅返回 `conflicts` 后继续被执行入口采用。

## 4. 实施顺序

1. 从干净的当前 M2 集成基线建立单一隔离候选；预检控制根 runtime、candidate HEAD、release metadata、Git worktree 身份和上述三条产品路径均无未知脏文件。
2. 新建独立 CHG 与精确 Decision。Decision 仅授权三条产品路径、一个隔离候选、一次实现 Run；明确禁止 release 指针、payload、数据库和历史证据写入。若先行 Decision 仅覆盖两路径，则原样保留并由同一 CHG 下的三路径补充 Decision 替代，不改写历史文件。
3. 实现控制根 runtime 识别：控制根 release 必须以 exact active slot 作为唯一可信来源；外部包或错误 release 立即异常。
4. 在同一候选补足单测。测试夹具必须在临时目录构造控制根、candidate root、pointer 与 release package，不读取或写入真实 release。
5. 仅在所有门禁通过时，经正常 hook 形成一个隔离提交；随后创建当前字节 Checkpoint，并以高层服务闭合 Run/Work/CHG。合并、推送、部署和 release 切换仍是独立边界。

## 6. 停止条件与失败出口

出现任一情况立即停止，不增加第四条产品路径：

- 修复需要改动 CLI、launcher、release manifest/pointer、Git hook 或控制面数据库；
- 双根合法调用无法在三条既定路径中表达；
- candidate 或 runtime 的 Git/worktree 身份不可证明；
- 任一门禁非零、候选出现额外脏路径、或直接启动候选变为可运行；
- 发现已有执行型入口在忽略 `WorkspaceContext.conflicts` 后仍可写入控制面。

失败时保留候选与测试输出，CHG 保持 implementing；不回退 release、不修改历史记录、不建立自动补偿链。若最后一项成立，应另行建立执行入口防御任务，而不是在本卡暗中扩大范围。
