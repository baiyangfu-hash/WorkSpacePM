## 1. 目标与最终裁决

本卡用于在 M2 继续扩展前完成一次有界的知识与工作区治理收敛，使后续 WBS
任务不会因陈旧文档、历史过程文件、母体脏状态或运行身份混用而发生错误路由。

本卡不以“删除全部历史文件”“主工作区绝对零脏”或“重写所有旧文档”为目标。
正常闭合后的唯一业务效果是：

1. 五大过程组中用于当前决策的文档与当前规范、WBS、canonical 运行态一致；
2. 历史材料均能被机器或清单识别为历史证据，不再参与当前路由；
3. 主工作区全部非洁净对象均有明确归类、来源、恢复方式和处置边界；
4. M2 只能从经验证的不可变前序任务或集成基线创建隔离候选，不能继承母体脏文件；
5. 形成一个机器可复验的 `M2_CONTINUE_ALLOWED` 或 `M2_BLOCKED` 裁决；
6. 本卡关闭后不遗留“继续整理全部历史资料”的隐含无限任务。

满足上述条件即可继续 WBS。被冻结但不影响当前真源和 M2 候选的历史资产，不阻塞
本卡关闭。

## 5. 每批统一执行模式

每批必须遵循：

1. 只读重验控制根、main、WBS、canonical DB、release 与 Git 状态；
2. 创建该批独立 CHG；
3. 由 DecisionService 生成精确 Decision，并固化到可验证的 Git HEAD；

5. 仅修改 owned paths；出现第 N+1 条路径立即停止；
6. 执行该批门禁并形成当前字节 Checkpoint；
7. 通过正常 hooks 创建唯一不可变提交；
8. 独立验收 Run、Work 和 CHG；
9. 采用、推送、部署和 release 切换仍是独立边界，不因本卡自动获得授权。

禁止直接在脏母体上批量编辑后再挑文件提交。

## 9. 失败分流与停止条件

### 9.1 非阻断差异

历史文档格式、无当前引用的旧术语、已归档材料的旧版本号等，记录到矩阵并保留，
不阻塞 M2。

### 9.2 阻断差异

以下任一项导致 `M2_BLOCKED`：

- 当前入口文档仍将退役能力或历史投影当作真源；
- 无法确定 M2 基线 HEAD 或候选继承母体脏字节；
- U01 提交、两条路径、控制面终态或验收引用发生非预期漂移；
- runtime identity 不一致且未 fail-closed；
- 当前 WBS、canonical 状态和 Git 基线互相矛盾；
- 未分类文件被测试、生成器、入口或当前文档读取；
- 台账对账非零或需要手改数据库；
- 必须扩大到生产源码才能证明准入安全。

阻断时停止当前批次，保留真实现场，只提交一个精确缺口；不得自动建立补偿链。

### 9.3 全局停止条件

- 周额度剩余量 `<=30%`；
- 当前 HEAD、DB 哈希、release、WBS 或 Decision 在执行中漂移；
- 出现 Decision 之外路径、跨项目写入或来源不明字节；
- 需要 `git clean`、`git reset --hard`、低层 SQL、`--no-verify`、手改 hooks；
- 需要重写历史 CHG、Checkpoint、验收报告或事故证据；
- 需要合并、推送、部署或切换 release，而当前批次未独立授权。

额度停止线触发时不启动新写入或测试批次；安全收集正在运行的进程与回执后停止，
不得以额度不足冒记本卡完成。
