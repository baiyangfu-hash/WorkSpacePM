# 详细设计说明书 (DSN) - auto-pm 自动化项目管理工具

> **2026-11-04 提示**：本文主体写于 2026 年 9 月，不描述后来的 Continuity v2 账本、工位、租约、发布快照等架构；现状以 `ARCHITECTURE.md`（V3.0.0）为准。

## 1. 分层架构与核心领域模型

```text
    auto_pm/
    ├── domain/                 # 核心领域逻辑 (无外部框架依赖)
    │   ├── plc/                # PlcChecker, PlcRepairer, PlcSclLinter, SpecSnapshotService
    │   ├── vartable/           # VarTableBatchParser, AutoshopParser, CodesysParser, Work3Parser
    │   ├── spec/               # SpecRegistryService, SpecIndexService, SpecCheckService
    │   └── models/             # Project, ChangeTicket, SpecItem, IOPoint DTO
    ├── infrastructure/         # 基础设施层
    │   ├── db/                 # SQLiteConnection, Repository, Schema
    │   ├── config/             # AppConfig
    │   └── utils/              # MarkdownParser, FileWatcher
    └── ui/                     # 用户交互层
        ├── cli/                # 14 大子命令入口 (project, plc, spec, change, etc.)
        └── qml/                # PySide6 QML 工业驾驶舱前端与 QObject Bridges
```

## 2. 关键核心算法与设计细节

### 2.1 PlcChecker 53 项门禁扫描算法
1. **物理目录唯一性判定**：检查 `01_启动` 到 `12_驱动器` 的序号唯一性，杜绝重复；
2. **FB PRD 四件套完整性矩阵**：遍历 `PLC_ST/` 下所有工站目录，断言每个工站必须具备 `IFC`、`DSN`、`CHG`、`UM` 4 份文档；
3. **SCL Linter 语法检查**：基于正则表达式与 AST 状态机，检查 VAR 变量未声明、无限循环与死锁风险；
4. **Spec Snapshot 一致性校验**：比对项目 `.plc.json` / `PM_SESSION` 中的快照与全局 `spec_registry.json` 是否同步。

### 2.2 VarTable 异构转译管道 (FormatDetector & BaseParser)
- **嗅探阶段**：检查文件魔数与首行特征（如 AutoShop 的 `_var_begin`，Work3 的制表符，CodeSys 的 XML 标签）；
- **转译阶段**：映射至统一 `IOPoint(tag_name, data_type, address, comment, station)` 模型；
- **持久化阶段**：批量输出至 `02_PLC程序/工程资产/io_points.csv`。
