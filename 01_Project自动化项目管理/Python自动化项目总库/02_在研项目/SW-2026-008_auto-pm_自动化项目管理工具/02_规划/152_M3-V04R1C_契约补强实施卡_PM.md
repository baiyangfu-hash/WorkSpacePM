## 1. 背景与已核实事实（2026-10-16）

1. **为什么**：项目 Claude 对卡 147、卡 148 的云端只读审计（`reviews/07_*`，2026-10-16 夜）指出三处，我在本机逐条核对后落地：
   - **启动时间按字符串比较**：同一时刻的两种写法（`Z` 与 `+00:00`、不同时区）被当成“换了进程”，`judge_process` 可能把活着的持有者判成 `PROVEN_DEAD`，进而允许回收；
   - **接受不带时区的 datetime**：本机时区一变，到期判断就漂；
   - **PENDING 的出口走不通**：卡 148 写“用户签 Decision 强制收回”，但代码里 `UNKNOWN` 分支排在 `forced_by_decision` 之前，永远到不了放行。
2. **做什么**（2 个已有文件改，不新增文件；见 §4）。补丁是项目 Claude 生成的（`patches/09`、`patches/13`），我用 `git apply --3way` 落在上一张卡的字节上，测试文件末尾两份补丁的冲突保留两边：
   - 启动时间统一成规范形式再比较：十进制 tick 数按整数；带时区的 ISO 时间转 UTC；不同种类、无法解析、只在较粗精度上相等而细处不同，一律 `UNKNOWN`，不判已死；
   - `lease_is_live` 与 `decide_reclaim` 拒绝不带时区的 datetime（`ValueError`）；
   - `decide_reclaim` 新增显式参数 `unknown_risk_accepted_by_decision`：只有它为真，`UNKNOWN` 才放行（原因写明“接受风险”），且绝不越过 `ALIVE`；`forced_by_decision` 的含义不变，原有测试不改；PENDING 的 `exit_path` 改指向这个参数；
   - 新增 6 个测试（合计 28 个）。
3. **开发期实测**（开发工作树，非治理）：28 个用例全过；`ruff`、`mypy` 干净。
4. **不做什么**：不改存储、不改任何其他文件、不读或返回 lease token、不改 `expires_at`、不加 `INITIAL_EPOCH`（留给存储卡）、不推送（夜间推送由我在收口后另行完成并读 CI）、不合并 main。
5. **容忍规则**：沿用 M3-RACE 的同一条具名规则（事先声明）：rest 组里若恰有 r09 一个失败且同字节隔离重跑 3/3 通过则放行并记偏差；此前所有受治理卡均严格全绿（未使用）。
6. **演练事实（非治理，草稿工作树，不是正式证据）**：2026-10-17 在基线（卡 154 的提交）的临时工作树里跑了一遍本卡的快速门禁与判卷（原始输出在 `.auto-pm/reports/m3-v04r1c/gates_rehearsal/`）：28 个契约用例全过、模块导入不加载存储、静态检查、20 个真实变异全部被抓住并按字节还原、真实 pre-commit 钩子退出 0；九组回归用合成输出（上一张受治理卡的输出按期望增量调整：contracts 组 +6）判卷，G1–G9 全 PASS，4 个反例变体判卷结果符合预期。演练不是正式证据，正式 Run 完整重跑。
