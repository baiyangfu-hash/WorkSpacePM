## 2. 单一目标（用户故事与完成定义）

作为用户，我希望规划失败后，已确认的事项仍然可见、可重试；重放不能忽略显式给出的新分类；文件取证必须真的是文件：

1. 非法的 scope、风险、非目标或执行授权使分类规划失败时，已确认条目保持 CONFIRMED、没有分类绑定、没有成功卡与成功事件（F01）；
2. 准备阶段（建单、写规范绑定、构造卡）失败后不消费条目，已预留的草稿与编号如实保留，同一请求冷重试成功且不重复建单；复用的 CHG 与分类或请求身份不符时拒绝（F02）；
3. 范围卡、分类绑定、条目与各自事件之间任一处在提交前故障，全部一起回滚、事件链连续（F03）；
4. 成功规划是持久的，重放得到相同的 ID 与 hash，消费、绑定、提交事件各恰好一次，执行对象（Mission/Work/Run）逐行不变（F04）；
5. 已绑定的重放，每个显式的 kind、action、domain、影响范围都必须与旧值一致，直接分类与收件箱两种来源都一样，跨项目借用被拒，全部省略的合法重放保留（F05）；
6. `file:` 取证必须是控制根内的普通文件，目录、缺失、断链、根外与无法证明者都被拒绝且不留条目与事件（F06）；
7. 同请求同内容、同条目不同请求、非法与合法计划的真实进程竞态，至多一份消费身份、无重复事件与编号（F07）；
8. 写后中断恢复、已保存卡的提交与批准、旧 SDK/GUI 兼容回归都仍成立，不增加执行权限（F08）；旧卡经 CLI 完整批准、批准身份与 plan_hash 在任何写入前核对、已批准请求的 `plan` 被拒而 `approve` 恢复同一张卡（C11、C12）。

### 5.2 行为合同

**5.2.1 分类规划的单一成功边界（A-P1-01）**
- `PmFacadeService` 在预留 CHG、写规范绑定或任何文件之前，先对范围卡契约做不落盘的纯校验（建草稿、用空 CHG 号构造一次范围卡以验证 scope、风险、非目标与执行授权），再只读解析分类（`IntakeStore.resolve_planning_classification`，不建绑定、不消费条目）。
- 成功的唯一入口是 `IntakeStore.submit_classified_planning_scope_card`：在同一个连接、同一个事务里重新解析分类，提交可读取的范围卡修订（沿用原公开方法 `submit_planning_scope_card` 的全部校验，由 `ContinuityStore._submit_planning_scope_card` 在调用方事务内运行），绑定分类、把条目由 CONFIRMED 改为 PLANNED 并写各自事件；任一步失败整体回滚。
- 带分类的 `create_planning_scope_card` 与 `submit` 都只在上述持久提交成功后才返回；不带分类的旧 SDK/GUI 路径保持原行为。
- 复用此前预留的 CHG 时，必须证明其项目、领域、性质、影响范围、紧急度与引用中的请求身份（request_id、input_fingerprint、kind、action、条目）都与本次分类一致；旧 SDK 卡的 CHG（没有入箱字段）只有在其既有分类字段全为 SDK 默认值且不可变身份一致时，才允许补上显式分类。
- CHG 文件与 SQLite 不具备跨资源原子性：失败前已产生的草稿、CHG 编号预留与规范绑定按既有合同保留给同一请求重试，条目不消费、不冒记成功。不新增表或 schema 版本；旧的 `bind_planning_classification` 接口保留。

**5.2.2 已绑定重放的分类核对（A-P1-02）**：已有绑定（直接分类或收件箱条目）时，每个显式给出的 kind、action、domain、影响范围都必须与旧值一致，不一致在写入任何草稿、CHG、范围卡或消费事件之前拒绝；全部省略的合法重放保留；request_id 不能跨项目借用。

**5.2.3 文件取证（A-P1-03）**：`file:` 必须 `resolve(strict=True)` 后位于控制根内且 `is_file()`；目录、缺失、断链、根外目标或无法证明者拒绝，不留条目与事件。不扩大成新的硬链接政策；`cmd`/`ledger`/`chg`/`commit` 取证的格式限制仍是既知局限（TD-SW008-072）。

**5.2.4 批准路径**：`approve` 在任何分类与写入之前先核对批准身份（`DecisionService.validate_planning_approval`），再用只读预览（`preview_planning_scope_card`，不落盘）重建卡并用恒定时间比较核对 plan_hash，过期或漂移即拒绝；已批准的请求，`plan`/`submit` 被拒，`approve` 恢复同一张卡。
