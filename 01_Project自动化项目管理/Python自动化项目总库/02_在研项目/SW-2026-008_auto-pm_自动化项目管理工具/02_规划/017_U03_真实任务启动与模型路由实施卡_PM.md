## 1. 用户故事与完成定义

用户故事：我在驾驶舱中只确认一次“开始执行”，系统只启动一个已经获得精确
批准的真实任务；在真实执行进程、session 和启动声明得到确认前，界面不得显示
“执行中”。重复点击、窗口重入或信号重放不得创建第二个 Run 或第二个进程。

本卡只处理从“已经批准的 PlanningScopeCard/Mission”到“真实受控执行已启动”的
链路，不负责：

- 为 U02 的 `PRE_AUTH` PlanningDraft 自动猜测范围或自动批准；
- 展示持续进度百分比、完整失败时间线或证据抽屉；
- 修改 E08 已验收的 LocalExecutor、监督器、租约或 Checkpoint 历史；
- 清理 C09/P2 历史 Work、Run、Checkpoint 或工作树；
- 合并、推送、部署、构建或切换 release。

完成必须同时满足：

1. 从 canonical 持久化批准链恢复的 PlanningScopeCard 与 Decision、CHG、plan hash、
   scope、execution grant 完全一致；恢复不完整时 fail-closed；
2. 一次确认只产生一个执行 operation、一个 Run 和一个真实启动声明；
3. QML 主线程不因前台执行 Saga 阻塞；同一 Mission 处于 inflight 时按钮不可再次触发；
4. 只有当前 Mission/root Work 的最新 Run 已取得真实 `RUN_STARTED`、session/PID
   证据后，驾驶舱才可显示“执行中”；
5. 启动失败、进程证据缺失或执行链中断时，不留下伪 `IN_PROGRESS/RUNNING`；
6. 历史 BLOCKED Run 不得污染当前 Mission 卡片；
7. U03A、U03B 分别形成当前字节 Checkpoint、正常 Hook 本地隔离提交和合法治理终态。

## 4. 模型路由修订

### 4.1 新的风险等级

| 等级 | 任务特征 | 默认执行 | 独立复核与升级 |
|---|---|---|---|
| `R0` | 纯文档、机械整理、只读清单 | Luna/Terra | 机器门禁即可；事实漂移时升级 R1 |
| `R1` | 单模块、边界明确、无状态机/租约/并发 | Terra high | 不同上下文只读复核；越界即升级 R2 |
| `R2` | 跨 UI/Service/Store、异步、幂等、持久状态 | Sol high/xhigh | Terra 或另一 Sol 会话独立复核；出现控制面矛盾升级 R3 |
| `R3` | 事件链、租约、进程回收、历史恢复、发布切换 | Sol ultra 或 Astra 规划，Sol 执行 | 必须异模型复核；不得由轻量模型单独裁决 |

规则：模型名称是当前路由实现，不是永久架构合同。WBS 固化风险级别，调度时根据
可用模型映射；Run 必须记录实际模型。不能因为使用高阶模型而跳过路径、门禁、
Checkpoint 或独立验收。

### 4.2 本卡路由

- `U03A = R2`：推荐 Sol high/xhigh 实施；由 Terra high 只读复核当前字节、真实
  进程证据和状态投影。若必须修改租约/监督器/事件模型，则立即停止并升级 R3，
  不在本卡内扩边。
- `U03B = R1`：推荐 Terra high 实施；由机器化 QML/Bridge 测试和 Sol 最终验收。
- Astra 不作为本卡日常执行模型；仅当现有 E08 合同无法表达“后台真实启动”或出现
  新的 lease/进程所有权矛盾时，进行一次只读架构裁决。

## 8. 有界纠正与停止条件

每阶段最多一个主 Run和一次同范围纠正 Run。只有失败稳定复现、全部位于本阶段
owned paths、子进程已可靠回收且预计 30 分钟内修复时，才允许纠正；否则停止。

以下任一情况立即停止，不创建平行补偿链：

- 周额度剩余 `<=20%`；
- 基线不再是规定提交、候选不干净或出现未声明路径；
- 需要修改监督器、LocalExecutor、租约、事件链、数据库 schema 或历史记录；
- 需要直接 SQL、手工 Checkpoint、`--no-verify`、测试跳过或类型抑制；
- LocalExecutor 无真实握手、session/PID 不可证明或子进程回收不明；
- 门禁未完整返回、QML 主线程仍阻塞、重复点击仍可产生第二 Run；
- canonical DB、WBS、CHG/Decision、runtime 身份发生未解释漂移；
- 需要合并、推送、部署、release 切换或清理历史工作树。

停止时保留当前真实状态和失败回执，不冒记 U03A/U03B 完成，不自动要求用户逐项
授权新补丁。若触发 R3 条件，只提交一次精确根因与最小新合同裁决。
