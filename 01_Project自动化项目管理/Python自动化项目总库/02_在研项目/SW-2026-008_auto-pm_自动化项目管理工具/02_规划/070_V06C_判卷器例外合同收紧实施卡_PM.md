## 1. 背景与已核实事实（2026-10-08，基线 `06f4ae4d`）

1. **审计发现**：GPT R4 审计（`.auto-pm/reports/m2-gpt-r4-20261008/AUDIT_REPORT_GPT_R4_V06.md`）在入库的判卷器里证实：基线例外状态可以没有例外条目；例外条目的复现证据可以指向不存在的文件或写错门禁编号仍被放行（R4-01，阻断）；九个门禁可共用同一份空报告并带正确 SHA 通过（R4-02）；畸形判卷文件会让判卷器抛 Python 异常（R4-08）。缺口在外部原件里就有，V06B 是等价迁入。台账已登记为 TD-SW008-099。
2. **历史判卷是约束**：我先把工作区里全部 110 份真实历史判卷用旧判卷器和新判卷器各判一遍：旧判卷器接受 66 份、拒绝 44 份；新判卷器逐份相同，**零差异**。过程中发现一个事实：历史判卷里的例外条目没有 `gate` 字段，编号 `E-G1-1` 并不指明门禁（例外实际属于 G2），所以不能按编号推断门禁——新合同把“没有 gate 字段的旧格式条目”按“覆盖该判卷全部例外门禁”处理，并仍要求其证据文件存在；带 `gate` 字段的新格式条目才按门禁一一对应，并要求证据文件绑定指纹。
3. **新合同**（判卷标准的其余部分一字不变）：
   - 状态为 PASS_WITH_BASELINE_EXCEPTION 的门禁必须被例外条目覆盖；带 gate 字段的条目只覆盖该门禁，其门禁必须是例外门禁；
   - 每个例外条目必须 source_reproduced 为真，且证据文件存在；新格式条目的证据还必须出现在 reports 里（指纹被校验）；
   - 多个门禁共用同一份空（全空白）报告拒绝；有内容的共用报告、门禁自己的空报告（比如成功的 diff 检查没有输出）放行；
   - 判卷文件读不了、不是合法 JSON、不是 JSON 对象、门禁/报告/例外的类型不对，都给出可诊断的拒绝而不是抛异常。
4. **工具侧（不在 Git 的门禁脚本，随卡冻结）**：变异运行器保存每次运行的完整 stdout/stderr 与退出码并绑定进判卷文件（R4-06）；新增“历史判卷回放”检查作为 G6 的一部分：110 份历史判卷新旧判卷器接受或拒绝逐份相同。
