## 1. 目标与完成定义

本卡建立一次性、可恢复、可审计的工作区卫生治理闭环。它不以“删除全部历史
工作树”作为目标，也不要求修复历史 C09/P2 控制面对象。

本卡只有在以下条件同时成立时才算完成：

1. 对本卡列出的五个托管工作树逐一完成当前性预检；
2. 预检通过的对象均通过 Codex 托管归档能力生成可恢复快照；
3. 未通过预检的对象不被移动或删除，并进入有证据的冻结清单；
4. 主工作区 Git 现场、canonical `continuity.db`、`main`、active/previous release
   指针及未列入本卡的工作树保持不变；
5. 形成当前对象清单、归档回执、冻结清单和恢复方式，并完成独立卫生治理 CHG；
6. 不遗留自动重试、补偿链或“继续清理全部历史对象”的隐含任务。

达到上述条件后，即使仍有被冻结的历史工作树，本轮卫生治理也应关闭。冻结对象
仅在其阻断条件消失或出现明确业务需求时，另行建立后续 CHG，不阻塞 M2。

## 3. 治理边界与授权结构

### 3.1 单一治理链

实施时只建立一条独立卫生治理链：

1. 新建一个 SW-2026-008 卫生治理 CHG；编号必须由当前台账与脚手架生成，禁止
   在本卡中预占编号；
2. 用户批准后，由 `DecisionService` 生成一张精确 Decision；
3. Decision 只授权本卡 §4 的五个 `identityKey` 执行托管归档，以及在
   `.auto-pm/reports/workspace-hygiene/` 写入本轮报告；
4. 一次批准覆盖五个对象的顺序处理。单个对象预检失败时，只冻结该对象并继续
   检查下一对象，不创建第二条补偿链，不要求用户逐个重新授权；
5. 所有对象处理结束后统一验收并关闭 CHG。

Decision 不授权源代码修改、Git 提交、分支移动、控制面状态流转、数据库写入、
缓存删除、release 操作或 WBS 修改。

### 3.2 绝对禁止

- 不使用 `pm-workflow`；
- 不执行 `git clean`、`git reset --hard`、`git stash` 或 shell 递归删除；
- 不直接执行 `git worktree remove`，不手工删除工作树目录；
- 不修改、压缩、复制或替换 canonical `continuity.db`；
- 不关闭、取消或改写历史 CHG、Decision、Mission、Work、Run、Checkpoint；
- 不合并、不推送、不部署、不构建或切换 release；
- 不调用、读取或依据已退役的 `pm-workflow` 执行任何治理动作；
- 不将 `.agents/` 中的旧实施卡、交接材料或过程日志纳入 Git；
- 不把被冻结对象的字节迁入 `main` 或 M2 候选；
- 不处理任何未在 §4 精确列出的工作树。

## 5. 每对象统一预检合同

每个对象在归档前必须独立满足全部条件：

1. `list_artifacts` 返回完全一致的 active worktree `identityKey`；
2. 物理目录存在，Git HEAD 与 §4 预期值一致；
3. `git status --porcelain` 为空；
4. canonical 只读查询确认 `run_items.worktree_path` 对该完整路径的引用数为 0；
5. 当前无 Python、Git 或其他已识别进程使用该目录；
6. 对象不属于当前执行任务、未挂载 PR、未初始化 submodule 或嵌套 Git 仓库；
7. 提交对象可由 `git cat-file -e <HEAD>^{commit}` 读取；
8. 主工作区、`main`、canonical DB 和 release 指针已采集动作前指纹。

任一条件不满足：不得归档、不得修复现场、不得自动重试；将对象记为 `FROZEN`
并写明失败条件，继续检查下一对象。

## 6. 实施步骤

### 阶段 A：当前性快照

1. 记录周额度、主工作区 HEAD/branch/status 指纹、`main`、active/previous
   release、canonical DB SHA-256；
2. 只读导出 9 条非终态 Run 的 ID、状态和工作树路径；
3. 调用 `list_artifacts`，确认 §4 五个 identityKey 当前仍可由托管能力处理；
4. 对五个对象执行 §5 预检，形成 `ELIGIBLE` 或 `FROZEN` 清单。

### 阶段 B：逐对象托管归档

只对 `ELIGIBLE` 对象调用 `archive_worktree`。每次仅归档一个对象，并立即验证：

1. 返回成功且 `list_artifacts` 中出现 `archived_worktree`；
2. 快照 identityKey、原 HEAD 和恢复信息可读取；
3. 其余四个目标及全部非目标工作树状态未变化；
4. 主工作区状态指纹、canonical DB SHA-256、`main` 和 release 指针未变化。

验证失败时停止后续归档；已成功产生的托管快照保留，不回档、不删除。

### 阶段 C：冻结清单与最终验收

在 `.auto-pm/reports/workspace-hygiene/<execution-date>/` 输出：

- `preflight.json`：动作前 Git、DB、release 与进程事实；
- `archive-receipts.json`：成功归档对象及恢复标识；
- `frozen-inventory.json`：本轮失败对象和所有明确禁止对象；
- `final-verification.md`：动作后不变量与完成结论。

报告只记录事实，不替代托管归档回执、CHG 或 Decision。

完成态允许两种结果：

- `COMPLETED_WITH_ARCHIVES`：至少一个对象成功归档，其余对象均有冻结原因；
- `COMPLETED_NO_ELIGIBLE_OBJECTS`：五个对象均因当前性条件失败而冻结，且未发生
  任何破坏性操作。

两种结果都允许关闭本轮卫生治理 CHG；禁止因“仍有历史对象”无限延长任务。

冻结不是删除前的等待队列。只有出现新的业务需要或冻结原因消失时，才能另行建立
精确 CHG；不得由本卡自动续作。

## 8. 额度与停止条件

在阶段 A 开始、每次归档前和最终 CHG 流转前检查周额度。剩余量 `<=40%` 时：

- 不启动新的归档动作；
- 完成正在返回的托管归档回执收集；
- 写明已完成对象、未执行对象和当前不变量；
- 保留现场并停止，不把额度不足解释为治理完成。

其他立即停止条件：

- 主工作区 HEAD/status、`main`、canonical DB 或 release 指针发生非预期变化；
- 发现运行中进程占用目标目录；
- 目标 HEAD、clean 状态、artifact identityKey 或 canonical 引用与预检不符；
- 托管归档未返回可恢复快照；
- 操作要求 shell 删除、数据库修改、分支移动、推送、部署或 release 切换。

## 9. 与 M2/WBS 的关系

- 本卡不修改 M0/M1 历史结论，不更新 WBS 历史事件；
- M2 从 `main@0d7071b7` 或其后续经独立验收的干净候选启动；
- 本卡未完成不阻塞 M2 的设计和隔离开发，只禁止使用被冻结工作树作为基线；
- 后续每个 M2 任务继续遵循“干净隔离候选、正常 hooks、不可变提交、独立采用”模式；
- 推送、部署、release 切换始终是独立边界，不由本卡授权。
