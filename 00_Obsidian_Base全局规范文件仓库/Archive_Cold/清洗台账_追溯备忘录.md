## 二、历史 TPL-* 项目模板销案决议（Superseded by Copier Templates）

在第 3 批清洗（2026-05-08）残留的任务清单（`checklist.md`）中曾记载：
> *"⚠️ 项目模板(TPL-*)共9个文件随旧目录被误删（需后续恢复）"*

经 2026-09-07 深度审计及针对活体工程（`DJ-2026-005`、`SW-2026-009`）的全面穿透调研，架构师团队做出如下**正式销案决议**：

1. **工程现状事实**：
   - 现行工作空间的所有工程初始化已全量下沉至驾驶舱 Copier 脚手架：
     - PLC 标准项目骨架：`00_Infrastructure/auto_pm/templates/plc-standard-project`
     - PLC 共享库骨架：`00_Infrastructure/auto_pm/templates/plc-shared-library`
     - Python 独立工具骨架：`00_Infrastructure/auto_pm/templates/python-tool`
   - Python 靶子 `SW-2026-009` 与 PLC 靶子 `DJ-2026-005` 均由上述 Copier 脚手架生成并受驾驶舱守护，**两工程对旧 `TPL-*` 文件的消费量均为 0**；
2. **战略基线铁律对齐**：
   - 依据 `AGENTS.md`【资产沉淀与生态位隔离铁律】：**Obsidian 规范库定位为“业务大脑”，只沉淀核心抽象规范与状态机逻辑；物理目录结构与工程骨骼属于驾驶舱 Copier 脚手架**；
   - 依据【模板即捕兽夹】原则：手写 Markdown 散装模板缺乏自动参数渲染与强制质量占位符，属于过时的早期过渡产物；
3. **裁决与销案**：
   - **决议**：9 个历史 `TPL-*` 模板正式判定为 **已被 Copier 脚手架降维取代（Superseded by Copier Templates）**；
   - **处置**：**坚决不从 Git 历史恢复回活跃规范库**，避免引入低价值死文档污染规范单真源。原清单挂账在此**正式注销、永久销案**！
