## 1. .plc.json 配置规范

### 1.1 必填字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | string | 是 | 项目编号(如 DJ-2026-005) |
| `description` | string | 是 | 项目中文描述 |
| `version` | string | 是 | 语义化版本号(如 V5.0.0) |
| `libraries` | string[] | 条件必填 | 当项目引用共享库时必须配置 |

### 1.2 libraries 配置

当项目使用 `01_SharedLibraries/SysLib` 中的功能块(如 FB_TON, FB_CTU 等)时, 必须配置此字段, 否则 LSP 无法找到功能块定义。

**配置规则:**
- 使用相对于项目 `.plc.json` 所在目录的相对路径
- 路径分隔符使用 `/`(正斜杠)
- 支持配置多个库目录
- **注意: 字段名必须为 `libraries`, 不是 `libraryDirectories`(后者不是 Siemens LSP 的有效字段)**

**标准配置示例:**

项目位于 `0100_PLC自动化/DJ-2026-005/`（推荐将 `.plc.json` 放在项目根目录）:
```json
{
  "name": "DJ-2026-005",
  "description": "边框缓存机 PLC 控制系统",
  "version": "V6.0.0",
  "libraries": [
    "../01_SharedLibraries/SysLib"
  ]
}
```

路径解析:
- `.plc.json` 位于 `0100_PLC自动化/DJ-2026-005/`
- `../01_SharedLibraries/SysLib` 解析为 `0100_PLC自动化/01_SharedLibraries/SysLib`
- 如果该路径不存在, 需要调整为正确的相对路径

**多项目共用库的路径计算:**

对于 `0100_PLC自动化` 下的项目, SysLib 共享库位于 `0100_PLC自动化/01_SharedLibraries/SysLib/`:

| 项目位置 | libraries 值 |
|----------|-------------|
| `0100_PLC自动化/DJ-2026-005/` | `["../01_SharedLibraries/SysLib"]` |
| `0100_PLC自动化/DJ-2026-000/` | `["../01_SharedLibraries/SysLib"]` |

### 1.3 常见配置错误

| 错误 | 现象 | 解决方法 |
|------|------|----------|
| 缺少 libraries | LSP 报错"未找到 FB_TON 的任何定义" | 添加 libraries 配置 |
| 使用 libraryDirectories(无效字段名) | LSP 静默忽略, 库文件不被扫描 | 改为 libraries |
| 路径错误 | LSP 仍然报错 | 检查相对路径是否正确 |
| 使用绝对路径 | 跨机器不兼容 | 改用相对路径 |

## 2. SysLib 共享库引用规范

### 2.1 SysLib 库结构

```
01_SharedLibraries/SysLib/
├── .plc.json          # 库配置文件
├── README.md          # 库说明文档
├── timer/             # 定时器功能块
│   ├── FB_TON.scl     # 接通延时定时器
│   ├── FB_TOF.scl     # 关断延时定时器
│   ├── FB_TONR.scl    # 保持型定时器
│   └── FB_TP.scl      # 脉冲定时器
├── counter/           # 计数器功能块
│   ├── FB_CTU.scl     # 加计数器
│   ├── FB_CTD.scl     # 减计数器
│   └── FB_CTUD.scl    # 加减计数器
├── edge/              # 边沿检测
│   ├── FB_R_TRIG.scl  # 上升沿检测
│   └── FB_F_TRIG.scl  # 下降沿检测
├── convert/           # 类型转换
│   ├── FC_DINT_TO_TIME.scl
│   ├── FC_TIME_TO_DINT.scl
│   ├── FC_INT_TO_TIME.scl
│   └── FC_TIME_TO_INT.scl
├── log/               # 日志
│   └── FC_LogMsg.scl
└── pulse/             # 脉冲生成
    └── FB_TaktGenerator.scl
```

### 2.2 FB_TON 定位规则

当 LSP 报错"未找到 FB_TON 的任何定义"时, 按以下步骤排查:

1. 检查 `.plc.json` 是否包含 `libraries` 配置
2. 检查相对路径是否指向正确的 SysLib 目录
3. 检查 SysLib/timer/FB_TON.scl 文件是否存在
4. 检查 FB_TON.scl 文件内容是否完整(FUNCTION_BLOCK FB_TON 定义)

### 2.3 FB_TON 接口规范

```scl
FUNCTION_BLOCK FB_TON
VAR_INPUT
    IN  : BOOL;    // 启动信号
    PT  : DINT;    // 预设时间(扫描周期数), 不是 TIME 类型!
END_VAR
VAR_OUTPUT
    Q   : BOOL;    // 输出信号(达到预设时间后为 TRUE)
    ET  : DINT;    // 已用时间(扫描周期数), 不是 TIME 类型!
END_VAR
```

**关键区别:**
| 参数 | SysLib FB_TON (LSP) | 标准 IEC TON (TIA Portal) |
|------|---------------------|---------------------------|
| PT 类型 | DINT (扫描周期数) | TIME (毫秒) |
| ET 类型 | DINT (扫描周期数) | TIME (毫秒) |
| PT 示例 | `PT := 500` | `PT := T#500ms` |
| ET 示例 | `ET => diElapsed` | `ET => tElapsed` |

## 3. 项目目录结构规范

### 3.1 标准 PLC 项目目录布局

```
0100_PLC自动化/DJ-2026-XXX/
├── .plc.json              # 项目配置文件(推荐放在项目根目录)
├── 00_项目管理/           # 项目管理文档
├── 01_需求与设计/         # 需求和设计文档
├── 02_PLC程序/
│   └── PLC_ST/
│       ├── .plc.json     # 项目配置文件(必须)
│       ├── 00_程序方案/   # 方案级文档：需求、技术方案、详细设计、接口文档_INT.md（标准位置）
│       ├── .plc-out/     # 自动生成目录(禁止手动修改)
│       ├── DB1/          # 数据块
│       ├── OB1/          # 主程序
│       ├── common/       # 公共功能块（各块目录下的 PRD/ 放该块的接口文档）
│       ├── conveyor/     # 输送机功能块
│       ├── external/     # 外部设备交互
│       ├── feeder/       # 送料机构
│       ├── pickplace/    # 取放料机构
│       └── Test/         # 测试用例
├── 03_HMI设计/
├── 04_现场调试/
└── ...
```

### 3.2 关键目录说明

| 目录 | 用途 | 可修改 |
|------|------|--------|
| 根目录 `.plc.json` | 项目配置（推荐标准位置） | ✅ 可修改 |
| `PLC_ST/.plc.json` | 兼容历史/嵌套工程布局 | ✅ 可修改 |
| `.plc-out/` | 自动生成输出 | ❌ 禁止修改 |
| `DB1/` | 数据块定义 | ✅ 可修改 |
| `OB1/` | 主程序 | ✅ 可修改 |
| `*/FB_*.scl` | 功能块源码 | ✅ 可修改 |
| `Test/` | 测试用例 | ✅ 可修改 |
| `PLC_ST/00_程序方案/` | 方案级文档（含 `接口文档_INT.md`），**标准位置**；根 `PRD/` 为历史兼容位置，驾驶舱继续接受 | ✅ 可修改 |
| `*/PRD/` | 该块目录的块级文档（`接口文档_IFC-<块名>.md` 等） | ✅ 可修改 |

## 4. 新建项目配置检查清单

创建新 PLC 项目时, 必须逐项检查:

- [ ] `.plc.json` 已创建, 包含 name/description/version 字段
- [ ] `libraries` 已配置, 指向 SysLib 共享库(注意: 不是 libraryDirectories)
- [ ] 相对路径已验证(从 .plc.json 所在目录出发能找到 SysLib)
- [ ] SysLib/timer/FB_TON.scl 文件可被 LSP 正确解析
- [ ] 项目目录结构符合 3.1 节的标准布局
- [ ] `.plc-out/` 目录存在(首次编译后自动生成)
- [ ] GlobalVars.db 数据块已创建

## 5. 多项目共享库访问最佳实践

### 5.1 共享库架构设计

#### 5.1.1 推荐目录结构

```
My_Workspace/
├── 00_Obsidian_Base全局规范文件仓库/  # 规范真源仓
├── 0100_PLC自动化/
│   ├── 01_SharedLibraries/    # 共享库根目录(所有项目共用)
│   │   ├── SysLib/            # 系统基础库
│   │   │   ├── .plc.json
│   │   │   ├── timer/
│   │   │   ├── counter/
│   │   │   └── edge/
│   │   └── AppLib/            # 应用业务库(可选)
│   │       ├── .plc.json
│   │       └── ...
│   ├── DJ-2026-000/          # 项目A
│   │   ├── .plc.json
│   │   └── 02_PLC程序/
│   │       └── PLC_ST/
│   ├── DJ-2026-005/          # 项目B
│   │   ├── .plc.json
│   │   └── 02_PLC程序/
│   │       └── PLC_ST/
│   └── DJ-2026-XXX/          # 其他项目
│       └── ...
└── .vscode/
    └── launch.json            # 多项目调试配置
```

#### 5.1.2 库分类策略

| 库类型 | 用途 | 变更频率 | 适用范围 |
|--------|------|----------|----------|
| **SysLib** | 基础功能块(定时器、计数器、边沿检测等) | 低 | 所有项目 |
| **AppLib** | 业务通用逻辑(如通用输送机控制) | 中 | 同类项目 |
| **项目私有** | 项目特定功能块 | 高 | 当前项目 |

### 5.2 多项目配置模式

#### 5.2.1 模式一: 统一工作区(推荐)

所有项目放在同一工作区下，共享库位于固定位置：

```
0100_PLC自动化/
├── 01_SharedLibraries/SysLib/    # 固定位置
├── DJ-2026-000/                  # 项目A
└── DJ-2026-005/                  # 项目B
```

**配置示例:**

项目 DJ-2026-005 (`.plc.json` 位于 `0100_PLC自动化/DJ-2026-005/`):
```json
{
  "name": "DJ-2026-005",
  "description": "边框缓存机 PLC 控制系统",
  "version": "V6.0.0",
  "libraries": [
    "../01_SharedLibraries/SysLib"
  ]
}
```

#### 5.2.2 模式二: 独立项目引用外部库

项目独立存在，通过绝对路径或网络路径引用共享库：

```json
{
  "name": "DJ-2026-005",
  "description": "边框缓存机 PLC 控制系统",
  "version": "V6.0.0",
  "libraries": [
    "D:/SharedLibraries/SysLib"    // 绝对路径(不推荐跨机器使用)
  ]
}
```

### 5.3 路径计算方法

#### 5.3.1 相对路径计算步骤

1. **确定 `.plc.json` 所在位置**
   - 示例: `0100_PLC自动化/DJ-2026-005/.plc.json`

2. **确定目标库位置**
   - 示例: `0100_PLC自动化/01_SharedLibraries/SysLib/`

3. **计算相对路径**
   - 从 `.plc.json` 向上返回 1 层: `../`
   - 然后向下进入库目录: `01_SharedLibraries/SysLib`
   - 最终: `../01_SharedLibraries/SysLib`

#### 5.3.2 路径验证方法

在命令行中切换到 `.plc.json` 所在目录，执行以下验证：

```bash
# Windows PowerShell
Test-Path "../01_SharedLibraries/SysLib"

# 或检查是否存在关键文件
Test-Path "../01_SharedLibraries/SysLib/timer/FB_TON.scl"
```

### 5.4 多项目调试配置

#### 5.4.1 launch.json 多项目配置

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Debug PLC (DJ-2026-000)",
      "type": "plc",
      "request": "launch",
      "program": "${file}",
      "plcRoot": "./0100_PLC自动化/DJ-2026-000",
      "stopOnEntry": false,
      "entryOb": "OB1"
    },
    {
      "name": "Debug PLC (DJ-2026-005)",
      "type": "plc",
      "request": "launch",
      "program": "${file}",
      "plcRoot": "./0100_PLC自动化/DJ-2026-005",
      "stopOnEntry": false,
      "entryOb": "OB1"
    }
  ]
}
```

**⚠️ 重要说明:**
- `plcRoot` 必须使用**相对路径** (`./`) 开头
- **禁止使用 `${workspaceFolder}` 变量**: Siemens PLC 扩展不支持此变量，会导致 "Unable to resolve a unique PLC root" 错误
- **禁止使用硬编码绝对路径**: 如 `d:/xxx/xxx`，会导致跨机器不兼容
- 路径相对于工作空间根目录解析

#### 5.4.2 调试注意事项

| 事项 | 说明 |
|------|------|
| **${file} 变量** | 启动调试前必须打开一个 `.scl` 文件 |
| **plcRoot 路径** | 必须指向包含 `.plc.json` 的目录 |
| **切换调试目标** | 在调试面板下拉菜单中选择目标项目 |
| **重启 LSP** | 修改 `.plc.json` 后需重启 VS Code 或执行"Reload Window" |

### 5.5 常见问题与解决方案

| 问题 | 现象 | 解决方案 |
|------|------|----------|
| **库文件不被加载** | LSP 报错"未找到 FB_TON" | 检查 `libraries` 字段名是否正确(不是 `libraryDirectories`) |
| **路径解析失败** | LSP 静默或报错 | 使用 5.3.2 节方法验证相对路径 |
| **多项目冲突** | 调试时加载了错误的库 | 确保每个项目的 `plcRoot` 配置正确 |
| **库更新不生效** | 修改 SysLib 后项目无变化 | 删除 `.plc-out/` 目录后重新编译 |
| **跨机器路径问题** | 在其他机器上路径无效 | 使用相对路径而非绝对路径 |

### 5.6 最佳实践总结

#### 5.6.1 配置规范

1. **统一库位置**: 所有项目使用同一共享库位置
2. **相对路径优先**: 避免使用绝对路径，提高可移植性
3. **字段名正确性**: 始终使用 `libraries`，不使用 `libraryDirectories`
4. **版本控制**: 将共享库纳入版本控制，确保团队一致性

#### 5.6.2 维护规范

1. **库变更通知**: 修改 SysLib 后通知所有使用该库的项目负责人
2. **兼容性保障**: 新增功能向后兼容，不删除或修改现有接口
3. **文档同步**: 更新库代码时同步更新文档和示例
4. **测试验证**: 修改库后在代表性项目中验证功能

#### 5.6.3 团队协作规范

1. **共享库所有权**: 指定专人负责维护 SysLib
2. **变更流程**: 修改共享库需通过代码审查
3. **版本标签**: 对共享库创建版本标签，便于项目锁定特定版本
4. **问题反馈**: 项目遇到库问题时统一反馈给库维护人
