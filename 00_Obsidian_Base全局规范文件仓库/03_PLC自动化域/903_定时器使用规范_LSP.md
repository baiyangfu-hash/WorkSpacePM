# 定时器使用规范 — FB_TON / FB_TONR 调用约定

> 版本：V2.2.0
> 状态：已验证
> 更新日期：2026-10-21
> 适用范围：SysLib 共享库定时器 FB_TON / FB_TONR

---

## 1. 定位与变更说明

### 1.1 定位

本规范定义 SysLib 中 **FB_TON** 和 **FB_TONR** 功能块的标准调用约定，替代旧版 V1.0.0 中基于 Go-Gen 纯逻辑计数器的定时器方案。

### 1.2 V2.0.0 主要变更 (Breaking)

| 变更 | V1.0.0 (已废弃) | V2.0.0 |
|------|-----------------|--------|
| **定时器实现** | Go-Gen Counter 纯逻辑 (`Counter := Counter + 1`) | SysLib FB_TON / FB_TONR (共享库实例) |
| **参数类型** | INT Counter | DINT PT / ET |
| **时间单位** | 扫描周期 (隐式) | 扫描周期 (显式, DINT=毫秒等效值); **V2.2.0 起为真实毫秒, 见 §1.4** |
| **调用方式** | `IF bStart THEN Counter := Counter + 1` | 三段式: 预赋值 → 全参数调用 → 读输出 |
| **测试框架** | Go 单元测试 `WAIT_CYCLES` | TIA Portal / 实体 PLC |

### 1.4 V2.2.0 变更 (用户 2026-10-21 批准)

| 变更 | V2.1.0 | V2.2.0 |
|------|--------|--------|
| **时间单位** | 扫描周期 (每调用一次 +1, 时长随扫描周期漂移) | **真实毫秒** (内部调用平台标准 IEC `TON`) |
| **接口** | IN / PT / Q / ET (+R), DINT | 不变 |
| **FB_TONR** | 按扫描次数累计 | 用 TON 分段累计毫秒, IN 断开保持, R 优先清零 |
| **PT<=0** | TON: Q 跟随 IN; TONR: 永不到达 | TON 不变; TONR: IN 接通即到达 |

调用方写法 (三段式、顶部无条件调用、DINT 赋值、禁用 `T#` 字面量) 全部不变, 只是 PT/ET 的单位从此按毫秒理解。

### 1.3 V2.1.0 变更

| 变更 | V2.0.0 | V2.1.0 |
|------|--------|--------|
| **FB_TON 调用位置** | IF 分支内条件调用 | 无条件顶格调用 (与 TONR 统一) |
| **定时器组织** | 分散在各逻辑块中 | 集中在 FB 顶部"定时器批量调用区" |
| **原理** | — | FB 实例每周期必须执行, 跳过调用导致 `.Q`/`.ET` 僵尸值 |

## 2. 功能块接口

### 2.1 FB_TON — 接通延时定时器

> 源码位置: `SysLib/timer/FB_TON.scl`

| 参数 | 方向 | 类型 | 说明 |
|------|------|------|------|
| `IN` | INPUT | BOOL | 启动信号, TRUE=计时, FALSE=复位 |
| `PT` | INPUT | **DINT** | 预设时间 (毫秒) |
| `Q` | OUTPUT | BOOL | 到达预设时间后为 TRUE |
| `ET` | OUTPUT | **DINT** | 已用时间 (毫秒) |

**行为**:
- IN=TRUE 时计数器从 0 累加, 达到 PT 后 Q=TRUE 并保持
- IN=FALSE 时 Q=FALSE, ET=0, 计数器清零

### 2.2 FB_TONR — 保持型接通延时定时器

> 源码位置: `SysLib/timer/FB_TONR.scl`

| 参数 | 方向 | 类型 | 说明 |
|------|------|------|------|
| `IN` | INPUT | BOOL | 启动信号, TRUE=累计计时 |
| `R` | INPUT | BOOL | 复位信号, TRUE=清零 |
| `PT` | INPUT | **DINT** | 预设时间 (毫秒) |
| `Q` | OUTPUT | BOOL | 到达预设时间后为 TRUE |
| `ET` | OUTPUT | **DINT** | 已用时间 (毫秒) |

**行为**:
- IN=TRUE 时计数器累计 (不清零), 达到 PT 后 Q=TRUE
- IN=FALSE 时计数器保持当前值不变
- R=TRUE 时 Q=FALSE, ET=0, 计数器清零 (优先级高于 IN)

## 3. 调用约定 (强制)

### 3.1 三段式标准模式

所有 FB_TON / FB_TONR 调用必须遵循 **预赋值 → 全参数调用 → 读输出** 三段式:

```
Step 1: 预赋值    — fb_tXxx.IN := <条件>;  fb_tXxx.PT := <DINT值>;
Step 2: 全参数调用 — fb_tXxx(IN := fb_tXxx.IN, PT := fb_tXxx.PT, Q => fb_tXxx.Q, ET => fb_tXxx.ET);
Step 3: 读输出    — result := fb_tXxx.Q;  elapsed := fb_tXxx.ET;
```

**强制要求**:
- 🔴 调用时必须包含**所有参数** (IN/PT/Q/ET, TONR 还须包含 R), **Q 参数不能为空**
- 🔴 **禁止裸调用** `fb_tXxx()` — 即使已预赋值参数, 也必须显式列出完整参数
- 🔴 **禁止内联直接传值** — 不使用 `fb_tXxx(IN := TRUE, PT := 100, Q => result)` 将调用方变量直接传入

### 3.2 FB_TON 标准示例

```scl
// === 消抖定时器示例 (来自 FB_1011_CylinderControl) ===
fb_tDebounceExt.IN := i_bExtendedPos;          // Step 1: 预赋值
fb_tDebounceExt.PT := i_dDebounceMs;

fb_tDebounceExt(IN := fb_tDebounceExt.IN,      // Step 2: 全参数调用
                 PT := fb_tDebounceExt.PT,
                 Q => fb_tDebounceExt.Q,
                 ET => fb_tDebounceExt.ET);

s_bExtDebounced := fb_tDebounceExt.Q;           // Step 3: 读输出
s_dExtDebounceEt := fb_tDebounceExt.ET;
```

### 3.3 FB_TONR 标准示例

```scl
// === 超时定时器示例 (来自 FB_1011_CylinderControl) ===

// --- 启动计时 (命令处理逻辑中) ---
fb_tTimeout.IN := TRUE;                         // Step 1: 预赋值
fb_tTimeout.R := FALSE;
fb_tTimeout.PT := i_dTimeoutMs;

// --- 每周期无条件调用 (FB 顶部定时器批量调用区) ---
fb_tTimeout(IN := fb_tTimeout.IN,               // Step 2: 全参数调用
             R := fb_tTimeout.R,
             PT := fb_tTimeout.PT,
             Q => fb_tTimeout.Q,
             ET => fb_tTimeout.ET);

// --- 超时检测 ---
IF fb_tTimeout.Q THEN                            // Step 3: 读输出
    q_bTimeout := TRUE;
END_IF;

// --- 到位后复位 (命令处理逻辑中) ---
fb_tTimeout.IN := FALSE;
fb_tTimeout.R := TRUE;
```

### 3.4 定时器批量无条件调用模式 (V2.1.0 新增)

所有定时器 FB 实例必须在 FB 顶部**无条件、批量**调用，不可放在 IF/ELSIF/ELSE/CASE 等条件分支内。

**强制要求**:
- 🔴 所有 `FB_TON` / `FB_TONR` 的 `()` 调用集中在 FB 顶部一个连续的"定时器批量调用区"
- 🔴 该区域**不能**被任何 IF 块包裹 —— 每周期必须执行全部定时器调用
- 🔴 定时器调用与业务逻辑解耦: 调用归调用, 参数归参数, 读值归读值
- 🟡 定时器调用区建议放在 VAR 声明之后、业务逻辑之前

**原理**:
```
FB 实例的 .Q / .ET 仅在 () 调用执行时更新。
若某周期因 IF 条件为 FALSE 而跳过调用,
.Q 保留上一周期的僵尸值, 后续代码可能读到过期状态。
```

**FB_1011_CylinderControl 示范 (3个定时器无条件批量调用)**:

```scl
FUNCTION_BLOCK FB_1011_CylinderControl
...
VAR
    fb_tDebounceExt  : FB_TON;       // ExtendedPos 消抖
    fb_tDebounceRet  : FB_TON;       // RetractedPos 消抖
    fb_tTimeout      : FB_TONR;      // 超时
    ...
END_VAR

(* ==================== 定时器批量调用 (无条件, 每周期执行) ==================== *)
fb_tDebounceExt(IN := fb_tDebounceExt.IN, PT := fb_tDebounceExt.PT,
                 Q => fb_tDebounceExt.Q, ET => fb_tDebounceExt.ET);

fb_tDebounceRet(IN := fb_tDebounceRet.IN, PT := fb_tDebounceRet.PT,
                 Q => fb_tDebounceRet.Q, ET => fb_tDebounceRet.ET);

fb_tTimeout(IN := fb_tTimeout.IN, R := fb_tTimeout.R, PT := fb_tTimeout.PT,
             Q => fb_tTimeout.Q, ET => fb_tTimeout.ET);

(* ==================== 以下业务逻辑: 只设 IN/PT/R, 只读 Q/ET ==================== *)
IF i_dDebounceMs > 0 THEN
    fb_tDebounceExt.IN := i_bExtendedPos;       // ★ 设参数, 不调用
    fb_tDebounceExt.PT := i_dDebounceMs;
    s_bExtDebounced := fb_tDebounceExt.Q;       // ★ 读输出
    ...
END_IF;
```

## 4. 常见错误

| 编号 | 错误写法 | 正确写法 | 后果 |
|------|----------|----------|------|
| ❌ E1 | `fb_tXxx(IN := TRUE, PT := 100, Q => result)` | 预赋值 `.IN` / `.PT` 后 `fb_tXxx(IN := fb_tXxx.IN, ...)` | 与 Siemens `#IN` 语义冲突 |
| ❌ E2 | `fb_tXxx()` 裸调用 | 带完整参数 `(IN := ..., PT := ..., Q => ..., ET => ...)` | 违反本规范 §3.1 |
| ❌ E3 | `PT : INT` / `ET : INT` | `PT : DINT` / `ET : DINT` | 类型不匹配, FB 接口为 DINT |
| ❌ E4 | `PT := T#500ms` | `PT := 500` (DINT 直接赋值) | TIME 类型不被 LSP 支持 |
| ❌ E5 | `INT_TO_DINT(i_iTimeoutMs)` 类型转换 | 变量声明为 DINT 直接赋值 | 多余转换, 增加编译开销 |
| ❌ E6 | 定时器实例为数组元素 `fb_tTimers[0]()` | 每个定时器用独立 FB 实例 `fb_tTimer0 : FB_TON` | 数组索引调用不稳定 |
| ❌ E7 | 定时器 `()` 调用放在 IF/ELSIF/CASE 分支内 | 所有定时器 `()` 调用集中在 FB 顶部无条件调用区 | 条件 FALSE 时跳过调用, `.Q`/`.ET` 保留僵尸值 |

## 5. 调用点位置约定 (V2.1.0 修订)

| 定时器类型 | 预赋值位置 | `()` 调用位置 | 原因 |
|-----------|-----------|--------------|------|
| FB_TON (消抖/延时等) | 业务逻辑中 | **FB 顶部无条件批量调用区** | FB 实例每周期必须执行; 跳过调用导致僵尸 `.Q`/`.ET` |
| FB_TONR (超时/累计等) | 命令处理逻辑中 (多处) | **FB 顶部无条件批量调用区** | 同上; 无条件调用确保 `R` 复位优先级正确 |

**禁止**:
- 🔴 定时器 `()` 调用放在 `IF` / `ELSIF` / `ELSE` / `CASE` 等条件分支内
- 🔴 定时器 `()` 调用散落在 FB 各处 —— 必须集中在顶部一个区域

## 6. 检查清单 (Code Review)

调用 FB_TON / FB_TONR 时逐条检查:

- [ ] PT / ET 相关变量声明为 `DINT`, 不是 `INT`
- [ ] 变量前缀与类型匹配 (`d` = DINT, 不是 `i` = INT)
- [ ] 调用包含完整参数: IN / PT / Q / ET (+ R for TONR)
- [ ] 不使用 `INT_TO_DINT()` 类型转换 (直接 DINT 赋值)
- [ ] 不使用 TIME 字面量 (`T#...`)
- [ ] 不使用裸调用 `fb_tXxx()`
- [ ] 不使用内联直接传值 `fb_tXxx(IN := TRUE, ...)`
- [ ] 定时器 `()` 调用集中在 FB 顶部无条件区域, 不在 IF/ELSIF/CASE 分支内
