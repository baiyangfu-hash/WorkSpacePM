# 定时器使用规范 — TIA 原生 IEC 定时器（多重实例）

> 版本：V3.0.0
> 状态：待 TIA 实机编译确认（见 §7）
> 更新日期：2026-11-05
> 适用范围：目标平台为西门子 TIA Portal（S7-1200 / S7-1500，当前 V19）的 SCL 程序。汇川 InoProShop 等 CODESYS 系平台的定时器类型名是 `TON` / `TOF` / `TP`，不在本规范范围内，由项目方案文档另行写明。

---

## 1. 定位与变更说明

### 1.1 为什么改（V3.0.0，Breaking）

V2.x 规定定时器统一用 SysLib 的 `FB_TON` / `FB_TONR` 包装块，三段式调用。2026-11-04 用户把 011 的 FB 用“外部源文件 → 从源生成块”导入 TIA Portal V19，TIA 报 `FB_TON` 类型不存在：公共库只在仓库里，TIA 工程里没有。包装块一层套一层，既让导入变难，也让接口和 TIA 的定时器对不上（毫秒 DINT 对 TIME）。

结论：**不再自写定时器包装。** 定时器、边沿、计数直接用 TIA 系统指令的多重实例，导入后 TIA 里无需任何库。可用类型和参数签名见 LSP-905 §4.9（TIA 系统指令白名单）。

### 1.2 与 V2.x 的对照

| 项 | V2.x（已废弃） | V3.0.0 |
|----|----------------|--------|
| 类型 | SysLib `FB_TON` / `FB_TONR` | TIA 原生 `TON_TIME` / `TOF_TIME` / `TP_TIME` / `TONR_TIME` |
| PT / ET 类型 | DINT（毫秒） | **TIME** |
| 毫秒变量怎么传 | 直接赋值 | `DINT_TO_TIME(#dXxxMs)` |
| 读已用时间为毫秒 | 直接读 | `TIME_TO_DINT(#fb_tXxx.ET)` |
| 调用方式 | 先赋 `.IN` / `.PT`，再 `fb(IN := fb.IN, … Q => fb.Q …)` 三段式 | 每周期一次全参数调用，之后读 `.Q` / `.ET` |
| 库依赖 | `.plc.json` 引用 SysLib | 无 |

## 2. 类型与参数

| 类型 | 输入 | 输出 | 说明 |
|------|------|------|------|
| `TON_TIME` | `IN` BOOL，`PT` TIME | `Q` BOOL，`ET` TIME | 接通延时：IN 为 TRUE 持续 PT 后 Q 为 TRUE；IN 为 FALSE 时 Q、ET 复位 |
| `TOF_TIME` | `IN` BOOL，`PT` TIME | `Q` BOOL，`ET` TIME | 断开延时 |
| `TP_TIME` | `IN` BOOL，`PT` TIME | `Q` BOOL，`ET` TIME | 脉冲 |
| `TONR_TIME` | `IN` BOOL，`R` BOOL，`PT` TIME | `Q` BOOL，`ET` TIME | 保持型接通延时：IN 断开时 ET 保持，`R` 为 TRUE 时清零（优先于 IN） |

在 FB 的静态区（`VAR`）声明，每个定时器一个独立实例（多重实例，不使用单独的 `IEC_Timer_0_DB` 全局数据块）：

```scl
VAR
    fb_tSyncWindow : TON_TIME;   // 同步窗口定时器 (TIA 原生 IEC 定时器, 多重实例)
    fb_tTimeout    : TONR_TIME;  // 超时累计定时器
END_VAR
```

## 3. 调用约定（强制）

### 3.1 全参数调用，之后读输出

每个周期对每个定时器**调用一次**，列出全部输入参数，之后读 `.Q` / `.ET`：

```scl
// 调用: IN 是条件, PT 是 TIME; 毫秒变量用 DINT_TO_TIME 转换
#fb_tSyncWindow(IN := s_bAnyPressed AND (s_iStep = 10),
                PT := DINT_TO_TIME(#i_dSyncWindowMs));

// 读输出
IF #fb_tSyncWindow.Q THEN
    o_bSyncFault := TRUE;
END_IF;

// 已用时间要毫秒时
s_dElapsedMs := TIME_TO_DINT(#fb_tSyncWindow.ET);
```

`TONR_TIME` 多一个 `R` 参数：

```scl
#fb_tTimeout(IN := s_bRunning, R := s_bTimeoutReset, PT := DINT_TO_TIME(#i_dTimeoutMs));
```

强制要求：
- 🔴 调用必须列出全部输入参数（`IN`、`PT`，`TONR_TIME` 还有 `R`）；不得裸调用 `#fb_tXxx();`
- 🔴 不得先单独赋值 `#fb_tXxx.IN := …`、`#fb_tXxx.PT := …` 再隐式调用；条件和时间都写在调用的参数里
- 🔴 不得把输出写回自己的成员（如 `Q => #fb_tXxx.Q`）；输出只读 `.Q` / `.ET`
- 🔴 PT 必须是 TIME：毫秒值用 `DINT_TO_TIME(...)` 转换，不得把 DINT / INT 直接赋给 TIME；常量时间统一也写 `DINT_TO_TIME(500)`，目前不写 `T#500ms` 字面量（驾驶舱 `plc check` 规则 LSP-906-TIMER-TIME-LITERAL 仍拦截，规则放开前保持一致）
- 🔴 变量名前缀按 LSP-905 §3.1，定时器实例用 `fb_t` 前缀

### 3.2 无条件调用

每个定时器的调用写在 FB 顶部的“定时器调用区”，不放在 IF / ELSIF / ELSE / CASE 分支里。原因：`.Q` / `.ET` 只在调用执行的那个周期更新，跳过调用会留下上一周期的旧值，后面的逻辑读到过期状态。

- 🔴 定时器调用集中在 FB 顶部一个连续区域，不被任何条件包裹
- 🟡 调用区放在 VAR 声明之后、业务逻辑之前
- 🔴 一个定时器一个实例，不用数组元素当定时器实例（`fb_tTimers[0](…)`）

```scl
// ==== 定时器调用区（无条件, 每周期一次）====
#fb_tDebounceExt(IN := i_bExtendedPos, PT := DINT_TO_TIME(#i_dDebounceMs));
#fb_tDebounceRet(IN := i_bRetractedPos, PT := DINT_TO_TIME(#i_dDebounceMs));
#fb_tTimeout(IN := s_bBusy, R := s_bTimeoutReset, PT := DINT_TO_TIME(#i_dTimeoutMs));

// ==== 以下业务逻辑: 只读 .Q / .ET ====
IF i_dDebounceMs > 0 THEN
    s_bExtDebounced := #fb_tDebounceExt.Q;
END_IF;
```

## 4. 常见错误

| 编号 | 错误写法 | 正确写法 | 后果 |
|------|----------|----------|------|
| ❌ E1 | `fb_tXxx : FB_TON;` 自写包装类型 | `fb_tXxx : TON_TIME;` | 导入 TIA 时类型不存在 |
| ❌ E2 | `#fb_tXxx();` 裸调用 | 全参数调用 `#fb_tXxx(IN := …, PT := …);` | 参数没有传入，计时不对 |
| ❌ E3 | `#fb_tXxx.IN := …;` 单独赋值再隐式调用 | 条件和时间写进调用参数 | 与 TIA 的多重实例调用方式不符，改动难审查 |
| ❌ E4 | `PT := #i_dMs`（DINT 直接给 TIME） | `PT := DINT_TO_TIME(#i_dMs)` | 类型不匹配，编译错误 |
| ❌ E5 | `s_dEt := #fb_tXxx.ET`（TIME 直接给 DINT） | `s_dEt := TIME_TO_DINT(#fb_tXxx.ET)` | 类型不匹配，编译错误 |
| ❌ E6 | 数组元素当定时器实例 | 每个定时器独立实例 | 数组索引调用不稳定 |
| ❌ E7 | 调用放在 IF / ELSIF / CASE 分支内 | 调用集中在 FB 顶部无条件区 | 条件为 FALSE 时跳过调用，`.Q` / `.ET` 保留旧值 |
| ❌ E8 | `"IEC_Timer_0_DB".TON(…)` 单实例全局 DB | FB 静态区多重实例 | 每个 FB 实例共用一个 DB，复制块、多实例时互相干扰 |

## 5. 旧项目迁移

| 旧写法 | 新写法 |
|--------|--------|
| `FB_TON` | `TON_TIME` |
| `FB_TONR` | `TONR_TIME` |
| `FB_TOF` | `TOF_TIME` |
| `FB_TP` | `TP_TIME` |
| `PT := 500`（毫秒 DINT） | `PT := DINT_TO_TIME(500)` |
| `ET`（DINT 毫秒） | `TIME_TO_DINT(#fb_tXxx.ET)` |
| 三段式预赋值 | 并入调用参数 |

SysLib 的 `FB_TON` / `FB_TONR` / `FB_TOF` / `FB_TP` 在所有项目迁移完成前保留；新写的程序不得再引用。迁移卡单独立，每个项目的改动按 LSP-905 §4.10 走 TIA 编译验证。

## 6. 检查清单（Code Review）

- [ ] 定时器用 `TON_TIME` / `TOF_TIME` / `TP_TIME` / `TONR_TIME` 声明为 FB 静态区的多重实例，没有 `FB_TON` 一类自写类型
- [ ] 每个定时器每周期调用一次，列出全部输入参数，没有裸调用
- [ ] 没有单独给 `.IN` / `.PT` 赋值再隐式调用，输出只读不写
- [ ] `PT` 是 TIME：毫秒用 `DINT_TO_TIME(...)`，已用时间要毫秒用 `TIME_TO_DINT(...)`
- [ ] 调用集中在 FB 顶部无条件区，不在 IF / ELSIF / CASE 分支内
- [ ] 没有数组元素当定时器实例，没有 `IEC_Timer_x_DB` 单实例全局 DB
- [ ] 项目 `.plc.json` 没有因为定时器引用 SysLib
