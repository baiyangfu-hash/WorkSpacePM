### 4.4 软件分层架构 (DEV-V2.0 新增)

#### 4.4.1 三层解耦架构模型

```
┌─────────────────────────────────────────────────────────────┐
│                   第1层: 主控调度层 (PRG_Main)               │
│  ┌───────────────────┬──────────────────────────────────┐   │
│  │ Region_800_输入分发 │      Region_900_输出收集         │   │
│  │  (物理IO → 逻辑变量) │    (逻辑变量 → 物理IO)          │   │
│  └───────────────────┴──────────────────────────────────┘   │
│  ┌───────────────────────────────────────────────────────┐  │
│  │ Region_500_主程序逻辑 (使能/初始化/模式分发/状态汇总) │  │
│  └───────────────────────────────────────────────────────┘  │
├─────────────────────────────────────────────────────────────┤
│                   第2层: 业务功能块层 (FB_xxx)               │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐     │
│  │FB_EquipA │ │FB_EquipB │ │FB_Process│ │FB_AxisCtrl│     │
│  │(纯逻辑)  │ │(纯逻辑)  │ │(工艺流程)│ │(运动控制) │     │
│  └──────────┘ └──────────┘ └──────────┘ └──────────┘     │
│  ★ 核心约束: 禁止引用任何 X/Y/M/D 物理地址                │
├─────────────────────────────────────────────────────────────┤
│                   第3层: 基础服务层 (FB_Service)              │
│  ┌────────────┐ ┌────────────┐ ┌────────────┐            │
│  │FB_AlarmMgr │ │FB_CommMgr  │ │FB_ModeMgr  │            │
│  │(报警管理)  │ │(通信管理)  │ │(模式管理)  │            │
│  └────────────┘ └────────────┘ └────────────┘            │
└─────────────────────────────────────────────────────────────┘
```

#### 4.4.2 架构设计原则

| 原则 | 描述 | 强制性 | 违反后果 |
|-----|------|:-----:|---------|
| **IO解耦** | FB禁止直接引用X/Y/M/D物理地址，所有IO通过PRG映射传入 | **必须** | 无法独立测试、无法复用 |
| **单一职责** | 每个FB只负责一个独立的设备或功能单元 | **必须** | 维护困难、耦合度高 |
| **接口清晰** | 输入参数用`i_`前缀，输出参数用`o_`前缀，内部变量用`s_`前缀 | **必须** | 可读性差 |
| **数据隔离** | 静态变量`s_`仅用于FB内部状态保持，不暴露给外部 | 推荐 | 状态污染风险 |

|---------|-----------|---------|------|----------|---------|-----------|---------|------|
| I0.0 | `i_bEmergencyStop` | BOOL | PRG→FB | 全局 | 常闭 NC | 急停已按下 | 按失效默认态处理并报警 | 安全回路 |
| I0.1 | `i_bStartButton` | BOOL | PRG→FB | HMI操作 | 常开 NO | 不动作 | 按失效默认态处理 | — |
| Q0.0 | `o_bMotorRun` | BOOL | FB→PRG | 执行器输出 | — | 停止 | 停机并输出报警 | 启动同步检测运行反馈 |
| [地址] | [变量名] | [类型] | [方向] | [目标FB] | [NO/NC/—] | [安全侧状态] | [处置动作] | [说明] |

### 5.4 标准程序执行流程 (DEV-V2.0 新增)

#### 5.4.1 PRG_Main 标准扫描周期

```
PRG_Main 每次扫描的标准执行顺序:
│
├─ [Step 1] 使能与安全检查
│   IF NOT i_SystemEnable THEN
│       全部输出归零 → RETURN (退出本次扫描)
│   END_IF
│
├─ [Step 2] 初始化流程 (首次使能或复位后)
│   IF NOT bInitComplete THEN
│       执行初始化: 气缸复位 → 伺服使能 → 状态清零
│       检查初始化条件满足 → bInitComplete := TRUE
│       RETURN (初始化期间不执行业务逻辑)
│   END_IF
│
├─ [Step 3] 故障预检 (最高优先级)
│   急停检查 → 安全门检查 → 伺服故障检测 → 传感器冲突检测
│   如发现新故障 → 设置报警码 → 进入安全状态
│
├─ [Step 4] 模式分发
│   CASE OperationMode OF
│       Auto:  → 调用各FB的自动模式逻辑
│       Manual: → 调用各FB的手动模式逻辑
│       ELSE:  → 无效模式, 全部输出归零
│   END_CASE
│
├─ [Step 5] 停止与复位处理
│   IF i_Stop THEN → 停止运行, 保持当前位置
│   IF i_Reset AND 有故障 → 清除报警, 重新初始化
│
├─ [Step 6] 状态输出汇总
│   o_Running := 各FB运行状态 OR 运算
│   o_Error := 各FB故障状态 OR 运算
│   o_AlarmCode := 最高优先级活跃报警码
│
└─ [Step 7] 结束扫描 (PLC自动刷新IO)
```

#### 5.4.2 FB内部标准执行顺序

```
FB_xxx 内部每次调用的标准执行顺序:
│
├─ [Region 100-400] 变量声明区 (编译时确定, 运行时不执行)
│
├─ [Region 500] 使能判断
│   IF NOT i_Enable THEN
│       清零所有o_输出 → RETURN
│   END_IF
│
├─ 初始化判断 (如需要)
│   IF NOT s_bInitDone THEN
│       执行初始化动作
│       RETURN
│   END_IF
│
├─ 故障自检 / 预处理
│   (传感器冲突检测、超时保护等)
│
├─ 模式分支
│   IF i_AutoMode THEN
│       ├─ [Region 600] CASE自动状态机
│       └─ (各步骤的进入条件/动作/退出条件/超时保护)
│   ELSIF i_ManualMode THEN
│       └─ [Region 700] 手动控制逻辑
│       (互锁保护 + 点动控制 + 气缸手动)
│   ELSE
│       无效模式 → 全部输出归零
│   END_IF
│
└─ 输出赋值 (汇总所有o_xxx输出变量)
```

### 6.5 IEC 61131-3 ST语言编程规范 (DEV-V2.0 新增)

#### 6.5.1 语言选择原则

| 场景 | 推荐语言 | 理由 |
|-----|---------|------|
| 复杂状态机/算法 | **ST** | CASE结构清晰，易维护 |
| 简单互锁逻辑 | LD | 直观易懂 |
| 运动控制 | **ST + FB调用** | 参数传递方便 |
| 数据运算 | **ST** | 表达能力强 |

#### 6.5.2 METHOD子程序使用规范

**适用场景**: FB内部功能复用超过2次时抽取为METHOD

**命名规则**: `METH_` + 动作名称，如 `METH_CheckSensor`, `AutoModeStateMachine`

**访问权限**: METHOD可访问FB的所有局部变量和静态变量

**示例**:

```st
METHOD AutoModeStateMachine : VOID
(* ================================================================= *)
(* 自动模式状态机: 11步完整取放料循环                              *)
(* ================================================================= *)
CASE s_iStep OF
    STP_IDLE:
        (* 待机等待启动信号 *)
        IF s_bStartTrigger AND NOT s_bFault THEN
            s_iStep := STP_WAIT_PLACE_DONE;
            s_bRunning := TRUE;
            s_iCompletedLayers := 0;
            s_iPickCount := 1;
            s_iCurrentPickLayer := 1;
        END_IF;

    STP_WAIT_PLACE_DONE:
        (* 等待上游输送机放料完成 *)
        (* ... 步骤逻辑 ... *)

    STP_PICK_DOWN:
        (* Z轴下降到取料高度 *)
        s_bZAxisReqDown := TRUE;
        fb_tActionTimer.IN := TRUE;
        fb_tActionTimer.PT := 5000;
        fb_tActionTimer(IN := fb_tActionTimer.IN,
                         PT := fb_tActionTimer.PT,
                         Q => fb_tActionTimer.Q,
                         ET => fb_tActionTimer.ET);
        IF fb_tActionTimer.Q OR i_bZAxisDownPos THEN
            s_bZAxisReqDown := FALSE;
            fb_tActionTimer.IN := FALSE;
            s_iStep := STP_CLAMP;
        END_IF;

    ELSE
        (* 非法状态 → 回到空闲 *)
        s_iStep := STP_IDLE;
        s_bFault := TRUE;
END_CASE
END_METHOD
```

#### 6.5.3 CASE状态机编写规范

| 规范项 | 要求 | 说明 |
|-------|------|------|
| 状态类型 | 必须使用常量或枚举 | 禁止硬编码数字(如CASE 1 OF) |
| 进入条件 | 每个状态必须有明确的进入条件 | 从上一个状态的退出动作触发 |
| 退出条件 | 每个状态必须有退出条件或超时保护 | 防止死锁 |
| ELSE分支 | **必须存在** | 处理非法状态，通常回到初始态 |
| 单入口原则 | 状态转换只能有一个入口 | 保证状态一致性 |
