# PLC 编程错误预防规则

> 版本: V3.0.0
> 状态: 待 TIA 实机编译确认（§1、§6、§7 为 2026-11-04 TIA V19 导入实测后新增或改写）
> 更新日期: 2026-11-05
> 来源: DJ-2026-005 项目实战经验；DJ-2026-011 TIA V19 导入实测

## 1. 定时器使用错误预防（TIA 原生 TON_TIME 等，详见 903）

> V3.0.0 起不再使用 SysLib 的 `FB_TON` / `FB_TONR`（TIA 里没有这些类型，导入会报类型不存在）。定时器直接用 TIA 原生多重实例。

### 规则 1.1: 定时器类型必须是 TIA 原生类型
- 只允许 `TON_TIME` / `TOF_TIME` / `TP_TIME` / `TONR_TIME`，在 FB 静态区声明，一个定时器一个实例
- 禁止 `FB_TON` / `FB_TONR` / `FB_TOF` / `FB_TP` 一类自写包装；禁止单实例全局 DB（如 `"IEC_Timer_0_DB".TON(…)`）

错误示例:
```scl
fb_tSyncWindow : FB_TON;
```

正确示例:
```scl
fb_tSyncWindow : TON_TIME;
```

### 规则 1.2: PT / ET 是 TIME，毫秒值要转换
- `PT := DINT_TO_TIME(#i_dSyncWindowMs)`；要毫秒的已用时间用 `TIME_TO_DINT(#fb_tXxx.ET)`
- 禁止把 DINT / INT 直接赋给 TIME，禁止把 TIME 直接赋给 DINT
- 常量时间统一写 `DINT_TO_TIME(500)`；`T#500ms` 字面量目前仍被驾驶舱 `plc check`（LSP-906-TIMER-TIME-LITERAL）拦截，规则放开前保持一致

错误示例:
```scl
#fb_tSyncWindow(IN := bCond, PT := #i_dSyncWindowMs);      // DINT 给 TIME
s_dEt := #fb_tSyncWindow.ET;                                 // TIME 给 DINT
```

正确示例:
```scl
#fb_tSyncWindow(IN := bCond, PT := DINT_TO_TIME(#i_dSyncWindowMs));
s_dEt := TIME_TO_DINT(#fb_tSyncWindow.ET);
```

### 规则 1.3: 全参数调用，不拆成预赋值再隐式调用
- 每周期调用一次，`IN`、`PT`（`TONR_TIME` 还有 `R`）全部写在调用里
- 禁止裸调用 `#fb_tXxx();`；禁止先 `#fb_tXxx.IN := …`、`#fb_tXxx.PT := …` 再隐式调用；禁止把输出写回自己的成员（`Q => #fb_tXxx.Q`）

错误示例:
```scl
#fb_tActionTimer.IN := TRUE;
#fb_tActionTimer.PT := T#500ms;
#fb_tActionTimer(IN := #fb_tActionTimer.IN, PT := #fb_tActionTimer.PT,
                 Q => #fb_tActionTimer.Q, ET => #fb_tActionTimer.ET);
```

正确示例:
```scl
#fb_tActionTimer(IN := TRUE, PT := DINT_TO_TIME(500));
s_bActionDone := #fb_tActionTimer.Q;
```

### 规则 1.4: 复位与保持
- `TONR_TIME` 的 `R` 为 TRUE 时清零并复位 `Q`，优先于 `IN`
- 需要“停止并清零”的普通定时器，把 `IN` 置为 FALSE 即可（`Q`、`ET` 复位），不要另写清零逻辑

### 规则 1.5: 定时器必须在 FB 顶部无条件调用
- 所有定时器调用集中在 FB 顶部一个连续区域，不被任何 IF / ELSIF / ELSE / CASE 包裹，每周期都执行
- 调用归调用，读值归读值

错误示例:
```scl
IF i_bStart THEN
    #fb_tActionTimer(IN := TRUE, PT := DINT_TO_TIME(500));   // 放在 IF 里
END_IF;
```

正确示例:
```scl
// ==== 定时器调用区（无条件）====
#fb_tDebounceExt(IN := i_bSensor, PT := DINT_TO_TIME(#i_dDebounceMs));
#fb_tTimeout(IN := s_bBusy, R := s_bTimeoutReset, PT := DINT_TO_TIME(#i_dTimeoutMs));

// ==== 业务逻辑: 只读 .Q / .ET ====
IF i_bStart THEN
    s_bDebounced := #fb_tDebounceExt.Q;
END_IF;
```

## 2. 自动生成文件保护

### 规则 2.1: 禁止修改 .plc-out 目录下的自动生成文件
- `.plc-out/golang/` 目录下的所有 Go 文件是由 Siemens LSP 插件自动生成的
- 修改这些文件无法解决根本问题, 下次编译会被覆盖
- 测试失败或运行时错误应从 SCL 源码层面解决

错误做法:
- 直接修改 `.plc-out/golang/builtins/b_fb_ton.go` 来实现 TON 定时器
- 修改 `.plc-out/golang/builtins/stub_support.go` 来跳过 stub 错误

正确做法:
- 检查 SCL 源码中的定时器调用是否符合 TIA 原生 `TON_TIME` 等的参数写法（见 LSP-903 V3.0.0）
- 检查 .plc.json 是否正确配置了 libraries
- 确保用到的类型要么在 TIA 系统指令白名单内（§6），要么在仓库里有定义并随项目导入 TIA

## 3. 项目配置检查

### 规则 3.1: .plc.json 必须配置 libraries
- 如果项目使用了 SysLib 共享库中的自有功能块(如 FB_1030_SafetyManager；定时器、边沿、计数不再使用 SysLib 的包装块，见 903 与 LSP-905 §4.9), 必须在 .plc.json 中配置 libraries
- libraries 使用相对于项目根目录的相对路径
- **注意: 字段名必须为 `libraries`, 不是 `libraryDirectories`(后者不是 Siemens LSP 的有效字段, 详见 907 §1.2)**

错误示例:
```json
{
  "name": "DJ-2026-005",
  "description": "边框缓存机 PLC 控制系统",
  "version": "V5.0.0"
}
```

正确示例:
```json
{
  "name": "DJ-2026-005",
  "description": "边框缓存机 PLC 控制系统",
  "version": "V5.0.0",
  "libraries": [
    "../01_SharedLibraries/SysLib"
  ]
}
```

## 4. METHOD 语法禁用

### 规则 4.1: 禁止使用 METHOD / METHODS / END_METHOD
- Siemens LSP 与本工作空间白名单均不支持 METHOD 语法
- 旧模板中出现的 `CALL_XXX`、`METHODS`、`END_METHODS` 均视为历史残留, 必须删除
- 需要拆分逻辑时:
  - 单个 FB 内的步序与模式分支 → 保留在 FB 主体 `CASE/IF` 中
  - 纯计算或无状态复用逻辑 → 提取为独立 `FC`
  - 带静态状态的子设备逻辑 → 提取为独立 `FB`

错误示例:
```scl
METHOD AutoModeStateMachine : VOID
    // ...
END_METHOD
```

正确示例:
```scl
CASE s_iStep OF
    0:
        // 初始化
    10:
        // 自动模式步序
ELSE
    s_iStep := 0;
END_CASE;
```

## 5. 类型转换限制

### 规则 5.1: 禁止 INT / DINT 与 TIME 直接互相赋值
- SCL 不做 INT / DINT ↔ TIME 的隐式转换，必须用转换函数：`DINT_TO_TIME(...)`、`TIME_TO_DINT(...)`（见 LSP-905 §4.9）
- 毫秒数量继续用 DINT 变量保存和传递，进入定时器的那一刻转成 TIME

错误示例:
```scl
tElapsed := iCounter;                     // INT → TIME 隐式转换, 编译错误
#fb_tTimer(IN := bCond, PT := diTimeMs);  // DINT 直接给 TIME, 编译错误
```

正确示例:
```scl
#fb_tTimer(IN := bCond, PT := DINT_TO_TIME(diTimeMs));
diElapsedMs := TIME_TO_DINT(#fb_tTimer.ET);
```

### 规则 5.2: 常量时间的写法
- 目前统一写 `DINT_TO_TIME(500)`，不写 `T#500ms` 字面量（原因同规则 1.2）

## 6. 类型与指令必须在白名单里

### 规则 6.1: 非白名单且仓库内无定义的类型、指令一律报错
- 允许使用的类型和指令有两类：① LSP-905 §4.9 列出的 TIA 系统指令（带参数签名）；② 本仓库里有源码定义的块、UDT（如项目自己的 FB、SysLib 的自有块）
- 其余一概不许用：包括自己想象出来的“标准库”类型名、其他平台才有的类型、TIA 里没有的函数
- 生成代码和检查都以白名单为准；新增一条白名单项要更新 LSP-905 §4.9，并写明参数签名和是否已在 TIA 实机确认

错误示例:
```scl
fb_tSync  : FB_TON;       // 仓库没有定义, TIA 也没有
fb_rTrig  : FB_R_TRIG;    // 同上
```

正确示例:
```scl
fb_tSync  : TON_TIME;     // 白名单: TIA 系统指令
fb_rTrig  : R_TRIG;       // 白名单: TIA 系统指令, 引脚是 CLK
```

## 7. 交付给 TIA 的文件

### 规则 7.1: 导入 TIA 的 .scl 必须是 UTF-8 带 BOM
- TIA 的“外部源文件 → 从源生成块”按系统 ANSI 编码读取，没有 BOM 的 UTF-8 文件里的中文注释会变成乱码（2026-11-04 实测）
- 交付给 TIA 的 `.scl`（块、数据块、OB）一律存成 **UTF-8 带 BOM**；同一个项目里不得混放带 BOM 和不带 BOM 的 `.scl`
- 仓库 CI（`reviews/tools/plc_ci.py`，随 DJ-2026-011 入库卡合并生效）检查：项目里已有带 BOM 的 `.scl` 时，没有 BOM 的 `.scl` 判新增失败。`.scltest` 只给 LSP 用，不进 TIA，不要求 BOM

### 规则 7.2: LSP 通过不等于可交付
- 本机 Siemens LSP 的 `check` 只查语法和类型，不能代替 TIA 编译
- PLC 卡的验收必须有 TIA 实机编译 0 错误（见 LSP-905 §4.10）

### 规则 7.3: 全局 DB 里不能放 FB 实例
- 全局 `DATA_BLOCK` 的 `VAR` 里不得出现 `fb_xxx : FB_某某;` 这类 FB 类型成员（TIA 不支持，DB 生成失败，调用处连环报“函数块调用无效 / 形参无效 / 操作数未定义”，2026-11-05 实测）
- FB 实例放进调用方 FB 的 `VAR`（多重实例），或用该 FB 的背景 DB（`DATA_BLOCK "DB_X"` 换行 `"FB_X"`）。测试外壳写法见 LSP-905 §4.11

### 规则 7.4: 程序循环 OB 编号
- agent 写的 OB 编号只能用 100 以上（用户 2026-11-05 规定；S7-1200 程序循环 OB 实际取 123 起），绝不用 OB1 或用户已有的编号；测试用 OB 默认 OB123，块名不用 `Main`（LSP-905 §4.11）。驾驶舱导出检查：编号低于 100 的 OB 直接拦截

### 规则 7.5: 不得覆盖用户的块
- 导入源文件里禁止 OB1、块名 `Main` 等常见用户块名；块名带项目标记（`DJ<项目号>` 或 `DJ` 前缀）；导入步骤第一条写“导入前先备份项目”（LSP-905 §4.11）。2026-11-05 事故：旧 `OB1.scl`（块名 Main、无 BOM）导入后覆盖了用户模板里的 `Main [OB1]` 并变乱码

## 8. 代码修改前检查清单

在修改任何 PLC SCL 代码之前, 必须逐项检查:

- [ ] 是否已阅读 903_定时器使用规范（V3.0.0）?
- [ ] 定时器是否用 TIA 原生 `TON_TIME` / `TOF_TIME` / `TP_TIME` / `TONR_TIME`（不是 `FB_TON` 一类自写包装）?
- [ ] PT 是否用 `DINT_TO_TIME(...)` 转成 TIME，已用时间要毫秒是否用 `TIME_TO_DINT(...)`?
- [ ] 定时器是否全参数调用、没有拆成预赋值再隐式调用?
- [ ] 定时器 `()` 调用是否集中在 FB 顶部无条件区?
- [ ] 用到的类型和指令是否都在 LSP-905 §4.9 白名单里，或本仓库有源码定义?
- [ ] 交付给 TIA 的 `.scl` 是否是 UTF-8 带 BOM?
- [ ] 新写的 FB 编号是否落在 LSP-905 §3.4 的编号段内（执行器 1001–1099、通信 1100–1199、安全 1200–1299、工站 1300–1999、公共服务 2001–2999、外部通信 3001–3999、测试 9001–9999）？DB 是否跟随所属 FB 编号？OB 是否 ≥123?
- [ ] 块名有没有用 Main/OB1 等用户常用名、有没有带项目标记、导入步骤第一条是不是“先备份”?
- [ ] 全局 DB 里有没有 FB 实例成员（必须没有）? agent 写的 OB 编号是不是 ≥100（实际 ≥123）、块名没用 `Main`?
- [ ] 是否在修改 .plc-out 自动生成文件?(如果是, 立即停止)
- [ ] .plc.json 是否配置了 libraries(不是 libraryDirectories)?
- [ ] 是否出现 METHOD / METHODS / END_METHOD 残留?(如果是, 删除并改为 FB 主体或独立 FC/FB)
- [ ] 是否有 INT → TIME 的隐式转换?(如果有, 改用 DINT)
