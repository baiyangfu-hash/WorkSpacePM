# SCL 注释规范 (Siemens LSP Go-Gen 兼容版)

> 版本：V1.3.0
> 状态：已验证
> 更新日期：2026-05-29
> 适用环境：Siemens LSP (VS Code)、TIA Portal、CODESYS、GX Works

---

## 1. 核心规则总结

| 规则 | 状态 | 说明 |
|------|------|------|
| `//` 单行注释 | ✅ **推荐** | 安全可靠，所有平台兼容 |
| `(* *)` 多行注释 | ✅ **允许** | 完全支持，适合大段注释或头部说明 |
| **注释分工** | ✅ **强制** | 变量/行内用 `//`，逻辑/流程块用 `(* *)`，详见§2.0 |
| 嵌套注释 | ❌ **严格禁止** | `(* 外 (* 内 *) *)` 或任何形式的嵌套都会导致LSP解析错误 |
| **注释内容含标记** | ❌ **严格禁止** | 注释文本中不能包含 `(*` 或 `*)` 字符串，会导致提前结束注释 |
| 中文标点 | ❌ **禁止** | 必须使用英文标点符号（`,` `:` `.` `;`） |
| 中文内容 | ✅ **允许** | 注释文字可用中文，但标点必须英文 |

## 2. 注释格式规范

### 2.0 注释类型分工规则（强制）

**核心原则：变量/行内用 `//`，逻辑/流程块用 `(* *)`**

| 注释场景 | 使用格式 | 理由 |
|----------|----------|------|
| 变量行内注释 | `//` | 紧跟声明行，简洁不破坏代码结构 |
| I/O 参数说明 | `//` | 一行说清用途，与声明行一一对应 |
| 赋值语句注释 | `//` | 简短解释赋值原因，同行直接可见 |
| 功能块头部 | `(* *)` | 大段描述信息（名称/版本/项目/说明），格式规整 |
| 逻辑分支说明 | `(* *)` | IF/CASE 分支可多行展开，清晰描述流程意图 |
| 状态机步骤说明 | `(* *)` | 状态步序需多行关联性描述，换行可读性高 |
| 函数头部 | `//` | 简洁函数说明（3-5行），与下方代码紧凑衔接 |
| 临时/调试注释 | `//` | 快速标记，易增易删 |
| region 折叠标记 | `REGION 名称 ... END_REGION` | 固定模板格式（西门子博图 TIA V19 可直接用，也是 siemens-lsp 支持的写法） |

```scl
// ✅ 正确示范：变量用 //，逻辑用 (* *)
VAR_INPUT
    i_bStart : BOOL;   // 启动信号（上升沿有效）
    i_rSpeed : REAL;   // 速度设定值（mm/s）
END_VAR

// ✅ 函数头部用 //
// ConveyorStepSequence: 输送机步序编排
// 输入: i_bAutoMode, i_bManualCmd
// 输出: o_iCurrentStep

(* ✅ 状态机逻辑用 (* *)
   Step 10: 等待来料传感器触发
     - 条件: stSensor.bFwdLimit = TRUE
     - 动作: 启动输送电机正转, 进入Step 20
   Step 20: 输送中, 等待到位传感器
     - 条件: stSensor.bRevLimit = TRUE
     - 动作: 停止电机, 进入Step 30
*)

// ❌ 错误：变量注释用了 (* *) 块格式，过度冗长
(* 预设时间（扫描周期） *)
PT : DINT;

// ❌ 错误：大段逻辑用 // 逐行写，视觉碎片化
// Step 10: 等待来料传感器触发
//   - 条件: stSensor.bFwdLimit = TRUE
//   - 动作: 启动输送电机正转, 进入Step 20
// Step 20: 输送中, 等待到位传感器
//   - 条件: stSensor.bRevLimit = TRUE
//   - 动作: 停止电机, 进入Step 30
```

### 2.1 推荐格式：单行注释 `//`

```scl
(* ============================================================================
功能块名称: FB_TON
描述: 接通延时定时器 - 当IN为TRUE时，经过PT时间后Q变为TRUE
============================================================================ *)
FUNCTION_BLOCK FB_TON
VAR_INPUT
    IN  : BOOL;
    PT  : DINT;   // 预设时间(扫描周期)
END_VAR
VAR_OUTPUT
    Q   : BOOL;
    ET  : DINT;   // 已用时间(扫描周期)
END_VAR
VAR
    Counter   : DINT := 0;
    Running   : BOOL := FALSE;
END_VAR

BEGIN
    // IN为TRUE时启动定时器
    IF #IN THEN
        IF NOT #Running THEN
            #Running := TRUE;
            #Counter := 0;  // 复位计数器
        END_IF;

        // 计时逻辑
        IF #Running THEN
            #Counter := #Counter + 1;

            // 判断是否达到预设值
            IF #Counter >= #PT THEN
                #Q := TRUE;
                #ET := #PT;
                #Counter := #PT;  // 保持最大值
            ELSE
                #ET := #Counter;  // 输出当前值
            END_IF;
        END_IF;
    ELSE
        // IN为FALSE时复位
        #Q := FALSE;
        #ET := 0;
        #Counter := 0;
        #Running := FALSE;
    END_IF;

END_FUNCTION_BLOCK
```

### 2.2 允许格式：多行注释 `(* *)`

**✅ 完全支持，推荐用于功能块头部或大段说明**

```scl
(* ============================================================================
 功能块名称: FB_TON
 描述: 接通延时定时器 - 当IN为TRUE时，经过PT时间后Q变为TRUE
 版本: V2.0.0 (多平台兼容优化版)
 ============================================================================

 ----- 多平台兼容性说明 -----

 此功能块使用纯DINT计数方式, 避免TIME类型转换,
 确保与Siemens LSP (Go后端)、TIA Portal、GX Works、
 CODESYS以及所有其他平台的兼容性.
 ============================================================================ *)
```

### 2.3 ⚠️ 严格禁止的写法

#### 2.3.1 嵌套注释（任何形式）

```scl
(* ✅ 正确 - 单层多行注释
   内容...
*)

(* ❌ 错误1 - 嵌套多行注释
   (* 内层注释 *)          <- 这里的*)会提前结束外层注释!
   外层内容...            <- 这些变成"代码"执行!
*)

(* ❌ 错误2 - 其他嵌套形式
   (* 内含 (* *) *)
)
```

#### 2.3.2 注释内容包含标记字符串（⚠️ 高危）

```scl
(* ❌ 错误 - 注释文本中含有(*)或(*)
   ============================================================================
   变更记录:
     - 文件头格式统一为标准(* *)块注释格式   <- 这里的*)提前结束整个注释!
     - 注释风格统一: 段落分隔符改为(* ==== *)格式  <- 后续内容变成代码!
   ============================================================================
   上面的内容从第一个*)开始就被当作代码了!
*)  <- 这个*)变成未配对的语法错误
```

**问题原理：**
- LSP解析器从左到右扫描，遇到第一个 `*)` 就认为注释结束
- 后面的所有内容被当作SCL代码执行，导致编译错误

**正确写法：**
```scl
(* ✅ 正确 - 注释内容不含(*或*)
   ============================================================================
   变更记录:
     - 文件头格式统一为标准SCL块注释格式      <- 用文字描述代替
     - 注释风格统一: 段落分隔符改为等号线格式   <- 用文字描述代替
   ============================================================================
 *)
```

#### 2.3.3 连续并列块（不推荐）

```scl
(* ❌ 不推荐 - 两个连续的块容易混淆
   第一部分...
*)
(* 第二部分...    <- 虽然语法正确,但视觉上像嵌套
*)

(* ✅ 推荐 - 合并为单一完整块
   第一部分...
   
   第二部分...
 *)
```

## 3. 标点符号规范（关键）

### 3.1 禁止使用的中文标点

| 中文标点 | Unicode编码 | 问题 | 替换为 |
|----------|-------------|------|--------|
| `，` (逗号) | U+FF0C | LSP识别为非法token | `,` |
| `：` (冒号) | U+FF1A | LSP识别为非法token | `:` |
| `。` (句号) | U+3002 | LSP识别为非法token | `.` 或省略 |
| `；` (分号) | U+FF1B | LSP识别为非法token | `;` |
| `（）` (括号) | U+FF08/U+FF09 | 可能导致解析问题 | `()` |

### 3.2 正确示例对比

```scl
// ❌ 错误 - 使用中文标点
// 描述: 接通延时定时器，当IN为TRUE时，经过PT时间后Q变为TRUE。

// ✅ 正确 - 使用英文标点
// 描述: 接通延时定时器, 当IN为TRUE时, 经过PT时间后Q变为TRUE
// 或者: 接通延时定时器 - 当IN为TRUE时经过PT时间后Q变为TRUE
```

## 4. 注释密度建议

### 4.1 推荐密度

| 代码位置 | 注释频率 | 推荐格式 | 示例 |
|----------|----------|----------|------|
| 文件头部 | 必须 | `(* *)` | 功能块名称、描述、版本 |
| 变量声明 | 每个重要变量 | `//` | `PT : DINT; // 预设时间(扫描周期)` |
| 函数/功能块开始 | 必须 | `//` (函数) / `(* *)` (FB头部) | 简短功能说明或大段头信息 |
| 关键逻辑分支 | 每个IF/CASE块 | `(* *)` | 多行描述分支条件和动作 |
| 状态机步骤 | 每个状态 | `(* *)` | 步骤条件和转换逻辑 |
| 复杂计算 | 计算前后 | `//` | `// 判断是否达到预设值` |
| 复位/初始化 | 每次 | `//` | `// 复位计数器` |

### 4.2 密度参考标准

- **每5-10行代码**至少1条注释
- **每个函数/功能块**必须有头部注释（3-5行）
- **每个变量**建议有简短说明（尤其I/O参数）
- **避免过度注释**：显而易见的代码不需要注释

## 5. 常见错误及解决方法

### 5.1 LSP编译错误

| 错误信息 | 原因 | 解决方法 |
|----------|------|----------|
| `unexpected token ，(LX003)` | 使用了中文逗号 `，` | 改为英文逗号 `,` |
| `unexpected token *(LX003)` | 块注释格式错误或嵌套 | 使用 `//` 单行注释或检查 `(* *)` 配对 |
| `字符 U+ff0c 与 ASCII 字符 U+002c 混淆` | 中文全角标点 | 全部替换为英文半角标点 |
| 注释未生效（显示为代码） | 缺少关闭符号 `*)` 或注释内含 `*)` | 检查注释内容是否包含标记字符串 |
| `unexpected end of file` | 注释被提前结束导致后续语法错乱 | 搜索注释内的 `(*` 和 `*)` 并移除 |

### 5.2 实际案例

#### 案例1：FB_CTD.scl 注释错误（已修复）

**❌ 错误代码：**
```scl
(* 先加载10，然后每脉冲减1，到达0时Q变为TRUE
    ----- 架构特性 -----

    - 纯逻辑实现: 无系统函数依赖，完全兼容go-gen仿真
    ...
*)
```

**问题分析：**
1. 第1行缺少关闭符号 `*）`
2. 第2行的 `----- 架构特性 -----` 被当成代码执行
3. 包含中文标点 `，`

**✅ 修复后：**
```scl
// FB_CTD: 减计数器
// 描述: CD上升沿时CV减1, 当CV<=0时Q变为TRUE

FUNCTION_BLOCK FB_CTD
VAR_INPUT
    CD   : BOOL;   // 减计数脉冲输入 (上升沿有效)
    LOAD : BOOL;   // 加载预设值 (TRUE时设置CV=PV)
    PV   : INT;    // 预设计数值 (初始加载值)
END_VAR
...
```

#### 案例2：FB_1001 文件头注释内容含标记（⚠️ 高危案例）

**❌ 错误代码：**
```scl
(* ============================================================================
 功能块名称: FB_1001_Conveyor4Layer_BufferFraming
 ============================================================================
 项目: DJ-2026-005 边框缓存机
 ...
 变更记录:
   V4.1.0 (2026-04-25): 规范化修订
          - 文件头格式统一为标准(* *)块注释格式   <- 致命!这里的*)结束注释
          - 注释风格统一: 段落分隔符改为(* ============ *)格式  <- 变成代码!
          - 规范引用更新至最新版本号(V1.0.5/V1.0.3)
 ...
============================================================================== *)
```

**问题现象：**
- IDE显示第54行之后的注释颜色变为正常代码颜色
- LSP报错: `unexpected token` 在后续行
- 编译失败或行为异常

**✅ 修复后：**
```scl
(* ============================================================================

 ...
 变更记录:
   V4.1.0 (2026-04-25): 规范化修订
          - 文件头格式统一为标准SCL块注释格式       <- 用纯文字描述
          - 注释风格统一: 段落分隔符改为等号线格式    <- 用纯文字描述
```

## 6. 多平台兼容性矩阵

| 注释特性 | Siemens LSP | TIA Portal | CODESYS | GX Works |
|----------|-------------|------------|---------|----------|
| `//` 单行注释 | ✅ 完全支持 | ✅ 完全支持 | ✅ 完全支持 | ✅ 完全支持 |
| `(* *)` 多行注释（不嵌套）| ✅ 完全支持 | ✅ 完全支持 | ✅ 完全支持 | ✅ 完全支持 |
| 嵌套注释 `(* (* *) *)` | ❌ **严格禁止** | ⚠️ 未定义行为 | ⚠️ 可能报错 | ❌ 编译错误 |
| **注释内容含 `(*` / `*)`** | ❌ **严格禁止** | ⚠️ 可能异常 | ⚠️ 可能异常 | ⚠️ 可能异常 |
| 中文内容 | ✅ 支持 | ✅ 支持 | ✅ 支持 | ✅ 支持 |
| 中文标点 `，：。` | ❌ **不支持** | ⚠️ 部分支持 | ⚠️ 部分支持 | ⚠️ 部分支持 |

**结论：使用 `//` 或单层 `(* *)` + 英文标点 + 内容无标记 = 最大兼容性**

## 7. 注释模板库

### 7.1 功能块头部模板

```scl
(* ============================================================================
 功能块名称: [功能块名]
 描述: [简要描述]
 版本: V[版本号] ([日期])
 ============================================================================
 项目: [项目名称]
 作者: [编制人]
 
 [详细说明...]
 ============================================================================ *)
```

### 7.2 函数头部模板

```scl
// [函数名称]: [功能描述]
// 输入: [参数说明]
// 输出: [返回值说明]
// 注意: [特殊情况说明]
```

### 7.3 行内注释模板

```scl
变量名 : 类型;   // [用途说明]
#Variable := Value;  // [赋值原因]
IF Condition THEN    // [条件说明]
```

### 7.4 region 折叠标记模板

**折叠区段统一写 `REGION 名称 ... END_REGION`。这是西门子博图（TIA Portal V19 可直接使用）的格式，也是 siemens-lsp 插件支持的写法；带 `#` 的 `#REGION ... #END_REGION` 与注释包裹的 `(* #region *)` 旧模板均不再使用。实际移植时要根据编译器平台自行适配。** 详见 LSP-905 §6.3（含较长示例）。

```scl
REGION [编号]_[区域名称] [简要说明]
... 代码 ...
END_REGION
```

## 8. 代码审查检查清单

在提交代码前，请确认以下项目：

- [ ] 所有注释使用 `//` 或**单层** `(* *)` 格式
- [ ] **严格禁止任何形式的嵌套注释**（包括 `(* (* *) *)`、混合嵌套等）
- [ ] **严格禁止注释内容中包含 `(*` 或 `*)` 字符串**（用文字描述替代）
- [ ] `(* *)` 注释必须正确配对（每个 `(*` 有对应的 `*)`）
- [ ] 所有标点符号为英文半角（`,` `:` `.` `;`）
- [ ] 每个公开的函数/功能块有头部注释
- [ ] 重要变量有行内注释说明
- [ ] 关键逻辑分支有注释解释意图
- [ ] 注释内容准确，与代码保持同步
- [ ] 无过时或冗余的注释
- [ ] 无连续并列的多个 `(* ... *)` 块（应合并为单个块）

## 9. 工具和自动化建议

### 9.1 IDE配置（VS Code）

推荐安装以下插件辅助检查：
- **SCL Language Support**: 基础语法高亮
- **Siemens LSP**: 实时错误检测
- **Unicode Detector**: 高亮非ASCII字符

### 9.2 正则表达式检查

可在IDE中搜索以下模式检测问题：

```
# 检测中文标点（高优先级）
[，：；。】【】《》""''

# 检测可能的嵌套注释（高优先级）
\(\*[^)]*\(\*

# 检测注释内容中的标记字符串（高危!）
# 注意: 此检测需人工确认是否真的在注释内部
\([^*]*\*\)

# 检测非标准的region格式（带 # 的写法不被支持，应写成 REGION ... END_REGION）
^\s*#\s*(END_?)?REGION
//\s*#\s*(end)?region
```

### 9.3 VS Code 任务配置

可在 `.vscode/tasks.json` 中添加自动检查任务：

```json
{
    "label": "SCL注释规范检查",
    "type": "shell",
    "command": "powershell",
    "args": [
        "-Command",
        "Get-ChildItem -Recurse -Filter '*.scl' | Select-String -Pattern '[\\uff0c\\uff1a\\u3002\\uff1b]|\\(\\*[^)]*\\(\\*' | Format-Table -Property Path,LineNumber,Line"
    ],
    "group": {
        "kind": "build",
        "isDefault": false
    }
}
```
