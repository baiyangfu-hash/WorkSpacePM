# 通用任务派发契约模板

## 1. 定位

本规范定义 Grooming 与 Execution 的结构化物理交接。Handoff 是对确定 checkpoint 的快照，不是授权源、状态库或自由文本 Prompt。对象边界和恢复规则遵循 PM-056，变更授权遵循 PM-042。

## 2. Handoff v2 必填结构

```json
{
  "schema_version": "handoff.v2",
  "handoff_id": "HO-...",
  "mode": "grooming | execution",
  "subject_project_id": "SW-...",
  "control_project_id": "SYS-...",
  "work_id": "WORK-...",
  "run_id": "RUN-...",
  "checkpoint_id": "CP-...",
  "authorization_ref": "READ_ONLY | DEC-...",
  "from_owner": "agent-a",
  "to_owner": "agent-b",
  "owned_paths": ["workspace/relative/path"],
  "development_root": "workspace/relative/path",
  "runtime_root": "workspace/relative/path",
  "release_id": "version-commit",
  "git": {
    "source_revision": "40-hex",
    "target_revision": "40-hex-or-empty",
    "worktree_ref": "workspace/relative-or-approved-absolute",
    "declared_dirty_paths": []
  },
  "lease": {
    "owner": "agent-a",
    "expires_at": "RFC3339",
    "version": 1
  },
  "goal": "one verifiable outcome",
  "read_first": ["path plus digest"],
  "strict_constraints": ["scope and safety constraints"],
  "acceptance": ["machine-verifiable checks"],
  "evidence": ["checkpoint evidence refs"],
  "capabilities": ["required adapter capabilities"],
  "snapshot_hash": "sha256"
}
```

`lease_token` 禁止出现在 Handoff、Resume、日志和报告中。接收方在 accept 操作中提交新的私密 token，成功后 lease 原子转移，旧 owner 立即失权。

## 3. Grooming 模式

Grooming 必须绑定 read-only Work，`authorization_ref=READ_ONLY`，不得修改业务代码、规范、运行指针或项目状态。

回执至少包含：读取文件与行号、当前逻辑、依赖关系、风险、无法从代码推导的决策、建议 scope、建议测试和 evidence。代码库已有事实不得转问用户。

## 4. Execution 模式

Execution 必须绑定已批准 CHG/Decision 和 READY Work。Run 的 owned paths 必须是批准 scope 的子集；Git HEAD、worktree 和 dirty 声明必须在开工前冻结。

执行者应在内部完成实现、测试和 bounded healing。任一必需门禁非零时不得提交成功结果；发现越界需求应返回 blocker 或创建关联 Work，不得顺手扩项。

## 5. 接收握手

接收方必须依次验证：schema/capability、snapshot hash、subject/control、Work/Run/Checkpoint、授权、Git baseline、owned paths、dirty 声明和 lease 有效期。任一项不符即拒绝 accept，并返回结构化 conflict。

允许 v1 只读查看历史证据；需要写权限、恢复或 lease 的场景禁止降级到 v1。

## 6. 结果回执

```json
{
  "schema_version": "handoff-result.v2",
  "handoff_id": "HO-...",
  "work_id": "WORK-...",
  "run_id": "RUN-...",
  "checkpoint_id": "CP-...",
  "result": "succeeded | blocked | failed",
  "changed_paths": [],
  "git_revision": "40-hex-or-empty",
  "dirty_paths": [],
  "verification": [
    {"name": "pytest", "status": "verified", "exit_code": 0, "evidence_ref": "..."}
  ],
  "discovered_work": [],
  "conflicts": [],
  "next_legal_action": ""
}
```

`verified` 必须有真实命令或物理验证证据；未运行的检查写 `not_verified`，不得写 PASS。

## 7. 豁免与失败关闭

源码注释、suppression 标签、聊天说明或执行者自称均不能形成豁免。豁免必须引用已批准 Decision，明确规则、文件、期限、风险 owner 和替代验证；缺一项即失败关闭。

以下情况必须拒绝执行：未知 schema、必填 ID 缺失、授权不覆盖 scope、快照 hash 不符、lease 过期、错误 owner、Git 漂移、未声明 dirty、capability 不满足或 Store 不可读。

## 8. Adapter 约束

Adapter 只转换平台输入输出，不保存 Work/Run/Handoff，不改写 next action。Codex、Cursor、Trae 或其他平台对同一显式 Work/Run 必须返回一致 canonical facts。
