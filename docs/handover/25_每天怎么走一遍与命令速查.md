# 每天怎么走一遍与命令速查

> 用途：没有协调者线程、只剩一个 agent（Trae 或别的）加用户时，一天的活怎么排、命令在 Windows 和 Linux/云端各怎么写。本文只是把已有手册串成一条线，**不新增规矩**；各条的出处看被引用的文件。写不准的标“未核实”。

## 一、一天的顺序

1. **进门定位（只读）**：按 `.trae/skills/cockpit-entry/SKILL.md` 的进门四步走一遍，用中文告诉用户当前焦点、下一步合法动作、冲突。没有已授权的 Work、Run 与租约之前只用只读命令。
2. **看昨夜结果**：GitHub 上开着的 PR（审计过没有、CI 绿没有、评审对话解决没有）；`main` 上有没有新合并；夜里跑的门禁有没有结论。拿不到的结论写“未核实”，不要猜。
3. **选今天做的事**：先看 `docs/handover/03_用户已定事项.md` 和 WBS 当前投影（`SYS-2026-001_WorkspaceGovernance/01_项目文档/39_PM-Flow_恢复与可用化总方案_WBS_PM.md`）；不在 WBS 里的活先补登再做；债务按 `21_技术债与问题池分级.md` 的级别排。需要用户定的事攒起来，一天最多 3 件、一句话能答。
4. **一件事一个 PR**：分支、PR 描述按 `.github/pull_request_template.md` 的栏目填（做了什么、可改范围、安全回路、证据、同类排查）；改受保护路径要把路径逐字写进“可改范围”。流水线和合并条件见 `01_角色分工与流水线.md`。
5. **自检再报**：交卷前把验收命令和退出码原样跑一遍；缺陷类 PR 带根因、同类排查清单和变异证据（改坏代码测试必须变红）。
6. **收尾**：只在自己的 PR 里写“建议回写”；台账、WBS、治理库由主执行（本地任务）写，见 `24_云端任务与本地任务分工.md`。向用户的汇报格式见 `20_工作方式与汇报口径.md`。

## 二、命令速查（工作区根目录，控制根）

| 要做的事 | Windows（笔记本） | Linux / 云端会话 |
|---|---|---|
| 驾驶舱入口 | `& ".\.venv\Scripts\python.exe" ".\main.py" <参数>` | `.venv/bin/python main.py <参数>` |
| 确认在控制根 | `git rev-parse --path-format=absolute --git-dir --git-common-dir`，两行相同 | 同左 |
| 列项目 | `... project list` | `... project list` |
| 定位（只读） | `... pm orient <项目编号> --json` | 同左（云端检出已核实可用，输出 `continuity-resume.v2`） |
| 审计一个 PR | `python reviews/tools/audit_pr.py <PR号>` | 同左（退出码 0 无 FAIL、1 有 FAIL、2 用法或 Git 错） |
| 越界检查（本地试跑） | `python reviews/tools/pr_scope_check.py --base <基线提交> --head <PR头提交>` | 同左 |
| 判卷脚本测试 | `python -m pytest reviews/tools -q -p no:cacheprovider -o addopts=` | 同左（约 2.5 分钟） |
| 项目内测试 | 在 SW-2026-008 目录下按 `pyproject.toml` 的口径 | 同左；云端环境与笔记本的差异看 `24_云端任务与本地任务分工.md` |

Trae 里的 AI 执行 `main.py` 一律用 `.\.trae\bin\pm-as-trae.ps1`，原因见 cockpit-entry 的“身份标记”一节。云端会话没有这个脚本。

## 三、卡住了怎么办

| 现象 | 做法 |
|---|---|
| 命令输出建议 `--fix`、`doc sync` 等修复命令 | 不运行；原文报告，停下等用户（没有授权的 Work 前只读） |
| 租约过期、续租被拒 | 长命令用 `continuity lease run-with-renewal` 包起来（见 `22_门禁发版与长任务.md`）；已经过期的，原样报告，不自己换身份绕过 |
| `No such command 'orient'` | 本机发布版本还没有这条命令，改用 `pm resume <项目编号> --json`；不是故障 |
| PR 的 `gate` 报越界 | “可改范围”漏了文件；补全路径，不要靠放宽目录前缀 |
| `safety-zone` 报要签字 | 只认用户本人在 PR 评论里写“安全签字 <提交号至少 12 位>”，agent 不代写，见 `01_角色分工与流水线.md` 第五节 |
| 想删分支、删文件、切换发布、改规范库、改 `.trae/` | 先问用户，见 `02_必须用户亲口同意的事.md` |
| 两条规矩互相打架 | 看 `90_规矩冲突待裁定.md`，不自己裁 |
