# 云端任务与本地任务分工

> **状态：用户已同意（2026-10-28 21:42 MST，回复“同意”，同意的是：本地任务接主执行这个角色；云端任务永远不写账本）。** 出处：协调者与项目线程 2026-10-29 的讨论；用户说明 Trae CN 同时有“云端任务”和“本地任务”两种，和 Claude 的云端会话与本地会话类似。`90_规矩冲突待裁定.md` 第 1、2 条的结论已在 #320 同步改写。

## 一、怎么分

| | 云端任务 | 本地任务（用户笔记本） |
|---|---|---|
| 对应现在的角色 | 云端会话：作者、审计、合并线程 | 主执行 |
| 干什么 | 一债一个 PR：推分支、开 PR、审计、合并 | 走驾驶舱：任务（Mission）、工单（Run）、验收、收口；跑 PLC 检查和西门子插件；全量测试和长门禁 |
| 写账本、台账、WBS、治理库、发布指针 | **不写**，只在 PR 里写“建议回写” | **只有它写** |
| 受哪条规矩管 | `AGENTS.md` 里“没有授权的 Work、Run 与租约只允许只读”**不适用**，改由 PR 范围检查（`gate`）和独立审计约束 | 受“没授权只读”约束 |
| 环境 | 沙箱虚拟机，约 2 核、4 GiB 内存，Python 3.14，没有西门子插件 | 用户笔记本，Windows，插件、虚拟机、PLC 工具都在 |
| 在线时间 | 24 小时 | 笔记本开着才行 |

## 二、两条已由用户同意

1. 本地任务接“主执行”这个角色（写账本的唯一一个）。
2. 云端任务永远不写账本。

## 三、实际含义

- 驾驶舱债这类小活：云端任务做 PR，本地任务回写台账。
- PLC、需要插件或虚拟机的验证：本地任务。
- 发布切换、删除、规范库改动、`.trae/` 改动：本地任务只在用户亲口同意后做，云端任务一律不做。
- 云端环境和项目 CI 的差异（Python 版本、内存）见共享文件夹里的环境体检记录（待搬）。

## 四、在工位目录里运行 `main.py` 会怎样（2026-11-01，TD-261 D10，协调者裁决：不改，只写明）

- 根入口 `main.py` 按**入口文件放在哪**判断，不按你当前在哪个目录判断。入口文件本身在工位（`.auto-pm/worktrees/<agent>`）里：一律拒绝，不管你站在哪、也不管是不是经符号链接调用。
- 入口是控制根的 `main.py`、但你当前目录在工位里：会放行，驾驶舱把当前目录（工位）当成工作区。这时只读命令照常跑；写命令会被“只能在含真实 .git 目录的主 Git 工作树执行”拦下，不会写进账本。
- 所以：驾驶舱命令在控制根里敲，用控制根的 `main.py`；别图省事从工位目录调控制根的 `main.py`。看到上面那条拦截信息，就是站错了位置。
- 这是用桩启动器在临时仓库里复现的结果，没在真实笔记本上跑；要不要改成按当前目录判断，已由协调者裁决为不改（改了反而会放松“入口在工位里”的拒绝）。
