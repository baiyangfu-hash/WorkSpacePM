# PLC 工作规矩

> 出处：用户已定事项（项目记忆，2026-10-21～10-26 整理，原话未逐条附）；`AGENTS.md` 的 OT 交付边界和 PLC 执行技能说明。**PLC 线目前整体挂起**（用户 2026-10-25），本文是恢复后的工作规矩，也是“现在别碰什么”的说明。凡标“未核实”的，开工前先对仓库核实。

## 一、现在的状态

- PLC 相关事项全部挂起：用户原话“PLC 相关的问题，先挂起来，等我有时间，有环境一起处理。驾驶舱的技术债和 WBS 任务优先”。需要用户拍板的 PLC 事项（仿真测试、方案、判卷规矩、盘点裁决）也一并挂起。
- 在用户主动说恢复之前，**不要**改 PLC 程序、不要排 PLC 的仿真和签字、不要就 PLC 向用户提问。只清驾驶舱（SW-2026-008）的技术债。
- 恢复时的顺序：先 DJ-2026-005（作为“靶子”实测驾驶舱），005 做好之后再看 DJ-2026-009（用户 2026-10-23 原话“009 不要看了，先看 005 靶子”）。

## 二、先逻辑，后测试

程序的**工艺逻辑没有被用户认可之前，不排仿真、测试、签字**；拿一份错的程序，做不出正确的测试。顺序固定为：

1. 工艺说明（以原程序、图纸为准）→ 2. 用户核对 → 3. 架构 → 4. 程序 → 5. 仿真 → 6. 安全签字（碰安全区时）。

排任何 PLC 测试、仿真、签字、演练之前先过三道检：工艺逻辑用户认可了吗；来料（上游 PR、共享库）有没有已知缺陷；前道任务到位了吗。有一道不过，写“等某某”，不排。

## 三、怎么向用户提 PLC 问题

用户 2026-10-24 原话：“有疑问，在 PR 上回我，最好指出是哪一段程序或者设计，我去确认。”

- 提问前先查原程序、IO 表、已定事项能不能自己答；答得出的不问。
- 问题写成 PR 行内评论，指向具体文件和行或设计章节；用工位、动作、信号来描述，不用自造的术语。
- 给 A/B 选项，一次最多 1～3 个，每个一句话能答。
- 问题本身要成立。曾有一次问“急停时待料步松爪”，而待料步爪子本来就是松开的，问题不成立，用户很不满。

## 四、程序结构原则

- **高内聚、低耦合、结构化**：按机构或功能拆 FB，接口清晰；不同客户的机型差异收在可替换的模块或参数里，不要整体重构（用户 2026-10-24）。
- 类似机型的现场方案只是参考，**细节不得当成另一台机的原机事实**（例如某海外现场的一套方案与 DJ-2026-009 的差异）。
- 不要把一个项目的结构照搬到另一个项目（009 曾照搬 005，被用户否掉）。
- 步序状态：目标平台是 TIA 博图 V19 时，没有枚举（命名值类型要 V20+），用 INT 加具名常量；平台支持枚举时可以用（用户同意修改规范库 LSP-905 以允许，改规范库仍走报批）。
- 005 的目标平台已定为 TIA 博图 V19；定时器先用平台自带的，不依赖共享库（2026-10-23）。

## 五、语言和写法规范（LSP 插件相关）

- 字符串取字符、数组下界**一律从 1 开始**（用户 2026-10-26），规范里注明“LSP/插件要求，移植按平台适配”。
- 折叠区段用 `REGION … END_REGION`（博图 TIA V19 的写法）；**禁用 `#REGION`**。
- 规范正本在 `00_Obsidian_Base全局规范文件仓库/03_PLC自动化域/`（904 注释规范、905 编程规范）；修改要走报批，AI 不自己改。

## 六、共享库 SysLib

- 路径：`0100_PLC自动化/01_SharedLibraries/SysLib`。计数、取沿、计时器等有现成块的，项目里必须调用，不许另写一份同样功能的逻辑。
- 计时器 `FB_TON`/`FB_TONR` 已定改为按真实毫秒计时（名字和引脚不变），影响 005、009、000 测试台、011 的双手启动窗；用户要上机实测 10 s。
- **AI 不改共享库**；发现共享库问题写进 PR 的“不做什么”，交给用户和主执行。
- 共享库没有版本管理（未核实最新状态）：项目用相对路径引用“当前库”。建议打标签冻结，是否做等用户点头。

## 七、交付边界

- AI 的零负担交付边界停在**静态检查全绿**：`main.py plc check <项目号>`、`main.py doc check` 退出码 0。
- 把源码导入 TIA 博图 / InoProShop、编译下装、仿真、捕捉断言报错，由用户接管，截图或文本再交回给 AI。
- AI 不下装，不改现场程序。现场改了程序，要按 `11_安全区与现场回传.md` 回传。
- 西门子项目的仿真在虚拟机的 PLCSIM 上跑，汇川项目用 InoProShop 仿真；虚拟机只装环境，不接活，不写账本。

## 八、断网、不开 AI 也要能用

用户硬要求（2026-10-22）：没有 AI 时他是项目经理兼电气工程师，**电气和 PLC 相关的东西离开 AI、断网也要能用**。

- PLC 程序、IO 表、业务变更记录保持普通文件加本机 Git。
- 检查命令（`plc check`、看板）纯本机 Python，零网络。
- 离线手册：`0100_PLC自动化/00_通用规范/无AI离线手册.md`。
- 断网时 `.scl` 照常本机提交，有网再推；用户本人可在人工工位（`manual/` 分支）用 `--no-verify` 跳过提交检查，**AI 不得用**。
- 新功能设计先问一句：“断网、不开 AI 能不能用？”不能，就留一条人工路线。
