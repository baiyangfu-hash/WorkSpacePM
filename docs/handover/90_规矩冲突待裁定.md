# 规矩冲突待裁定

> 这份清单只列“现有规矩之间互相打架或没衔接”的地方，**接手的 AI 不要自己裁**，交给协调者或用户。每条写了冲突在哪、各自的出处、影响。出处里的 `AGENTS.md` 章节是已核对原文的；项目记忆的出处标“记忆”。整理日期 2026-10-29。

## 1. “没有授权就只读”与“一债一个 PR”的云端做法

- 规矩 A：`CLAUDE.md` 与 `AGENTS.md` 写“没有已授权的 Work、Run 与有效租约之前，只允许只读命令”；阶段 2 要求先建 Work、起带租约的 Run、声明 owned paths，执行端创建检查点。
- 规矩 B（实际做法）：云端清债线程不开 Work、不起 Run，直接开分支、一债一个 PR，范围靠 PR 描述里的“可改范围”和 `gate` 越界检查约束，台账只写“建议回写”（记忆）。
- 影响：Trae 如果严格按规矩 A 走，会进驾驶舱 Mission/Run 流程并写账本；如果按规矩 B 走，就绕开驾驶舱。试跑话术里临时写了“若 .trae 规则与本段冲突，以本段为准”。需要用户裁定两条路各管哪类活。

## 2. 谁来写台账、WBS、治理库

- 规矩：台账、WBS、治理库、发布指针只由账本主机上的“主执行”写，云端和工位里的 agent 不写（`AGENTS.md` WS-001 铁律 6；记忆）。
- 现状：主执行是用户笔记本上的一个 Claude 会话。**Claude 不可用之后，没有指定谁接这个角色。**
- 影响：回写会停；技术债清单会越来越旧（已发生过“修了没改状态”）。需要用户指定接手者，或授权云端 Trae 会话写“建议回写”之外的更新。

## 3. `.trae/` 谁能改

- 规矩：`AGENTS.md`：“`.trae/` 由 Trae 生态维护；其他 AI 只读，除非用户明确要求修改”；同时“改 `.trae/`、`AGENTS.md` 的文字要用户确认”（记忆）；`.trae/` 也在受保护文件清单里。
- 现状：Trae 将成为主力，却仍受“改 `.trae/` 要用户确认”的约束。
- 影响：Trae 想修自己的规则文件时要不要每次问用户？需要用户裁定，是“Trae 可自改、事后告知”，还是维持现状。

## 4. 做和审要分开会话，但接手后只剩一个模型家族

- 规矩：`AGENTS.md` AUD-001：写这个 PR 的 agent 或会话不能审它，换另一个 agent 或另一个会话。
- 现状：Claude 退出后，作者和审计都是 Trae 会话，同一模型更容易同时看漏。
- 影响：规矩文字没破，但独立性变弱。需要用户裁定是否加一条“抽查”（用户或另一家 AI 每周抽审 N 个 PR），以及哪些 PR 必须用户亲自点。

## 5. 合并由谁点、用什么身份

- 规矩：合并条件＝审计过 + CI 全绿 + 评审对话已解决，只用 Merge commit（`AGENTS.md` AUD-001 第 6 条）。合并线程用 GitHub 接口做（记忆：笔记本上的 `gh pr merge` 被权限分类器拦）。
- 现状：云端 Trae 当前推送用的是用户**本人**账号令牌（10-28 实测），它也能代签安全签字、合并；仓库规则集在 10-24 查时没有“必须有审批人”（现状未核实）。
- 影响：需要用户裁定：只有用户点合并，还是单独账号的“合并会话”合并（并用 CODEOWNERS 把安全区、`.trae/`、`AGENTS.md`、规范库留给用户）。

## 6. “17:00～21:00 禁跑”是不是对云端也成立

- 规矩：重载任务 17:00～21:00 MST 禁跑（记忆）；用户 2026-10-28 15:48 MST 原话“17:00 不停了”，云端不停息清债。
- 理解：禁跑只指**笔记本**上的全量测试和长门禁；云端不受限。但文字上两处没写同一句话。
- 影响：低。建议在 `AGENTS.md` 或操作手册里写明“只限笔记本”，改文字要用户确认（见第 3 条）。

## 7. 规矩说“报批后才能执行”，而 Claude 一直“技术决策自定”

- 规矩：`AGENTS.md` 的“澄清-报批-执行-验收”要求出《需求分析与技术实施计划》并显式停下等用户“同意/批准”才开工。
- 现状：清技术债时，云端线程按用户授权（记忆，原话未找到）技术决策自定、先做后告知；只有安全区、`.trae`、规范库、删除、切换发布才等用户。
- 影响：Trae 该照哪条？建议用户裁定“哪类债可以不报批直接做”（试跑方案里的‘一档’：只改测试、文档、单文件小修）。

## 8. 审计放行条件有两种说法

- 规矩：`AGENTS.md` 写“审计通过、CI 全绿、评审对话全部解决，三条都满足才能合并”。
- 协调者 2026-10-28 12:05 MST 补充：判“有条件过”且唯一条件是 CI 绿的 PR，合并线程在头提交不变、CI 全绿时直接合（记忆）。
- 影响：不冲突，但后一种没写进仓库。已写进 `01_角色分工与流水线.md`；如果用户不同意，请推翻。

## 9. Trae 的工位名和云端 Trae 的位置

- 规矩：`AGENTS.md` WS-001 表：Trae 在笔记本上的工位是 `.auto-pm/worktrees/trae`、分支前缀 `trae/`；表里说“云端会话不占本机工位，每个云端会话的克隆就是自己的控制根”，但那一行写的是“项目 Claude、云端会话”，没提云端 Trae。
- 现状：云端 Trae 工作区已能用 `trae/` 前缀推分支（探路成功），它的克隆是单分支克隆，没有 `origin/main` 引用，要用 `git fetch origin main` 后 `git switch --detach FETCH_HEAD`。
- 影响：需要补一行：云端 Trae 算不算“控制根”；它能不能跑驾驶舱写命令。
